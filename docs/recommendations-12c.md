# 扩展 12C：系列摘要、关联详情与本人记录闭环

日期：2026-10-25。已实现 [扩展 12 方案](recommendations-extension-12-plan.md) 的 12C。12B 的只读公共合同保持独立，本轮增加私人读取和界面；没有开启线上开关、同步正式数据或修改推荐排序。

## 用户可见变化

- 个性化推荐、单番相似、按标签找的作品详情新增“系列与关联”，最多展示三条直接关联与覆盖状态，再进入完整页面。
- 私人手账仅在预览详情增加紧凑摘要；编辑窗口及公开手账不增加此入口。默认安全范围；身份未能解析时可明确选择“以包含已审核 NSFW 的范围重新读取（仅本次）”，仍须通过现行开关及作品审核，不能据此放行未知分级或身份。
- 系列页面按“故事前后 / 番外与分支 / 总集与其他版本 / 其他关联”分组，发行形式、日期与关系标签分别显示。日期未知明确标出。世界观、角色等弱关系有单独说明，不合并成连续剧情。
- 展示本人已确认身份的想看、在看、看过、搁置；未确认身份显示“记录身份待核对”，未找到已确认记录显示“无已确认记录”。不说“没看过”，不读取或返回个人评分、长评。
- 条目可查看公共详情、加入想看及寻找资源；总集篇与续集均不自动跳过或批量添加。资源使用既有侧栏，NSFW 封面继续留空。身份冲突沿用旧记录核对流程，不在系列页猜测或合并记录。
- 未获取、空观察、部分获取、最近失败、资料过期都有明确文案。无可展示关联不等于独立作品。

一级导航仍为“个性化推荐 / 单番相似 / 按标签找”。系列页通过详情进入，没有第四个推荐入口。

## 返回、并发与失效

页面地址为 `/recommendations/series/:bangumiId`。从手账或三种探索进入时，使用 React Router 背景 location 保留原组件，并由全屏原生 dialog 展示系列页面；原详情、筛选、已加载批次和滚动位置继续保留。直接打开地址时提供普通独立页面和返回番剧探索入口。

背景地址只接受 `/dashboard`、`/recommendations`、`/recommendations/similar`、`/recommendations/tags`，不会打开任意外部回跳地址。跨刷新后的原页数据仍需重新读取，不承诺保留浏览器刷新前的内存批次。

系列内加入操作得到服务端确认后才更新状态并发送既有失效事件。背景手账在返回时刷新记录与统计，保留筛选和预览；背景推荐遵守原有刷新门槛。全部详情、查询和写入都绑定本次账号、来源与范围，取消或晚到的旧响应不能恢复已关闭或其他账号的界面。

每 30 秒及回到前台校验关系上下文；范围到期和 15 分钟上下文期限有独立计时。系列版本变化使用 `series_snapshot_changed`，仅使系列页失效；不能误判为 NSFW 授权变化并重置原页开关。访问范围本身失效仍关闭旧结果。

资源、关联详情、系列页及原预览可以逐层 Escape 返回。滚动锁按引用计数释放，支持浏览器后退时多层同时卸载；原生 dialog 的 Escape 不继续关闭下面的手账预览。

## 后端合同

全部接口需要登录，返回 `private, no-store`，沿用当前内容范围校验及限流。不接收用户 ID、评分、长评、任意编辑字段。

| 接口 | 合同与行为 |
| --- | --- |
| `GET /api/recommendations/series/<id>/` | 保留 `recommendations.series.read.v1`，不读取手账，`can_add_from_series=false` |
| `GET .../series/<id>/workspace/` | `recommendations.series.workspace.v1`：范围内直接关联、本人状态、签名 context |
| `GET .../series/record/<record_id>/` | `recommendations.series.record.v1`：仅解析该账号的精确手账身份；不用标题或记录 PK 猜 Bangumi ID |
| `GET .../series/<source>/items/<target>/?context=...` | `recommendations.series.detail.v1`：context 当前有效、目标属于可见直接关联或来源本身，返回公共详情及本人状态；不伪造推荐依据 |
| `POST .../series/<source>/items/<target>/want/?context=...` | 仅空 JSON 对象；验证关系后复用 `add_want`，返回原 `recommendations.want.v1`，新建 201、已有 200 |

workspace/detail 返回 12B 的覆盖状态、排序含义、depth=1、limit=200、truncated、来源快照与版本；本人状态额外字段是 `watch_status`、`record_state`。context 沿用 12B 的账号、来源、系列版本、完整目录摘要、节点摘要、内容范围版本签名及 900 秒期限。

GET 在数据库强制只读快照内构建，发送前再次检查系列、节点、目录、范围及运行开关。本人身份仅按当前直接 ID / 有效私人别名解析，查询只涉及本次最多 201 个可见 ID，记录上限 5000；不通过每条详情重复扫描整份手账。

写入按账号 → 系列状态 → 节点 → 范围控制 → 目录顺序加锁，再检查签名和当前审核。系列服务不复制新增记录逻辑，也不覆盖已有评分、状态或长评。直接 ID 与别名冲突、旧别名过期时，即使伪造 POST 也要求先核对。已经提交的写入确认不会在响应阶段因为关系变化被转换为失败提示。
