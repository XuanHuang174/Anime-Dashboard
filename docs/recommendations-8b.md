# 增强 8B：V1 反馈接入与页面闭环

## 范围与后端复用

本阶段直接复用已部署的 8A 服务，不增加表、迁移或算法，不修改 V1 相关性、IDF 或重排公式，不启用 V2。

既有流程已经是：安全目录 → 当前用户精确 Bangumi ID 反馈排除 → 前 400 条候选选择 → 原有 V1 排序。8A 的 `engine.py` 与 `evidence.py` 已将独立 `feedback_version` 纳入分页 HMAC 和证据上下文；8B 没有另建排除系统，也没有先取满再过滤。

后端新增一条集成回归：撤销后，其他卡片的旧详情令牌、旧分页同样返回 409，画像不变且默认仍为 V1。原有隐藏前截断、用户隔离、成人/未知分级过滤、幂等与真实 PostgreSQL 行锁测试全部复跑。

## 最终页面呈现

- 主推卡、普通卡和详情标题右侧增加小号 `⋯`。仅有“不感兴趣”一项；白底、2px 黑边、小硬阴影，悬停淡黄，触摸目标至少 44px。
- 卡片底部仍是“查看详情 / 加入想看”；反馈入口不挤入主按钮区。详情底部的加入想看与资源入口保持原位。
- 成功后只显示一条可替换提示：`已在推荐中隐藏《作品名》。`，提供“撤销 / 查看已隐藏作品”。默认计时 12 秒；悬停、键盘焦点在内或提交中暂停。
- 撤销提示只说恢复参与推荐资格，不承诺原位置。
- 顶部工具区新增“已隐藏作品”，使用同一原生 dialog 容器的独立侧边管理面板。白底正文、青绿说明，展示名称、季度、类型、隐藏时间与撤销按钮，支持 12 条分页、空状态和重试。
- 管理抽屉与详情/资源/筛选/偏好面板互斥。管理面板中的 Toast 留在原生顶层内部，不挂到 body 后被 dialog 的 inert 背景拦截。
- Escape 优先关闭已展开的 `⋯` 菜单并回焦到菜单触发器；详情/资源原有 Escape 规则保持。

## 状态协调与错误边界

核心实现：

- `frontend/src/utils/recommendationFeedback.js`：反馈及隐藏清单状态机、严格响应验证、幂等请求、同作品写入门闩。
- `frontend/src/hooks/useRecommendationFeedback.js`：页面级共享操作状态与独立隐藏清单读取状态。
- `frontend/src/utils/recommendationFeedbackSync.js`：跨标签页失效探测。
- `frontend/src/utils/recommendationSession.js`：账号作用域的内存生命周期提示，不用于鉴权。
- `frontend/src/pages/Recommendations.jsx`：成功后的详情关闭、资源销毁、第一页重读和错误恢复协调。

### 隐藏或撤销成功

1. 验证后端确认合同与作品 ID，不做乐观删除。
2. 废弃整份旧详情并关闭资源会话，不只是改按钮或旧证据文案。
3. 取消旧列表和分页请求，从第一页重读画像、偏好、推荐。
4. 新响应必须达到已确认的反馈版本，旧版本不回填。
5. 若管理面板打开，独立重读其第一页；替换单条成功提示并通知其他标签页。

若推荐刷新失败，保留确认状态，显著显示 **“反馈已保存，推荐更新失败。重新加载推荐”**；重试仅重读推荐，不重复提交反馈。管理抽屉内也提供此提示，避免提示被原生 dialog 背景屏蔽。

### 失败、未确认与冲突

- 提交失败不移除卡片、不关闭详情或资源，也不把资源区变成全局错误。
- 同作品的加入想看和反馈共用同步写入门闩；即使 React 尚未重绘禁用按钮，也不能在同一任务中同时发起两个写操作。
- 用户级反馈版本使不同作品反馈也需串行，本页同时只允许一项反馈写入；不同作品的加入想看不被全局锁死。
- 网络超时、5xx 或响应合同无法确认时，保留原 UUID、完整请求体及原期望版本，显示“重试确认原操作”。新反馈暂缓，不能擅自生成新 UUID 重放旧决定。
- 409 提示明确重新读取后再确认，不静默重试或移除版本参数。旧撤销目标继续由后端校验。读取后旧 Toast 废弃，用户可在最新隐藏清单操作。
- 隐藏清单的请求代次、取消、分页版本和最低已知版本独立校验；失败仅影响管理区，不清空手账或伪装成空清单。
- 安全 UUID 生成不可用时拒绝发送请求并释放门闩，不退化成弱随机操作编号。

## 跨标签页与账号边界

- BroadcastChannel 只传固定 `invalidate`，localStorage 只存失效随机 nonce；不发送用户 ID、作品 ID/名称、标签、评分、令牌或隐藏清单。
- 收到通知后，使用当前标签页正常授权读取服务端自己的反馈版本；只有版本升高才使旧详情、资源和列表失效并重读第一页。不相信其他标签页提供的私有内容。
- 通道不可用则退回 storage；两者都不可用时，通过聚焦/重新可见探测。失败探测不生成假的空状态，下次通知或聚焦可重试。
- 探测请求也有代次和取消保护，迟到结果不能回写；不会降低已知反馈版本。
- 另一标签页切换账号时，推荐工作区重新挂载，丢弃旧画像、手动草稿、Toast、详情、隐藏清单和待处理操作。JWT subject 仅作本地作用域提示，不承担授权；真实权限始终由服务端 `request.user` 决定。正常令牌刷新若仍为相同账号，不丢失当前草稿。
- 写操作发起前和确认前再次校验账号作用域，不能将旧账号操作回调应用到新账号。
