# 主理人一般成人作品公共发布（2026-10-23）

## 展示方式

用户明确选择直接在公共番剧库展示自己公开的作品，不增加访客登录或 NSFW 勾选要求。原有公共展示范围继续包含主理人选用的封面、作品资料，以及其本人的评分、长评、观看状态与标签。其他人的手账不会被公开或修改。

公共展示与私人推荐的本次浏览开关分别生效。推荐总开关控制推荐功能，不自动决定公共库的发布或撤回。

## 修复的缺口

旧的历史作品确认接口对所有 `nsfw=True` 目录资料直接拒绝，推荐新增想看也跳过了公共库协调。待公开列表却仍签发确认凭据，因此页面允许勾选，提交后才显示笼统的“不能通过此入口公开”。

- 已有隐藏作品：XHcode 在手账或推荐页的“公共库待公开”中重新读取，逐部勾选并确认；当前有效的一般成人审核允许发布。
- 新增作品：主理人新建手账记录时复用原有公共库协调；已审核 NSFW 作品不再被跳过。普通用户添加只创建自己的私人记录。
- 历史隐藏原因不明的作品仍需逐部确认；管理员下架不能通过此入口恢复。
- 不合格条目在读取时就显示具体原因且不签发凭据，不再显示可操作的确认框。分别说明未审核、审核失效、分级未知、目录缺失、内容排除及身份冲突。

## 核验与并发

公共发布复用现有 `release-review.general-adult.v2` 作品审核台账，检查准确 Bangumi ID、当前目录摘要、排除项确认、依据、审核版本、有效期或永久有效标记。永久有效仅取消时间截止；目录变化、撤销、政策版本变化与内容排除仍生效。

确认凭据继续有效 10 分钟，新增绑定本次内容审核签名。审核更新后旧凭据返回 409；当前审核失效返回明确 403。事务内保留用户、手账、目录、共享行的锁，公开动作只更新共享可见性字段，不改写个人资料。

待公开列表按页批量预检，避免逐条查询目录及身份关联。

`/api/showcase/` 与 `/api/anime/`（含 `/api/animes/` 别名）的列表、详情及公共统计筛选使用当前内容状态。已公开 NSFW 在审核撤销、过期或目录变化后不再返回；不会删除私人记录或在 GET 中批量改动公开标记。序列化结束后再次核查返回作品，期间状态失效则丢弃载荷并返回 409。响应禁止缓存。

普通无推荐目录的手工作品保留原有新增行为；已有准确目录时必须遵守其当前分级。历史恢复具有 Bangumi ID 的作品仍要求准确目录，不按标题猜测身份。

## 截图条目的单独处理

Bangumi **8019** 不作为一般成人作品放行。已有[来源核对记录](recommendations-general-adult-source-review-batch1-20261022.md)指出其相关人物的年级及未成年外观风险；[作品及人物资料](https://en.wikipedia.org/wiki/A_Kiss_for_the_Petals)也不能支持“仅涉及成年人”的核验结论。本次将准确 ID 纳入既有不可由管理员审核覆盖的内容排除集合，公共读取同样排除；即使旧台账为通过或分级被误标为非成人也不覆盖该限制。

这不修改历史审核记录、导出清单或任何生产数据，不代表此前导出的全部 484 个 ID 均可公开。截图条目会显示明确的内容排除原因。

## 部署与使用

无需新增数据库迁移。部署后先重新读取待公开列表，旧凭据不用于本轮新增的成人发布能力。符合条件的历史作品由主理人自行确认；本轮代码开发未代替主理人执行任何线上公开操作。

回退代码不会撤回已作出的公开决定。需要撤回某部作品时使用现有单作品下架流程，不批量翻转共享可见性。
