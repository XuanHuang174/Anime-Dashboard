## 9C 本机进程连接 Neon：带 SQL 与阶段计时

命令 `profile_recommendation_browse` 在每次读取中使用 PostgreSQL `REPEATABLE READ, READ ONLY`；报告绑定代码与公共目录精确指纹。与上表不是同一个部署执行环境，不能跨表计算“线上提升百分比”。

| 场景 | A wall ms / SQL数 | B wall ms / SQL数 |
| --- | ---: | ---: |
| 均衡，公共缓存禁用 | 3294.954 / 18 | 2775.380 / 18 |
| 均衡，公共缓存热命中 | 1575.729 / 17 | 1531.125 / 17 |
| 下一页，不重排 | 1291.752 / 16 | 1269.477 / 16 |
| 下一批，不重排 | 1271.654 / 16 | 1272.639 / 16 |
| 贴近口味，热缓存 | 1766.285 / 17 | 1476.309 / 17 |
| 开放一些，热缓存 | 1792.311 / 17 | 1483.171 / 17 |

同条件下，禁用缓存、首次启用与热命中的首屏作品/证据摘要完全相等。缓存的是公共题材特征，不是私人结果。两账号共享同一公共指纹，因此 B 的 `cache_fill` 已命中，不能误标为冷缓存。

本次 12 次启用缓存的首屏请求中 11 次 hit、1 次 miss；另有 2 次明确 disabled、4 次游标 not_used。它只是本机进程的一组观察，不代表线上缓存命中率。

热均衡 SQL execute 合计约 1247/1276ms，包含驱动及网络等待，不是数据库纯 CPU。剩余时间还包含 fetch、Python 特征/排序/序列化。全量精确目录核验仍然每次执行，不能为了性能省掉安全失效检查。

## 复现

仅在明确授权后传入精确账号，密码不用于本机 DB 只读命令。不要把真实报告或 `.env` 加入 Git。

```powershell
.\.venv\Scripts\python.exe manage.py profile_recommendation_browse --user-email <授权账号A> --user-email <授权账号B> --confirm-authorized-samples
```

命令仅接受 1–2 个精确账号，输出到新的 `.tools/browse-performance/<时间>/`，拒绝覆盖及目录外输出。代码、目录或画像中途变化会停止，不生成完整对比报告。
