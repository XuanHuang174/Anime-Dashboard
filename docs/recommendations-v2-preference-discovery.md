# V2 单偏好发现修正与留出目标去向诊断

本阶段将候选 V2 的策略号从 `balanced-rerank.v2` 升级为 `balanced-rerank.v3`。线上仍为 `content.v1`，没有签发 V2 上线许可，没有修改真实账号、目录或前端，也没有新增迁移。

## 1. 修正范围

仅同时满足以下条件时使用新计分：

- 当前模式为 `preference_based`：高分样本尚不足，依据明确选择的题材推荐。
- 分类为 `all`（为你发现）。
- 正常执行当前 V2 策略，而非离线前版对照分支。

原策略以“与参考题材集合尽量相同”为主要信号。明确偏好只有一个题材时，作品多出其他题材就会在集合重合度与余弦关联中受到多重降权，可能持续选择单一题材组合。这不等于用户明确要求作品只能含一个题材。

新策略使用：

```text
0.40 × 明确偏好题材的 IDF 加权覆盖
+ 0.45 × sqrt(有界题材向量余弦关联)
+ 0.10 × 有界公共评价信号
+ 0.05 × 新题材占比
```

平方根仅缓和附加题材在冷启动下受到的余弦降权，仍是内部排序变换，不是喜欢概率或置信度。覆盖信号只能来自当前用户明确保存的题材；附加题材不自动写入用户偏好。

保持不变的部分：

- 高分画像模式的所有分类计分。
- 熟悉的心动、换一种口味的计分。
- 400 候选上限、分层策略、重复惩罚强度和 120 返回上限。
- V1 的计分、排序、缓存命名空间与策略无关的快照语义。
- 强制实际关联、结构化证据、安全分级、手账隐藏与反馈排除规则。

不设置硬性题材配额、不猜作品系列、不随机补无关条目。候选不足允许少返回；没有替代组合时，同题材作品仍可正常重复。大的基础相关性分差仍不能仅靠多样性惩罚被逆转。

## 2. 前版对照与版本边界

`diagnose_recommendations --compare-previous-v2` 在同一只读快照中运行三臂：

- `content.v1`：当前稳定基线。
- `content.v2`：当前 `balanced-rerank.v3`。
- `content.v2.previous`：离线标签，走本次修订前的 V2 计分分支（`balanced-rerank.v2`）。

这里的前版分支保留本次没有修改的共同候选池和重排步骤；只关闭本轮新增的明确偏好计分。不代表未来修改共同步骤后仍能凭这个分支声称完整复原所有历史版本。

`v2_policy_version` 是可信 Python 离线调用参数，不是 HTTP 查询项；API 明确拒绝它和诊断目标标记。不能将服务端算法设为 `content.v2.previous`。正常站点请求仍只使用已配置并经批准的算法。

策略版本与参数进入 V2 公共缓存命名空间、分页快照及证据上下文；旧 V2 快照不能与新策略混用。源文件/专项测试进入发布指纹，旧批准文件不能批准新代码。即使高分画像结果完全相同，V2 策略升级仍要求重新读取。

## 3. 为什么留出命中为零不能只看一个数字

原留出规则固定取当前有效种子中 Bangumi ID 最小的一组目标，默认最多 4 个。重复跑同一账号并不会自动增加新的独立目标。固定集适合作回归，但不足以代表所有口味、年代或真实用户。

新增 `_diagnostic_target_trace` 仅观察现有候选决策，记录匿名目标在基本合格候选、前 400 池及水合复核阶段的位置。正常请求没有这个标记；观测不修改得分、不强行插入目标、不扩大候选池，也不对外输出目标 ID。

留出报告区分：

| 原因 | 含义 |
| --- | --- |
| `hit_top_k` | 实际进入前 K 条 |
| `below_top_k` | 已返回，但排名在 K 之后 |
| `outside_candidate_pool` | 基本合格，但没被前 400 候选池召回 |
| `outside_returned_limit` | 复核后合格，但未进入返回前 120 条 |
| `explore_requires_new_topic` | 不含超出训练喜好的新题材，不符合探索类定义 |
| `no_effective_catalog_genres` | 目标目录题材不能形成有效特征 |
| `no_training_topic_overlap` | 与当前训练喜好没有真实题材交集 |
| `not_retained_after_validation` | 实际水合/证据复核后未保留，不猜测具体数据变更原因 |
| `not_eligible_under_actual_rules` | 实际未入基本合格集合，未用标题/简介推断补因 |

原始 Hit@K/MRR/NDCG 保持不变，不通过删除难目标、改变 K、取消反馈或放低评分门槛制造改善。探索类的条件不适用目标也仍在原指标分母中，另加明确原因计数，不把其零命中简单解释为算法全面失效。

单纯重排无法找回已经在召回阶段丢失的作品。题材相关性代理高，也不代表一定找回某一部具体作品；同题材作品之间仍存在排名竞争。若要提高真实留出表现，需要独立检查召回覆盖、目录与私人题材差异，并设计预先固定的更广评测集；不能事后挑命中较高的目标替换原固定集。

## 4. 验证与复跑

独立 PostgreSQL 入口沿用 [诊断指南](recommendations-v2-diagnostics.md)。当前固定回归包：**233 项通过，0 失败，0 跳过**，保留原 16 项行锁并发测试。

新增专项验证：

- 单偏好多题材候选可以参与发现，弱关联不能仅靠重复惩罚越过大的分差。
- 高分画像计分及另外两类与前版精确一致；无关/不安全/已隐藏/已有记录不补池。
- 观测开关不改变 V1/V2 的实际输出顺序。
- 合成 PostgreSQL 正控中，真正移出训练集与已有排除的留出目标能在三臂获得非零命中；正控不是向真实账号造分。
- HTTP 无法注入旧策略或目标标记；策略变更隔离 V2 缓存/快照，V1 快照不因 V2 策略号变化而改变。
- 评分、长评、私人标签、观看状态保持原值。

Django check 与迁移漂移检查通过。没有前端改动，本阶段不把已有浏览器回归冒称为新的界面验收。

真实数据复测只使用明确授权账号，数据库强制只读。私有 `diagnostic.json`、`report.md`、`findings.md` 放在 `.tools/v2-diagnostics/`，不提交 Git；其中记录三臂同快照比较、关联与多样性的取舍、目标去向和性能，不能只展示有利指标。

```powershell
python manage.py diagnose_recommendations --user-email '<授权账号A>' --user-email '<授权账号B>' --confirm-authorized-samples --compare-previous-v2 --repeats 3 --top-k 10 --max-holdouts 4 --output-dir .tools/v2-diagnostics/<新的唯一目录>
```

本次定向修正不意味着解决了候选召回覆盖或零留出命中，更不等于 V2 已经满足上线条件。仍需完整质量评测、部署环境性能与人工批准；不放宽门槛、不清全站缓存、不改变正式用户评分。
