# P2：画像取样门槛工作台与保存闭环

## 阶段边界

复用现有三列“我的口味”工作台，在第二列“我的作品画像”内加入个人评分取样设置。没有新增弹窗系统、业务表或迁移；不改 V1 排序公式、不启用 V2、不更改生产环境变量。本阶段没有读取或写入真实账号手账。

`RECOMMENDATION_PROFILE_CUSTOM_THRESHOLD_ENABLED` 仍默认 false。关闭时，显示已保存值与实际生效值，控件禁用，继续按 8.5 分取样；只修改题材时不会提交门槛字段，更不会清除已保存门槛。开启与线上多端验收留待 P3 明确执行。

## 页面与草稿

- 九档：6.0—10.0，步长 0.5；恢复默认 8.5 只改草稿。
- 明确区分个人评分取样门槛与最低 Bangumi 公共评分筛选。降低门槛不保证推荐更准确，仍需至少 3 部安全、已看过、已关联且有有效题材的作品。
- 初次打开不请求预览。改变门槛后防抖 350ms，调用现有只读 GET 预览；快速修改、恢复原值、关闭或保存时取消旧预览。
- 预览有独立的 loading/error/retry 状态；请求序号、编辑会话、偏好版本和当前草稿值共同防止迟到响应写回。失败不显示假 0，不替换下方“已生效画像”。
- 标签清空不恢复门槛；关闭不保存。私人评分、标签和长评不变。
- 沿用桌面三列滚动区和移动端单滚动布局。控件有可访问名称、焦点样式和至少 44px 选择区。

## 保存与冲突

一次 PATCH 原子提交标签、变化的门槛和 expected_version，快速连击合并为同一请求。后端确认后才使旧详情/资源/浏览会话失效，重新读取 profile、preferences 与推荐第一页。

- 保存失败：保留两类草稿；重试仍带原 expected_version，不会覆盖新版本。
- 不兼容的成功响应：进入待确认状态，只允许读取最新设置，不自动重发。
- 保存成功、刷新失败：保留保存确认，显示“偏好已保存，推荐更新失败”；恢复仅重新 GET，不重复 PATCH。
- 标签继续三方增量合并。两处都改变门槛且不同，必须明确选择本页或最新值，再人工保存；不会自动合并单值设置。
- 服务回退或关闭编辑时，不静默丢弃本地门槛草稿；要求采用最新设置。旧服务器完全没有新字段时走兼容标签路径，部分缺失的新合同则拒绝使用。
- 跨标签页沿用现有不透明失效通知，不把门槛、题材或私人数据写入通知载荷。

## 依据与合同

`recommendationSampling.js` 集中校验九档值、P1 偏好合同、预览标记与版本、实际生效政策。保存后的 profile、preferences、推荐证据上下文必须一致；同版本保存回执也须与重读值一致。

证据有效性读取后端证据版本内的 `profile_policy_version` 与 `profile_min_score`，绝不读取未保存草稿推断来源资格。完整且一致的 7.0 分政策允许真实个人 7.0 分来源；缺失一半、未知版本、非法档位或列表/详情不一致均中性降级。旧的完整证据合同仍沿用 8.5，不猜测更低门槛。

来源仍展示“你对《作品》的评分”，并注明取样依据；公共分仍为 Bangumi 评分。不展示匹配率，不把低门槛来源叫作“高分作品”。身份核对、冷启动和口味摘要改用“达标记录／作品画像”等动态中性文案。

## P3 部署验收准备

先部署兼容前后端，确认 P1 迁移已完成，保持开关关闭做只读验收。随后仅在明确批准的环境开启开关，补验桌面/窄屏真实浏览器、账号切换、多标签页、慢网、非默认门槛保存与回退。自动化组件/合同测试不能冒充这些实际浏览器验收。

回退优先关闭门槛开关并按平台要求重启后端，前端重新读取实际 8.5 分政策；旧快照失效走原重载路径。不删除偏好列、不清空门槛、不反向删除迁移、不动私人手账，也不切换 V2。公共目录缓存与私人门槛不混用，无须清空所有用户数据或全站缓存。
