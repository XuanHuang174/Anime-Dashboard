## 2. 部署后：只读脚本

必须先由操作者确认部署完成，再在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/verify_recommendation_feedback_deployment.py --deployment-confirmed --expected-account '<明确授权的账号>' --expected-dist frontend/dist
```

- 密码通过 `getpass` 输入，不写在命令行、代码、文档或报告中。只使用明确授权账号，不遍历全站用户。
- `--expected-dist` 仅在本地构建就是这次部署产物时使用，用于核对线上入口哈希；若部署平台构建不一致，应先核对发布产物，不为通过而忽略版本差异。
- 可附加 `--adult-id <已确认成人目录ID>` / `--unknown-id <已确认未知分级目录ID>`。只能用已知的公共目录测试 ID，禁止扫描私人手账或猜测分级；未提供时报告明确标为未核验。
- 不带 `--deployment-confirmed` 时在网络/密码提示前停止。脚本不加载 Django/`.env`，不访问数据库。
- 正常登录是唯一允许的 POST；业务仅 GET，包括三类推荐、画像/偏好、详情、反馈版本/隐藏清单和只读错误边界。隐藏清单 owner 覆盖、无版本二页、陈旧版本必须被拒绝。
- 报告保存为 `.tools/deployment-8c/<UTC时间>.json`，不输出密码、令牌、作品标题或私人长评。正常登录会产生常规认证日志；这是授权认证，不是反馈写入测试。
- 清单为空只能证明空状态；不能声称已在线验证非空分页。多用户竞争、写入幂等、撤销、保存后刷新失败在隔离环境验证，不在生产制造数据。
- 账号若在验收期间被其他标签页修改，脚本可因版本/摘要变化停止：重新确认当前状态再只读复验，不强行接受陈旧上下文。

## 3. 授权账号页面只读检查

优先产品内置 Browser，正常站点登录；不复制浏览器令牌，不通过绕过权限的方式取会话。桌面和窄屏分别检查：

- [ ] 推荐默认为 V1；公共评分明确写作 Bangumi 评分，证据只表示题材关联。
- [ ] 主推卡、普通卡的 `⋯` 可以展开/收起，Escape 回到触发器。**不点击“不感兴趣”。**

- [ ] “已隐藏作品”抽屉与详情互斥；名称/季度/类型/时间、空状态或分页正常。**不点击“撤销隐藏”。**
- [ ] 窄屏无横向溢出，抽屉内可滚动，Tab/Shift+Tab 留在弹窗，关闭后焦点回到合理入口。
- [ ] 在不提交写入的前提下切换分类/关闭弹窗/返回手账，迟到结果不串场。
- [ ] 不启动 Magnet、本机 BT 客户端，不进行真实剪贴板写入；这些副作用已经在隔离测试中模拟。

Toast 的真实隐藏/撤销、连续写入及保存后读失败由隔离脚本覆盖；只读验收不为产生 Toast 而写生产数据。

## 5. 回退与缓存规范

### 8C 代码回退

出现回归时，用部署平台的“部署上一稳定版本/指定 commit”回退前后端到 **`50ba9e4`（8B）** 或当次发布前已确认的稳定构建，不使用 `git reset --hard` 或强推。8C 仅有模态焦点保护与测试/文档，回退不要求数据库反迁移。

保留所有用户反馈、独立反馈版本和幂等 UUID 回执。新版本曾确认过的操作即使回退代码也不能被删除、重复执行或把计数归零。

### 算法开关边界

`RECOMMENDATION_ALGORITHM_VERSION=content.v1` 是现有服务端算法回退开关；本阶段一直保持 V1。若未来经批准切换 V2 后需回退，可恢复该值并让全部实例重新加载配置，再验证返回 `algorithm_version` 为 V1。

**该开关不是反馈功能开关**，不能用“切回 V1”来假装关闭已经集成的反馈。当前没有新增反馈禁用开关；反馈异常使用已验证的部署版本回退，不临时绕过过滤或版本校验。

### 缓存与旧标签页

1. 后端保留现有按用户、算法/规则/画像/偏好/反馈版本隔离的快照机制；版本不符应明确 409 并重新读取第一页，不能剥掉旧 token 后自动重试写入。
2. 发布/回退后让 HTML 重新验证；如 CDN 仍缓存旧 HTML，仅失效该入口文件/已确认的静态路径，不全站清空缓存，不删除 R2 封面或用户媒体。
3. 浏览器重新加载页面以丢弃内存推荐上下文；恢复正常认证即可。不要求 `localStorage.clear()`、删除全部 cookies 或清理他人会话，也不全局执行 Django `cache.clear()`。
4. 网络结果未知时优先保留原操作 UUID 进行服务端确认，不手工再提交新 UUID“补一次”。刷新失败只重新 GET，不重复 POST。
5. 恢复后再次核对 V1、反馈版本、安全过滤与授权账号只读结果，明确记录异常原因与影响范围。
