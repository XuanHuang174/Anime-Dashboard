# 永久审核后的 NSFW 筛选误退修复

## 问题与原因

作品已登记永久审核、一般成人会话模式和推荐总开关已开启时，用户勾选“包含 NSFW 作品”并应用筛选，页面却提示“访问授权或服务状态已变化，已恢复安全范围”。

永久审核目录没有有限截止时间，后端按已有合同返回 `scope_valid_until=null`。此前前端 `controlledScope` 仍要求未来时间字符串，将这一正常响应误判为范围失效；其异常被 API 客户端当作 scopeLost，触发安全范围恢复。这是永久审核功能引入时遗漏的前端兼容，不代表用户真实授权或管理员开关发生了变化。

另一个兼容遗漏是页面原先仅为有时间字符串的范围启动状态监测；只修复响应校验会导致永久范围不再轮询。因此一并修复监测，保留主动关闸/撤销后的退出能力。

## 修改

- 仅当前 `content-scope.general-adult.v1` 且对应 `release-review.general-adult.v2` 的自助会话允许明确的 `scope_valid_until=null`。其他版本、缺失字段、错误类型、已到期时间以及旧人工授权模式的空期限继续拒绝。
- 页面在收到有效的当前成人范围后启动监测；使用范围 revision 作为依赖，避免从安全范围切换到永久成人范围时因期限同为空而漏启动。
- 监测器明确区分 null 和错误期限：永久范围不设假的到期计时器，但仍每 30 秒前台检查，恢复前台/聚焦时检查，后台时取消请求，销毁时清理计时器和监听。403、409 或确认范围失效仍退出；定期范围原有精确到期处理保持不变。
- 没有延长浏览快照/证据的 TTL，没有修改内容边界、审核记录、管理员开关、推荐排序或用户私人字段。无需新增迁移、重新导入作品或重新批准账号。

## 验证

- 修复前先新增永久 null 范围复现测试，确认失败；修复后通过。
- 前端定向 32 项通过，完整前端 302 项全部通过，生产构建通过（保留既有主包大于 500 kB 提示）。
- 独立本机 PostgreSQL 相关回归 34 项全部通过，17.712 秒；包含一般成人会话、受控服务和新增跨前后端合同测试。本轮没有重跑完整后端全仓测试。
- 新合同测试使用 14 部合成作品，经实际 TXT 批量审核服务登记永久结论；两个没有管理员权限、没有账号审批记录的合成普通用户分别请求与反馈截图相同的 OVA / 2008–2012 / 评分≥7 / 隐藏已有记录筛选。
- 实际 API 的列表、下一页、详情、画像、偏好、能力和上下文响应交给生产 JS 客户端及浏览控制器，验证进入 ready、12+2 条翻页、详情中性封面、两次上下文检查不误退；关闭服务后的真实 403 仍触发退出。
- 没有读取生产账号私人记录、改写生产审批/开关或获取成人媒体；以上是本机合成验证，不冒充真实线上账号的交互验收。

## 发布

发布本次前端构建。已打开的旧页面需要刷新以加载新版资源，再勾选 NSFW 并应用筛选；不需要重新导入或反复开关总闸。生产资源是否更新与普通账号交互结果分开核实。
