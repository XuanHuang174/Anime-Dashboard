# TXT 批量作品审核

## 使用方法

部署后进入 Django 后台的“推荐作品内容审核”，点击 **导入 TXT 批量审核**。单作品审核页也有同一入口。

路径：`/admin/recommendations/recommendationcontentreview/batch/`。

1. 选择已下载的 [484 项 Bangumi ID 清单](nsfw-review-bangumi-ids-20261023.txt)，点击“上传 TXT 并预检”。文件每行一个正整数，最多 500 个非空行、64 KiB，支持 UTF-8（可带 BOM）和带 BOM 的 UTF-16。空行忽略，重复 ID 合并；不接受网址、逗号列表或其他字段。上传文件不持久化。
2. 核对作品名称、季度、类型、当前审核状态和本次处理。不存在的 ID、未知/非成人分级、现有内容边界拦截或缺少有效题材都会阻止整批提交。请核对并修改 TXT 后重新预检，系统不会静默删除这些项目。
3. 已有当前有效审核的作品跳过，保留原依据、期限和审计；无须重复批准。全部为此类作品时不显示提交表单。需要改变某部有效审核的期限时使用单作品入口。
4. 为可审核作品填写审核原因和本批核验依据编号，例如 `manual-review-20261023-A`。编号必须对应管理员保存的逐作品核验记录；不是以统一编号替代实际核验。每部作品分别保存 `manual-review-20261023-A.bgm.ID`，可按确切 ID 追溯。
5. 有效天数默认 **0＝永久有效**，也可选择 1–30 天。明确确认两项内容核验条件均覆盖每部待登记作品，并勾选本批清单确认，点击“确认批量审核通过”。
6. 成功后显示登记数和跳过数。批量审核不改服务总开关；推荐开放仍按部署开关、带审计后台开关和用户本次筛选生效。

## 事务、并发与失败处理

- 预检只读取公共目录和审核元数据，不建审核记录、不读取私人手账、不获取媒体、不调用外部内容服务。
- 确认凭据绑定操作者、排序后的确切 ID 集合、每部审核版本/目录指纹、处理类别和规则版本，15 分钟有效。修改隐藏 ID、复用他人凭据或过期凭据无效。
- 提交时重新核验权限，按 Bangumi ID 升序锁定全部目录行，再锁全局审核版本和审核行。与单作品写入使用一致的锁序；等待期间权限撤销同样拒绝。
- 每部可审核作品仍必须符合当前一般成人内容边界、有有效题材、真实核验依据和两项明确确认。不会继承旧版批准或忽略拦截。
- 一批一个原子事务；任何资料/审核变化、版本上限、数据库或审计失败都整批回滚。批量写入减少逐作品数据库往返，仍为每部作品生成独立审核、独立操作 UUID 和独立审计，并递增全局审核版本。
- 同一凭据、同一表单重试只返回原批次登记结果，不重复追加审计，也不重新激活之后已撤销的作品。同一凭据改原因、依据或有效天数会冲突。
- 表单校验失败保留原凭据和已填写字段。数据库结果不确定时也保留原提交，重试原操作。若资料变化或凭据过期，重新上传预检；已经提交成功且仍有效的作品会显示为跳过。
- 使用既有后台 Session、CSRF 和专门审核权限；不提供公开批量批准 API，不提供任意表字段更新或文件执行能力。
