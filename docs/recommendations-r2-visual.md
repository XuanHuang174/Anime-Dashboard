# R2：推荐页与手账视觉语言统一

## 已实现

- 紧凑的珊瑚红网格页眉，呼应手账预览页；保留 R1 的章节标签、控制栏及首屏主推布局。
- 米白点阵纸面、纯白正文卡片；沿用手账的 `#ff6b6b` 珊瑚红、`#4ecdc4` 青绿、`#ffe66d` 淡黄、`#111` 黑色。
- 黑底章节标题、少量贴纸与胶带装饰；不增加仪表盘、计数卡或空泛的宣传文案。
- 主推海报采用青绿纸框；普通海报采用白色留边。主推仍是当前批次首项，不称为每日精选。
- 卡片标题仍最多两行；推荐理由改为最多两行的浅青绿摘要，完整证据仍通过原生“为什么推荐？”展开。
- 题材胶囊、明确的公共评分、紧凑双主按钮与辅助菜单；不添加第三排操作。
- 口味便签、分区标题、批次页尾及原生 Dialog 采用统一描边与小硬阴影。
- 手机端收紧留白与导航文字，保留至少 44px 的卡片菜单触控目标；详情和资源面板的原生顶层、inert、焦点及 Escape 行为保持不变。

## 实现边界

新增 `frontend/src/styles/recommendations-theme.css`，在基础样式和 R1 布局样式之后加载。所有选择器限定于 `.memphis-rec-container`，不影响手账页或全局同名控件。

生产组件仅增加页眉包装和 `aria-hidden` 装饰标记；推荐请求层、后端、V1 排序、画像与证据生成、加入想看、反馈和资源搜索服务均未改动。没有数据库迁移、用户数据写入、新依赖、外部字体或生产图片素材，也未引入 GSAP。现有资源面板转场保留，R3 再开发新的动效体系。

## 验证结果

- 全部前端自动化测试：**167 项通过，0 失败、0 跳过**。新增 4 项 R2 测试覆盖命名空间、手账品牌色、无模糊叠加阴影、证据及焦点样式边界、主要文本配色对比度。
- Vite 生产构建通过。原有主入口大于 500KB 的 chunk 警告仍存在；本阶段不以修改告警阈值掩盖它。
- 本机真实 React / 原生 Dialog 浏览器回归：**26 项通过**。包含原 13 项浏览控制/状态回归、R1 的 6 项布局/多状态检查及 R2 的 7 项视觉/焦点检查。
- 1440×900、1366×768、1024×768 检查首屏主推及按钮；768px、390px、320px 检查先主推后便签、网格、触控范围及无横向溢出。
- 加载海报、模拟海报 404、缺图占位、完整结构化证据、长标题、冷启动、仅明确偏好、筛选为空、加载失败与恢复分别验证。
- 公开评分与个人评分仍有明确标签；展开证据不触发新的推荐请求。菜单没有被卡片裁切，Escape 可回到触发按钮。
- 手机资源面板检查等待原有转场结束后再断言完整覆盖范围，确认不是仅“已经可见”的过渡帧。

浏览器全程使用本机合成响应。海报是测试脚本本地返回的合成 SVG，明确标记“合成验收海报”，不下载真实封面、不作为生产素材；外网请求被拦截，不读取真实账号或生产数据库。唯一的加入测试是本地模拟，不产生线上写入，不启动 BT 客户端或操作真实剪贴板。

截图与 JSON 执行记录保存在被 Git 忽略的 `.tools/acceptance-r2-browser/`。该记录为本地验收，不代表已部署或完成线上真实数据验收。

## 重跑与回退

在 `frontend` 目录执行：

```powershell
node --test tests
node node_modules/vite/bin/vite.js build
# PLAYWRIGHT_MODULE 可指定本机 playwright 模块，默认使用 Edge headless。
node scripts/test-recommendation-theme.mjs
```

回退时通过正常发布流程回退 R2 前端提交并重建静态资源即可；R1 布局、V1 引擎、偏好、反馈及手账数据不需迁移或清理。不切换 V2，不清空业务缓存或用户数据。
