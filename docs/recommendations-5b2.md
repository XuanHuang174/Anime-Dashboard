# 核心 5B-2：相关性优先的多样性重排

## 发布范围与开关

本阶段仅增加 Django V2 实现及测试，不修改页面布局、目录标签、私人标签、评分、长评、作品身份或偏好。没有数据库迁移。

- 冻结基线：`content.v1`，仍是默认线上算法。
- 新实现：`content.v2`，策略版本 `balanced-rerank.v1`。
- 服务端配置：`RECOMMENDATION_ALGORITHM_VERSION=content.v1`（默认）。只允许 v1/v2；非法配置返回 JSON 503，不静默回退。
- 不接受客户端算法切换、其他用户 ID 或安全过滤开关。返回体的 `algorithm_version` 是实际执行版本。
- 不更改真实 `.env`、不切换线上流量。按既定节奏先完成 5B-3 同快照评测，再决定是否在部署环境启用 v2；未证明在线提升。
- 现有 `audit_recommendation_quality` 命令和 `rank_context` 默认仍冻结为 V1，不随部署配置变化。实验可显式调用 `rank_context(..., algorithm_version='content.v2')`，不能把 V2 结果标成 V1 基线。

## 1. 当前安全候选与均衡取样

`engine._rank_context_v2` 先读取当前明确非成人、标准 ID 非空的公共字段：Bangumi ID、标题（仅排除同名标签）、原始标签、评分和类型。按 ID 排序，500 条流式读取，最多 50,000 行；超过预算返回 JSON 503。评分/类型筛选先执行，排除画像来源及用户已记录作品。缓存只提供公共 IDF 权重，不能决定当前分级、题材或推荐证据。

入池前必须同时满足：有效已定义题材、与当前喜好向量有实际共有题材、可追溯证据和有限数值评分。个性化 `familiar` 只接受高分作品证据；偏好冷启动可用明确偏好证据，不冒充完整画像。无题材、无关联、无证据作品不进入分层，不为数量补入无关作品。

`ranking_v2.balanced_candidate_pool`：

1. 按标准 Bangumi ID 去重。同名、相同题材、不同季度/续作不合并；冲突副本不联合标签。
2. 按基础分降序、Bangumi ID 升序排序，保留前 200 条（池容量 400 的一半）高相关性核心。
3. 剩余作品归入一个喜好题材层：优先其共有题材中候选频次最低的题材，再用偏好权重和题材名称确定平局。多标签作品不能让高频题材占据所有层。
4. 各非空层按固定顺序轮流取一条，耗尽的层退出，未用容量让给其他仍有实际关联的层。直到 400 条或全部合格候选耗尽。
5. 对均衡池再次查询当前安全资料，并重建证据；期间发生安全或标签变更只能剔除作品，不绕过安全限制。池末次复核不足时允许少返回。

高分来源作品的安全分级在池构建后也再次复核；若扫描期间来源变成成人/未知，返回 JSON 409 要求重新读取画像，不通过推荐理由泄露该来源。

这是“保留高相关头部 + 题材均衡补充”的折中，不承诺每一题材在 Top-120 均分，也不保证弱关联稀有题材必定进入前几名。最终排名仍以相关性为主。

## 2. 三类独立重排

共有基础：IDF 降权的加权余弦相关性；实际共有标签证据；公共评分只作为有限公共评价信号，不是用户喜欢概率，未作评分人数可信度修正。

| 分类 | 基础分 | 重复惩罚上限 | 重复定义 |
| --- | --- | --- | --- |
| 为你发现 `all` | 0.85 相关性 + 0.10 公共评价 + 0.05 新题材占比 | 0.10 | 与整个已选前缀的最大 IDF 加权题材 Jaccard |
| 熟悉的心动 `familiar` | 0.65 来源作品题材亲近度 + 0.30 相关性 + 0.05 公共评价 | 0.025 | 同上，允许口味适当集中 |
| 换一种口味 `explore` | 0.65 相关性 + 0.25 新题材占比 + 0.10 公共评价 | 0.12 | 0.20 完整题材重复 + 0.80 新题材方向重复 |

探索的相关性权重由 V1 的 0.50 提高为 0.65，新题材占比由 0.40 降为 0.25。仍要求与喜好有关联，且有至少一个喜好向量之外的新题材；“音乐+日常”可以探索“音乐+成长”，不是随机引入全无关联作品。

每轮取 `基础分 − 系数 × 重复程度` 最大者；平局按 Bangumi ID 升序。首次无惩罚，因此第一条是最高基础分。重复度为 0–1，惩罚有上限：基础差距大于该类上限时，弱相关作品不能只靠多样性逆转次序。增量维护整个已选前缀的最大重叠，不再只看最后 5 条。上限 400 入池、120 返回，重排复杂度 O(400×120×题材数)，不读取简介或私人长评。

惩罚不是硬屏蔽；口味窄时仍可正常返回相同题材组合。三类独立运行，允许同一作品合理重叠。相似题材不作为系列/续作判断。所有基础分、系数和惩罚均为内部排名单位，不向页面展示“匹配百分比”。系数是待 5B-3 检验的初始策略，不声称已调优。

## 3. 稳定分页与状态边界

- 不缓存用户结果或画像；每次请求重读当前用户画像、偏好和记录状态。
- HMAC 快照绑定用户、实际算法、V2 全部策略参数及版本、题材/提取规则、完整只读画像摘要、偏好版本与题材、种子与来源、已有记录、筛选和结果顺序/元数据。
- 变更评分、私人题材、记录状态、身份/画像摘要、偏好、结果安全性、算法或惩罚策略后，旧第二页返回原有 JSON 409。前端复用现有取消过期请求/重载第一页逻辑，不修改布局。
- 所有集合运算的 V2 浮点求和采用确定性顺序，平局按标准 ID，避免不同进程哈希种子带来的极小分差漂移。
- 成人及未知分级继续后端过滤，详情和加入想看也保留原安全服务，绝不依赖前端隐藏。
- 空手账无偏好仍冷启动；筛选无结果不伪装冷启动；明确偏好只影响排序信号，不偷偷变成硬性题材过滤。

本地 `.env` 连接正式 Neon，不得用默认 settings 执行测试。所有下面的命令使用隔离 SQLite，清空生产库/R2 配置，不写真实手账：
