# 私人手账：整理作品标签

入口：私人手账 → 编辑模式 → 数据管理 → **整理作品标签**。提供默认的“保守整理”以及可选的“标准题材重建”，均先预览再应用。

## 标准题材重建

- 新扫描可以选择两种模式。保守整理保持原有名称规范化、明确冗余清理与保护逻辑。重建模式用已确认作品的有效本地标准题材替换原有题材，同时保留用户选择的作品属性和个人标记。
- 复用推荐模块当前题材字典及已批准别名，不按用户明确偏好给作品补标签，不从片名或长评猜测题材。标准资料仅限已关联且可用、明确非成人的本地记录；身份未确认、标准资料不可用或题材为空时标记“无标准来源”，原标签和个人标记均不改写。核对身份后需要新建扫描。
- “默认保留个人标记、预设引用和已有配色标签”初始勾选。可取消勾选，将这些旧标签列入拟移除方案。作品格式、来源及分级标签（如 TV、剧场版、原创、漫改、NSFW）独立保留，不当作题材噪声删除。
- 前后对比显示基础标签及个人标记；逐标签列出本人自定义、个人常用预设、快捷筛选包含/排除条件、已有配色、管理/细分标记等依据。历史数据不据配色推断标签是手动还是自动录入。
- 每个非固定旧标签可选“保留原位”“保留为个人标记”“移除”。选择保存在服务端预览，不立即修改作品；更新后保持当前对比展开和列表位置。个人标记与标准题材别名重叠时避免重复徽章，例如保留真百时不再另加百合徽章，但仍参与标准题材识别。
- 应用重建方案需要再次确认；选中作品涉及个人标记移除时，显示准确数量并要求勾选核对。取消选择的作品和无标准来源作品不计入个人标记移除数量。
- 只改本人基础标签、自定义标签及本次移除标签对应的配色。预设与快捷筛选定义不变，其命中结果可能随作品标签变化。记录的评分、评价、进度、观看状态与业务更新时间不变；公共作品、其他用户记录、已有精选投稿不变。
- 撤销恢复本次基础标签、自定义标签和配色。应用后任一相关标签/配色或保护集合被编辑，则跳过该作品，保留新内容；只改评分不阻止撤销。使用现有最近 5 次、最长 30 天的恢复期，JSON 备份和完整变更清单可另行保存。
- 完成或撤销后刷新手账、筛选项，并通知推荐页面更新。预览模式更多功能菜单中，番剧共创宇宙位于核对标准作品之前。

## 使用流程

1. 选择当前筛选的全部作品（含其他分页），或全部私人手账。范围在创建任务时固定，之后新增的作品不会混入。当前筛选沿用搜索、单标签、年份、观看状态、分类和本人快捷筛选。
2. 可先下载完整 JSON 备份；这不是执行的前置条件。扫描只保存方案，不修改作品。
3. 预览主要变化，展开卡片查看完整前后对比、保护说明。可切换全部／有变化／未知保留／已保护，以及存在冲突时的冲突分类；重建模式显示“待取舍”和“无标准来源”。每页 20 部。支持全选本页／取消本页，勾选跨分页和分类保留。关闭、刷新或切换任务后重新核对勾选。
4. 点击“应用选中的 N 部”。任务逐批执行，可在完成当前批次后暂停；关闭、刷新后从最近任务继续。
5. 完成后可下载 JSON 变更清单，或点击“撤销本次整理”并二次确认。部分应用也可直接撤销，只回滚已应用的作品。

面板内最近 5 次已完成任务，最长保留至应用开始后 30 天；扫描/预览草稿有效期 24 小时。新扫描会使旧待确认草稿失效。新任务与已有扫描、应用、撤销任务互斥，应先继续现有任务。无变化的记录不需要应用。

## 保守模式的整理与保护规则

- 仅写入本人的 `UserAnimeRecord.private_base_tags`。自定义标签、常用预设、本人全部已保存快捷筛选的包含/排除标签、该作品已有配色标签默认保护，不改写其名称。保护名称比较忽略首尾空格、大小写及全半角差异。
- TV、OVA、OAD、剧场版、泡面番等作品格式，以及既有管理标签、重看标记保留。
- 已知题材别名按项目 taxonomy 规范化；重复项合并。与作品名、制作公司完全对应的非题材标签、明显年份标签会列为拟移除项。已识别题材优先于标题同名判断。
- 无法确认用途的标签默认保留，放入“未知保留”，无需额外确认，不会猜测它是无用标签。历史字段格式不规范的记录跳过。
- 标准题材补充只使用已确认身份、当前有效且非成人的本地标准作品库。不会调用外部 Bangumi、自动猜测身份、抓取未知作品或开放成人资料。没有可用标准题材时只整理已有标签。
- 自定义标签会在“已保护”说明中展示；前后对比列显示基础标签，不把自定义标签重复写回基础标签。
- 评分、长评、观看状态、进度、业务更新时间不变。非常早期尚未初始化私人快照的记录，首次应用会初始化等效私人资料，再修改标签；撤销只恢复标签，不撤销快照初始化。
- 共享 `Anime` 资料、其他用户手账、已有精选投稿快照不变。已经公开分享的本人手账会读取更新后的本人标签。

## 一致性、恢复与接口

任务与逐作品变更保存在数据库，不依赖浏览器内存或后台进程存活。每个 step 最多处理 50 部，批次事务提交；失败整批回滚。前端每批间隔 550ms，写入失败/429 不自动重放，用户重新读取任务后继续。

创建使用用户范围的 `request_id` 幂等键；服务端持有范围与完整预览方案，客户端只能提交排除的作品 ID，不能指定标签覆盖内容。每次写入锁定账号、任务及目标记录；同账号同 cursor 的重复并发请求返回已提交进度。

应用前重新校验标签、自定义标签、配色、个人保护集合、标题/公司和标准题材来源、规则版本。任何变化按作品跳过，不覆盖新资料。撤销校验应用后标签/自定义标签/配色与保护集合；之后发生相关编辑则跳过并提示从变更清单核对。单独修改评分等非标签字段不会阻止撤销。已删除作品跳过。

v2 将模式、个人标记保护策略保存在任务中，逐作品保存完整标签/配色快照、来源版本与取舍选择。取舍修改与应用都锁定账号及任务；修改选择递增 `revision`，应用必须提交核对时的版本。已开始应用后不能更改取舍。每次修改取舍也重新验证记录、保护集合和来源。客户端不能注入预览之外的标签、任意结果数组或移除固定作品属性。

旧 v1 的扫描/未应用预览会提示规则已更新，允许新建扫描替换；旧已应用或部分应用任务仍可按原有快照撤销。过期脱敏同时清空新快照、取舍及配色数据。

JWT 账号限定所有列表、详情、下载和写入；跨账号任务返回 404，响应为 `private, no-store`。账号切换关闭面板并取消旧读取。记录中断后需用户主动继续，不会打开即写入。

API 路径（均位于 `/api/` 下）：

| 方法与路径 | 用途 |
| --- | --- |
| GET/POST `tag-cleanup/` | 最近任务／创建范围快照；创建可带 `mode: conservative/rebuild`、`keep_personal` |
| GET `tag-cleanup/{uuid}/?page=1&filter=all` | 预览分页；filter 支持 changes/review/protected/conflicts/no_source；review 在保守模式对应“未知保留”，重建模式对应“待取舍” |
| POST `tag-cleanup/{uuid}/step/` | `{phase: scan/apply/undo, cursor: N}` |
| POST `tag-cleanup/{uuid}/decisions/` | `{record_id, revision, choices: [{name, action: keep/personal/remove}]}`；仅重建模式的未应用方案 |
| POST `tag-cleanup/{uuid}/apply/` | `{excluded_ids: [...], revision, confirm_personal_removal}`；重建模式要求版本，移除个人标记要求明确确认 |
| POST `tag-cleanup/{uuid}/undo/` | `{}`，开始安全撤销 |
| GET `tag-cleanup/{uuid}/changes/` | 下载本次变更清单 |

过期写入/变更下载返回 410；任务阶段或规则不符返回 409。过期预览不返回标签内容。

## 工作台样式与交互优化

- 标题区紧凑化；桌面保留任务栏，主要由作品列表滚动。手机/短屏改为主内容单一滚动，最近任务默认折叠，底部操作始终位于内容之外；手机端主要按钮不低于 44px。
- 显示当前任务保存的范围与条件；“新建扫描”设置独立展开，避免把历史任务误当作当前筛选。只要有未完成任务，就提示先继续。新扫描覆盖未应用草稿前有明确提示。
- 分类显示任务全量统计，新增 `change_records`；不同分类可重叠，不把数量相加。预览默认打开有变化，完成后有冲突则优先展示冲突。无变化项紧凑显示。
- 标签以独立块标出新增、移除、名称规范和保护，并有文字/符号辅助；主要变化超过 6 项时折叠其余内容。完整对比和解释可展开，展示的是任务快照，不宣称是作品当前标签。
- 扫描/应用/撤销使用各自真实 cursor 与处理总量计算进度，不模拟进度。暂停反馈明确等待当前批次；阶段结果区只在状态变化时播报。手机完成态省去重复进度条。
- 分类或分页读取时显示加载状态，暂时隐藏旧记录并禁用应用/选择；读取失败保持原分类，取消旧读取不会显示连接错误。下载有准备状态并阻止同一时刻重复下载。
- 撤销使用就地二次确认；确认期间隐藏“继续应用”，防止两个任务方向争夺主要操作。完成后突出“完成并关闭”。
- 弹窗进入 180–200ms、退出 140ms、展开 160–180ms；不反复播放整批卡片入场动画。遵循减少动态效果，保留焦点轮廓与原生 dialog 键盘约束；关闭后返回可见的手账菜单按钮。
- 修复根因：原 `.memphis-public nav[aria-label]` 样式收窄为 `.memphis-record-pagination`，保留真正分页的原外观，避免污染标签整理导航。测试夹具加载完整 `index.css` 和手账祖先类，并实际访问 Dashboard 路由验证。

此前工作台样式优化仅增加统计字段和冲突只读筛选，无新增数据库迁移、依赖或环境变量。本次重建功能的新增迁移及部署顺序见下文。

## 部署和保留期维护

新增迁移：`anime/migrations/0027_tag_cleanup_jobs.py`，创建两个任务表。**后端启用新接口前先执行迁移，再上线前端入口**；确认 Render 的构建/启动流程包含现有 `python manage.py migrate --noinput`。无需新增环境变量或依赖。本地隔离测试设置不得用于生产。

标准题材重建追加迁移 **`anime/0029_tagcleanupitem_details_and_more`**：任务模式、保护开关、方案版本，以及逐作品完整快照和个人标记移除计数。部署顺序为执行迁移 → 更新 Render 后端 → 发布 Cloudflare 前端。已有已应用任务不需要批量回写；未应用旧预览请重新扫描。本次开发没有连接生产数据库或对生产账号执行整理。

到期内容在创建/完成任务时自动清理；定时执行以下命令可主动脱敏长期不再访问账号的过期快照。每次最多处理 100 个账号（可指定 1–500），只清理整理任务的标签载荷，不删除用户作品，也不会撤销已应用结果。

```powershell
python manage.py purge_tag_cleanup_history --limit 100
```
