## 本轮代码范围

1. 推荐页复用 `BackToTop` 的 Memphis 外观：滚动超过 300px 出现；原生 Dialog 打开时隐藏；不可见时不进入键盘 Tab 顺序。
2. 等待超过原有 8 秒门槛后显示：`这次加载较慢，请稍候。预计还需 5s~15s。`
   - 按需求替换的是静态提示，不是服务端测量的 ETA 或倒计时；极端慢网仍可能超过这个区间。
3. 原评分下拉增加 `6.0及以下`。原有“不限 / 6.0及以上 / 7.0及以上 / 8.0及以上 / 9.0及以上”保留。
   - 前端草稿值 `lte6` → 请求 `min_score=0&max_score=6.0`；不是加载后在页面上过滤。
   - 公共评分必须满足 `0 < score <= 6.0`。原始 0 包含来源缺失/非法值归零等情况，不能都当成实际低分；不改变个人主动保存的 0 分。
   - 候选截取前应用，上限进入签名游标、实际条件、前后页校验及旧分页状态令牌。改变条件需新会话；快照冲突继续 409。
   - `max_score` 为可选兼容扩展；不限制时不增加响应条件键，不改变默认排序、分页或默认令牌形状。最低分高于最高分、重复/非法参数继续 400。
   - V2 内部调用兼容可选范围，但不启用 V2、不改变任何排序权重。

## 内容范围提案：现状与真实收益

本轮对配置的公共推荐目录执行 PostgreSQL 强制只读事务聚合。没有读取私人手账、评分或长评，没有调用外部模型。

| 目录分级字段 | 总量 | 有明确 Bangumi ID 且按当前规则具备有效题材 |
| --- | ---: | ---: |
| `nsfw=False` | 28,636 | 12,951 |
| `nsfw=True` | 2,468 | 521 |
| `nsfw=NULL` | 0 | 0 |

这些是当前快照，不是所有用户都能收到的推荐数量。题材先按现行白名单和明确同义规则清洗，排除作品名称标签；没有根据标题或简介推断题材。

即使后续允许成人标记作品，目前有题材及身份基础的新增范围也只有 521 部，约为当前非成人有效范围的 4%。还要继续受真实喜好关联、筛选、已有记录、反馈和候选上限约束。成人开关不等于题材扩充，不把“成人”当成用户喜欢的题材，不保证凑满结果。

## 建议产品语义与最终呈现

在现有筛选 Dialog 增加一行 `包含成人标记作品（18+）`，默认关闭。不要在主页面新增大说明卡。

- 关闭：继续仅接受明确非成人作品。
- 开启：在满足访问资格时，允许“明确非成人 + 明确成人”共同参与；不是只看成人。
- 未知分级始终拒绝。开关不代表自动认定作品符合任何地区的法律要求。
- 修改仅是本地草稿，点击“应用”后生效；关闭面板不写入、不改变结果。
- 生效后条件摘要出现 `包含成人标记作品 ×`，卡片有中性 `18+` 标记。首版建议只保持当前页面会话，不保存为长期偏好；恢复默认立即关闭。
- 使用既有推荐结果、详情和资源组件；不新造一套推荐页。

首次启用需要内容提示及访问资格流程。目前账号模型没有出生日期/可靠成年资格数据，不能直接把“已登录”视为成年人，也不能声称勾选声明等于年龄验证。正式开发前需要明确适用人群、访问资格方案、平台政策与地区要求；服务端必须执行相应资格判断，不能只靠前端确认框。

## 必须同步处理的工程边界

1. **统一内容范围策略**：新增独立 `content_scope` / 策略版本，按 `request.user` 的资格计算。默认 `safe`，获准且主动开启后才可 `include_adult`。不全局删除 `nsfw=False`。
2. **全链路一致**：列表、候选复核、详情、证据、加入想看、反馈与撤销/已隐藏读取、身份核对必须走同一受控策略；不能“卡片可见、详情或加入失败”。仍不混用三类 ID。
3. **证据保守处理**：首版不将成人手账自动纳入高分画像；成人候选仅基于现有安全画像/明确偏好的真实共有题材。成人历史画像学习另行讨论，不读取长评、不改评分/标签、不调用外部 AI。
4. **缓存与失效**：内容范围、资格/策略版本进入缓存键、分页快照和证据令牌。开关变化立即取消旧请求、清理详情/资源会话、新建第一页；关闭后任何迟到响应不能回写成人内容。
5. **封面独立策略**：首版建议成人封面用统一中性占位，不回退外部原图。若未来提供真实封面，需受控存储/授权分发；公开 R2 URL 前端模糊不是访问保护。文案和详情内容同样纳入范围校验。
6. **公开与私人分离**：允许私人推荐/加入不等于允许进入公共库展示。保留公共搜索、公共手账和 XHcode 展示的独立安全规则，不能因开关开启而自动公开成人作品。
7. **开关与回退**：独立服务端功能总开关默认关闭；回退只禁用范围扩展并作废对应快照，不删除手账/反馈，也不启用 V2。

## 建议分三阶段（待用户确认后执行）

### N1：访问资格、数据范围与合同

确认允许人群和资格机制；审计分类来源、可展示字段与封面；冻结内容范围合同及安全测试矩阵。未确认资格机制不放行开放入口。

### N2：受控服务与筛选接入

统一范围策略、前后端合同、候选前置筛选、详情/加入/反馈一致性、受限封面、快照隔离；复用筛选草稿和现有组件。V1 算法仍然不变。

### N3：隔离回归与灰度验收

独立 PostgreSQL 验证未获资格、默认关闭、未知分级、越权访问、跨用户/跨模式缓存、旧游标、迟到请求、公共展示隔离、无真实手账字段覆盖；验证一键关闭回退。只有全部通过才讨论开放。

目前未添加任何 NSFW 请求参数、页面开关或安全绕过代码；现有成人和未知分级硬过滤仍有效。
