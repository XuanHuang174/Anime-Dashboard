# 加载链路统一：第一步验收

## 本次实现

1. 路由代码等待：用米白点阵、珊瑚网格页眉、书签手账和主推/便签占位替换原来的白底文字。显示“正在翻开番剧发现手账…”，保留返回手账入口。
2. 接口数据等待：复用相同的海报纸面，保留标题、评分、理由、题材、双操作区及三行口味摘要的骨架位置；少量网格占位按桌面/手机列数收纳。显示“正在读取你的口味与推荐…”，不显示假评分、零样本或可点击的假卡片。
3. 加载超过 8 秒时补充“这次加载较慢，请稍候。也可以返回手账后再试。”，不是超时判定、进度百分比或完成时间预测。改变类别/筛选会重新计时，成功、失败、离开会清理计时器。
4. 骨架采用低对比度呼吸与小书签位移；减少动态效果时静态展示。没有新增图片、字体、网络服务、GSAP 依赖或强制最短等待时间。
5. 页面资源/渲染错误使用独立的重新加载页面入口；接口失败继续使用原有推荐局部重试。加载更多、换批仍保留原有卡片与局部等待/错误，不换成整屏骨架。

## 工程边界

`RecommendationRoute` 仍位于原有 `ProtectedRoute` 内。路由加载组件及 `recommendations-loading.css` 提前进入主入口，不等待推荐页分包；生产构建检查确认 `.rec-loading-route` 存在于入口 CSS。

共享的骨架仅作用于 `.rec-loading-route` 或 `.memphis-rec-container` 内的专属元素。业务请求层、V1 算法、后端、推荐排序、偏好编辑面板及数据库不变，没有迁移或生产写入。

本次只完成加载体验，不开始第二步的宽版三栏偏好面板。

## 部署与回退

只需正常部署前端静态构建，无数据库迁移、不切换 V2。上线后检查首次进入、慢加载、返回手账及异常重试；代码加载失败的恢复需重新加载页面，接口失败只重读推荐。

需要回退时正常回退本阶段代码提交并重建前端即可，不删除手账、偏好、反馈或缓存中的用户资料。
