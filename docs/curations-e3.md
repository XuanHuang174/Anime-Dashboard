# E3：片单收录联动、本机长图与完整验收

接续 [E1 数据与备份](curations-e1.md)、[E2 工作区与编排](curations-e2.md)，完成私人主题片单的入口、观看安排往返、回顾创建和本机图片导出。README 勾选 E3 及“主题片单与私人策展”主项。片单始终仅本人可见，不新增公开发布入口。

## 收录与往返

- 本人手账编辑模式：列表、海报墙和作品编辑详情可直接收录一部；“收录本页作品到片单”只提供当前页候选，默认不勾选。单次手动收录最多 100 部，超过时提示调整分页，不截断选项。海报墙入口放在文字区，避免遮挡评分。
- 可选择已有片单（包括已归档片单），或原子创建片单并收录。重复成员保留原位置与入选理由；收录不会修改评分、长评、状态、进度、历程或安排。结果停留原来源，用户明确点击“查看片单”才跳转。
- 个性化、相似、标签三种推荐共用卡片及详情操作。推荐作品先经身份校验，明确加入或核对私人手账，再独立选择片单。已有记录不被覆盖；取消第二步保留已加入的“想看”记录，不自动创建计划或开始观看。账号或推荐范围变化取消旧请求，迟到响应不打开旧账号面板。
- 片单作品详情保持只读；编辑模式另有“观看安排”入口，沿用现有独立保存与草稿保护。关闭后保留片单、成员页码和当前位置。`/dashboard?curation=<UUID>` 只导航至自己的片单，消费参数后不因再次切换工作区重置分页。
- 编辑详情有未保存修改时禁用收录按钮。收录草稿可继续填写或明确放弃；Esc 只关闭最上层面板，遮罩关闭、键盘焦点与移动端布局沿用片单对话框。

## 从回顾创建固定片单

月度、自选区间、年度回顾均可创建。入口使用**已经应用的期间及签名依据**，不使用尚未提交的日期草稿，也不局限于当前回顾分区或分页。读取完整“确定属于本期”的作品候选，默认不勾选；用户明确选择最多 500 部，一次创建固定手动片单。只有年份的记录可属于年度，不能猜测分配到某个月。

初始简介加入“创建自 YYYY-MM-DD 至 YYYY-MM-DD 的观看回顾（年度／月度／自选期间）”说明，仍可作为普通简介编辑。不复制私人随记、轮次备注、评分或进度。之后调整回顾日期不会自动同步片单成员。

服务端在同一写入事务中锁定账号及私人来源记录，验证原始期间、15 分钟签名、来源指纹和明确选择的作品归属，再创建片单与全部成员。版本冲突、过期来源、记录移除、混入他人作品或超限时整批失败，不留下空片单。丢失回执时沿用原 UUID 与原请求核对；已经成功的原操作可在来源随后变化后重放回执，不重复创建。

## 接口与事务

`POST /api/curations/` 新增两个动作：

| 动作 | 必要参数（共同参数之外） | 限制 |
| --- | --- | --- |
| `create-with-members` | `title`, `record_ids` | 手动选择 1–100 部 |
| `create-from-review` | `title`, `record_ids`, `review` | 完整确定候选中明确选择 1–500 部 |

共同参数仍为 `action`、片单库 `version` 和 `operation_id`。创建动作不传 `list_id`；可带普通片单元数据。`review` 仅接受 `year`、`month` 或 `start/end` 及 `snapshot`。每账号 100 张、每张 500 项、合计 5000 项的原限制继续生效。原 `add` 动作仍最多 100 部。

`GET /api/curations/<UUID>/export/` 一次返回完整片单及最多 500 项成员，包含失效占位，不受详情页分页影响。响应合同为 `journal.curation-export.v1`，包含 `collection`、`entries`、`version`、`snapshot`、`generated_at`；仅接受初始 `version` 或复核 `snapshot`。始终认证本人、`private, no-store`，数据库读取故障返回 503，拒绝部分结果。

导出使用数据库强制的只读一致性快照（PostgreSQL repeatable read / read only；SQLite query_only）。15 分钟签名绑定账号、片单、顺序、理由、成员当前作品资料及库版本；评分／进度等未提升片单版本的变动同样会使旧依据失效。海报身份以存储路径或原 URL 绑定，临时签名 URL 刷新不造成误冲突。复用的回顾签名验证不在写入事务中启动嵌套只读事务。

## 图片与隐私

“导出片单长图”读取整张片单，保留实际编排顺序和失效条目名称。默认只导出名称与作品清单；专题简介、入选理由、观看状态与进度、个人评分、海报均需分别勾选。关闭作品清单同时关闭依赖的成员选项。私人文字可续段，无 Unicode 截断；图片不含访问令牌、签名或公开地址。

月度／自选／年度回顾与片单共用 `PrivateImageExporter`：先完整读取，再测量分页；预览支持适应宽度／原尺寸，缩放不影响输出。每页 900 CSS 像素宽、最多 5000 CSS 像素高，以 1.5 倍生成 PNG；多页 ZIP 保留顺序，最多 100 页。分页在预览前确定，下载不静默改页。读取或生成中取消、关闭、离开或账号变化会停止下载；预览完成、下载前后都会复核来源。海报最多代理读取 24 张、并发 2、每张最多 1.5 MB，失败、损坏或超限显示占位，文字不丢失。

仅发起本机 PNG／ZIP 下载，无上传、分享链接或自动发布。恢复及删除关联继续使用 E1 的 JSON 备份、影响确认和失效占位规则；图片不替代可恢复的 JSON 备份。

- 原 E2 浏览器完整回归通过；C3 月度／自选导出实际下载 3 份、D3 年度导出 16 页 ZIP 和单 PNG 回归通过，含私密选项、长文字、分页、坏海报、资料更正拦截与取消。已人工检查片单导出及小屏预览，ZIP CRC、页数与 PNG 尺寸匹配。

浏览器仅使用 `config.journal_polish_e2e_settings` 和隔离 SQLite `.tools/watch-history-a3.sqlite3`，未操作生产账号或数据库。执行 `scripts/seed-curations-e3-e2e.py` 创建新合成账号，启动本机 8000／5191，在 frontend 配置本机 `PLAYWRIGHT_MODULE`，依次运行上述两个 E3 脚本。完整重跑前重新生成账号。E2、C3、D3 回归分别使用对应新种子，避免复用被更正的来源。合成令牌、数据库、PNG／ZIP、日志均留在忽略的 `.tools` 中。

发布顺序：先部署支持新增创建动作及导出接口的后端，再部署前端；原 E1 的 **0037** 迁移必须已应用。E3 无新增迁移、依赖或环境变量。
