# 作品永久审核与待登记 Bangumi ID 清单

## 本次行为

- 作品审核表“通过结论有效天数”默认 **0（永久有效）**；1–30 仍表示有限天数。内部服务省略 days 时同样默认 0。
- 永久审核明确保存 `never_expires=True, expires_at=None`，审核审计保存 `resulting_never_expires=True`。空截止时间本身不代表永久审核；没有永久标记的缺失截止时间仍无效。
- 历史审核及其审计的新标记默认 False，现有截止时间不改写。需要延长的历史审核应重新读取并由管理员明确提交审核，正常增加版本和审计。
- 永久审核仍可撤销；内容边界、证据编号、规则版本、当前目录指纹、总开关与用户本次筛选全部继续生效。该功能不自动批准任何作品或开启服务。
- 全部作品均为永久审核时，不以作品期限限制会话；浏览快照、签名凭据仍按原 TTL 到期。混合目录继续以最早的有限审核截止时间约束会话。
- 本次修改只针对作品审核，旧人工模式下账号访问授权仍有原来的有效期。

## 部署

1. 在生产正常备份及部署流程中先应用 `0012_content_review_permanent`：`python manage.py migrate`，再由新版后端接收审核操作。本次开发没有执行生产迁移或改写真实作品审核。
2. 迁移新增两个带数据库默认 False 的布尔字段，并更新作品审核约束；不批准作品、不修改旧期限或开关。旧后端不会放行新增永久审核，但新后端需要新字段，不能在迁移前启动新代码。
3. 部署完成后进入 Django 作品审核页，读取单作品，填写依据及确认；有效天数保留 0，提交后检查实时判定 approved 和“永久有效”。
4. 如需回退，先通过既有带审计开关关闭 NSFW 服务。不要直接逆向迁移：存在永久 approved 记录时，旧版“批准必须有截止时间”约束无法恢复。应保留增量字段；需要转换期限时须使用正常审核操作并生成审计。
