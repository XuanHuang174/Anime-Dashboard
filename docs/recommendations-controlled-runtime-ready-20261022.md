## 下一步由操作者完成

### 1. 两个测试账号分别申请

分别登录两个测试账号，进入推荐页的筛选面板，在“NSFW 访问”中阅读并确认提示，点击“申请开启”。这只创建待审批申请，不是开启当前浏览范围，也不是年龄核验。

### 2. 超级管理员审批

进入“管理员控制台 → 模块 3 → 受限内容管理”，选择待审批，逐一读取两个测试账号的审批详情，设置有效期（界面允许 1–30 天）、填写本次测试授权原因并明确确认批准。不是以测试账号自己批准自己。

**此时后台服务继续关闭。** 不审批其他用户、不修改手账评分／标签／长评。

### 3. 少量作品逐条审核

进入现有 Django 管理后台的“推荐作品内容审核”，按确切 Bangumi ID 读取作品，逐条核对完整名称、季度、类型及资料。仅在人工核对当前资料及排除项后提交审核结论，记录真实的内部依据编号与有效期；不得编造审核依据、让系统按标题自动猜测，或把 NSFW 标记当作审核通过。

未知分级不能放行；未成年人或年龄不明人物性内容等禁止情形不能审批通过。本轮不由助手替代内容审核或生成成人内容样例。

### 4. 开闸前核对实际范围

模块 3 的服务开关是全局开关，不是“只允许这两个账号”的新白名单。用户审批与作品审核也不是彼此独立的专属灰度配对：开放后，所有当前有效授权账号都可主动请求当前所有已有效审核放行作品。

因此管理员需先检查是否存在本次范围外的既有有效账号授权或有效作品审核，确认实际开放集合符合“两个测试账号＋少量作品”。如有其他有效记录，先停止并反馈，不能自动撤销其他授权或误称范围已限制为两人。无需为此读取私人手账。

完成后告知两个账号已批准，并提供首批经确认审核的公共目录 Bangumi ID。先做服务关闭状态下的只读核对，确认授权有效、服务仍关闭；再由超级管理员明确执行“准备开启 NSFW 推荐 → 填原因／确认 → 确认提交”。

### 5. 开放态验收与回退

用户默认仍为安全范围；获准测试账号需在筛选中主动开启并应用。验收需覆盖已审核作品可访问、未审核／未知分级拒绝、详情和分页范围一致；真实写入或撤销演练仍需明确范围，不以本轮只读测试替代。

异常时优先模块 3 持久关闸，必要时关闭部署变量；保留所有审批审计与用户数据，不重置控制版本，不切换 V2。详见 [M3 发布／回退清单](recommendations-controlled-m3-release-checklist.md)。
