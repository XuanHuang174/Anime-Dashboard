# 核心 6B：评分语义与页面表达

## 范围

复用 5C 的主推卡、网格卡、详情元数据及原生“为什么推荐？”展开区。
不增加统计卡或仪表盘，不修改任何后端模型、导入逻辑、个人记录、V1 排序或 V2 开关。

## 1. 公共评分来源核实

本阶段通过项目现有真实导入路径核实语义，不为核实评分扫描私人手账或请求外部服务：

- `recommendations/source_pipeline.py:normalize_subject` 从官方归档/API 的 `score` / `rating` 取值，调用 `clean_score`。
- `recommendations/normalization.py:clean_score` 支持 `rating.score`；`None`、空字符串、非法字符串、布尔值、非有限数和越界值均归一为 `0.0`，合法零值也为 `0.0`。
- `recommendations/ingestion.py:normalize_row` 使用同一清洗函数；增量导入缺失评分字段时保留旧值，新建记录模型默认值为 `0.0`。
- `recommendations/api_enrichment.py:merge_metadata` 不以归一化后的 0 覆盖已有非零评分。其旧注释中的“unrated”不能证明每条目录零值的来源。
- `RecommendationAnime.score` 当前为非空浮点数，未保存逐条评分状态、归一化原因或可靠评分人数。
- 5A 的 `quality_audit.score_state` 已将公共 0 标为 `zero_ambiguous`。本阶段与其保持一致，不把 0 当成已证实的低分或未评分。

因此无法从当前单一数值反推某条记录是“无人评分”“原始零值”还是“清洗占位”。本阶段不伪造该来源，不回写数据补状态，也不宣称实施评分可信度修正。

| 输入 | 展示 | 语义 |
| --- | --- | --- |
| 公共合法正数（0–10 内） | Bangumi 评分 7.5 / 10 | 作品公共评价；不是个人分或喜欢概率 |
| 公共 0 | Bangumi 评分 状态待核实 | 标题提示及读屏说明涵盖源站零值、缺失/异常归一化的歧义 |
| 显式公共 null | Bangumi 评分 暂无数据 | 不强制转成 0，不推断作品质量 |
| 非法传输评分、缺失字段、数字字符串 | 原有合同错误及重试 | 不在传输层宽松转型；单独展示函数对异常输入仍返回中性占位 |
| 个人 0 / "0" / "0.0" | 0.0 分 | 用户真实评分，不是未评分 |
| 个人 null / 空串 / 非法值 | 评分数据暂不可用 | 不补为 0 |

个人评分格式化与“高分证据来源资格”严格分开：高分来源继续要求 ≥8.5。个人 0 虽是真实分数，却不能作为高分画像证据；页面不为了显示 0 放宽画像门槛。原手账个人 0 分、标签及长评均不改动。

## 2. 文案与组件合同

- `recommendationCopy.js` 集中维护只读文案，绝不作为排序或写入值。
- `RecommendationPublicScore` 由现有 `RecommendationMeta` 复用，统一覆盖主推、网格和详情；公共标签加粗，保持原行内元数据布局。
- `RecommendationPersonalScore` 在证据区显示“你对《来源作品》的评分：X.X 分”，仅使用结构化 `source.personal_score`，不从当前作品公共评分补值。
- 明确偏好固定标为“来自你选择的题材”，无来源作品、无虚构个人评分。
- 共同题材是关联证据，不代表唯一排序原因、匹配率或喜欢概率。内部排序数值不映射、不展示，未新增任何可信度或概率指标。
- 正文仍为白底，证据仍为青绿色；仅补充行内评分样式及读屏辅助说明。

## 3. 缺失／失效与恢复

- 结构化证据缺失、共有题材无效、来源评分不合资格或理由为空时，显示中性占位，不从标题、简介、标签或长评猜测理由。
- 出现 6A 元数据时，校验证据合同版本、上下文各字段一致性及“非概率／非完整排序解释”标识。部分丢失或不一致则只降级该解释。
- 兼容旧 5C 格式仅限整套 6A 元数据均未出现；不以缺字段绕过一份不完整的 6A 合同。
- 客户端检查不能验证 HMAC 真伪或自行判断服务器是否已变化；详情继续携带原卡片令牌，由 6A 后端负责拒绝过期或跨作品令牌。
- 展开区提供“重新加载推荐”：卡片触发原有快照重载；详情关闭旧面板后重载列表。独立组件没有回调时提供同路由的普通刷新链接。渲染不触发请求或写入。
- 详情 409 及加载失败继续复用既有错误/重试入口，不静默取消令牌请求，不回退 Mock。
