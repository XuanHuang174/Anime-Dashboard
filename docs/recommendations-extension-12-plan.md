# 扩展 12：系列关系与观看衔接

日期：2026-10-25。方向已由用户确认；12A、12B 后端已实现，12C–12F 待分阶段推进。扩展 11 全量开放及验收完成由用户确认，本轮没有重新操作或核验线上账号。

## 产品范围

取消独立的动态本季推荐模块，保持 **个性化推荐｜单番相似｜按标签找** 三个一级入口。围绕“作品有哪些前后关联、这些关联代表什么、我已记录哪些作品”展开。未来季度快捷筛选单独评估，不属于本阶段。

- 详情：增加紧凑的“系列与关联”摘要，查看全部进入系列详情页；复杂关系按组展示，第一版不做可拖拽关系图。
- 私人手账：预览详情可查看关系，编辑窗口继续只修改资料。
- 单番相似：可靠关联与其他题材相近作品分区；相似区的系列排除必须在截断前执行，不能只移走首屏几张卡片。
- 按标签找：保留匹配的不同季条目，增加关系说明，不默认一系列只保留一部。
- 个性化推荐：“你看过的故事，还有后续”作为后续轻量区块；依据本人记录及已确认关系，不把无记录说成没看过，不改变长期偏好。

## 核心语义

1. Bangumi ID 是唯一外部作品身份，标题相似不建立关系。
2. 发行形式与关系种类分轴：剧场版不等于总集篇，OVA 不等于番外。关系是两个条目之间的事实，不能给每个作品强制选一个全局“主线/续作/总集篇”互斥类型。
3. A → B 表示 **B 相对于 A** 的关系；`summary` 表示 B 是 A 的总集篇，`full_story` 表示 B 是 A 对应的完整故事。
4. 故事前后、发行日期、建议观看顺序分开。源关系和来源列表 `order` 不生成必看前置或观看指南。
5. 单条关系、系列归属和同一连续剧情分开；角色出演、联动、相同世界观、改编不做传递合并。
6. 未获取、空观察、部分获取、失败、过期和已观察分别记录；空结果不证明独立作品。
7. 关系不是内容审核、目录收录或加入想看资格。缺少资格的关联节点不能自动进入推荐候选池。

## 12B 的明确输入与门槛

以 [12A 合同与核验记录](recommendations-12a.md) 及 `recommendations.series.assertion.v1` 为基线。建议增量模型分为：

- 公共节点：Bangumi ID、条目媒介、原始发行日期及发行形式、资料状态；可选关联现有目录，不强制目录中存在。
- 来源观察：来源、快照、抓取时间、原文摘要、权限范围及结果状态。导入器必须实际校验原文摘要，合同格式校验不能代替真实性校验。
- 关系断言：源/目标 ID、关系种类、原始值、来源排序、观察版本、有效性与复核状态。允许同一对存在待复核的多个断言。
- 人工修订：保留原始断言，记录修改人、依据、时间、撤销及替代关系，不静默覆盖上游数据。

优先复用官方 Archive 做后台基线，不在页面请求中递归访问 Bangumi。API 仅作独立来源的定向补齐，实时连通性与权限行为须在启用前核验。跨媒介原始关系保留供审计，第一版动画视图不扩展成漫画/音乐推荐。

后台同步设节点/边数、深度、超时和批次上限，遇循环/冲突不强行排成直线；发布日期未知时排后并说明，日期也不能证明已播出或可观看。来源更新导致关系与旧分页不一致时，应明确提示重新读取，不能沿用失效上下文。

12B 先交付按已验证关系读取的局部关联服务。可靠系列归属及连续剧情分组另有审核规则，不能把所有已知关系做无差别连通分量。
