# 快速筛选：评分、状态与完整范围预览

入口仍为私人手账筛选栏的“编辑自定义快速筛选”；管理员精选筛选复用同一编辑器。

## 条件与匹配

- 新增 `score_min/score_max`，可空，范围 0–10，最多一位小数，包含两端。支持只填一边、只设置评分条件。
- `score_state` 为 `any/rated/unrated`。0 分属于已评分；未评分是数据库空值。区间始终排除未评分，与星级、配色、档位和 Bangumi 公共评分无关。
- 填写区间时草稿自动切换为仅已评分；切换不限或仅未评分时清空区间，未评分状态收起区间。服务端把有区间的不限状态规范为 rated，拒绝 unrated 与非空区间的矛盾组合。
- `watch_statuses` 是不重复的有效状态数组：想看、在看、看过、搁置。空数组不限，多选命中其中任意一种。
- `review_state` 为 `any/with/without`。仅含空格、换行及 Unicode 空白（含导入 BOM）视为无长评，前后端一致。
- 年份、评分、观看状态、长评、包含/排除条件组之间为 AND。“包含条件匹配方式”只控制包含标签与中日文标题词之间的任意/全部关系；排除命中任一项即排除。
- 允许纯评分、状态、长评、排除和年份组合；禁止完全没有条件，名称仍必填且同账号不可重复。历史组合新增字段默认为不限，匹配结果不变。
- 本人私人基础标签、个人标签和私人标题/年份继续参与匹配。页面外层搜索、标签、年份及观看状态仍与组合相交，不会被偷偷清空。

## 编辑体验

- 桌面左侧为已保存组合及摘要，右侧分“常用条件”和“标签与标题”。手机/短屏折叠已保存组合；已选标签不因搜索消失。
- 展示完整条件摘要；底部固定数量、范围说明、“保存组合”“保存并应用”“关闭”。内容滚动，窄屏按钮保持可达。
- 保存组合更新配置；保存并应用还会选中组合。修改正在使用的组合后刷新结果并回到第一页，避免停在已不存在的分页。
- 未保存关闭、切换组合或创建新组合时可继续编辑或放弃草稿；删除使用就地确认，不删除作品。
- 原生 dialog 提供键盘约束，使用统一滚动锁与关闭焦点返回。进入/退出 180/140ms，遵循减少动态效果。账号切换关闭编辑器并取消旧请求。

### 标签与视觉调整

- 已保存组合恢复青绿编辑、珊瑚红删除按钮，使用实心笔和垃圾桶图标、黑边与偏移阴影。当前编辑项使用浅绿背景，摘要默认最多两行，可展开查看完整条件。
- 包含标签用青绿勾选态，排除标签用浅红禁止态；两侧各有已选数量、独立已选区和清空按钮。搜索只筛候选，已选标签保持可见；达到每侧 8 个上限后明确提示。
- 候选标签若已在另一侧，显示“改为包含/排除”，点击后从另一侧移除，避免矛盾条件；可撤销最近一次跨侧移动。撤销只恢复两侧标签，不覆盖评分、年份、标题词等其他草稿。
- 条件摘要省略无效占位信息；全空草稿提示先设置条件，随后展示全量匹配预览。

### 独立排序模式

- “已保存的组合”下新增“调整顺序”。进入后读取完整组合和顺序版本，可拖动手柄，或通过上下按钮、手柄上的方向键移动；首尾按钮禁用。移动后焦点跟随原组合，提供位置播报，过渡遵循减少动态效果。
- “保存顺序 / 取消排序”独立于“保存组合 / 保存并应用”。排序期间条件草稿保留；手机暂时收起条件表单，优先呈现排序列表。取消排序不改变已保存顺序，关闭未保存排序会提示。
- 保存失败不自动重放，顺序和条件草稿保留。409 冲突时主动“重新读取顺序（替换排序草稿）”，仅重建排序草稿，不覆盖右侧条件草稿；同一次保存用同步门闩防止双击重复写入。
- 私人手账、共创宇宙打开的公开手账及公开首页统一读取作者顺序；全站精选组合单独排序。所有组合读取入口读取完整分页，避免只显示前 20/100 项。其他已打开页面下次读取时获取新顺序。

`GET /api/quick-filters/order/` 返回 `{filters, version}`，为本人全部组合；`POST` 提交完整 `{ids, version}`。不得重复、遗漏或混入其他账号 ID；序号在普通 CRUD 中只读。版本由 ID 与位置生成，成员或顺序变化返回 409，单纯修改条件不改变版本。

创建、编辑、删除和排序使用同一范围的数据库锁；排序批量原子更新 `sort_order`，不改变条件及更新时间，新建组合追加至末尾，编辑保留位置。`featured-filters/order/` 只允许超级管理员读取和写入，全站范围使用共用锁；公开精选列表仍只读。

## 只读预览

`POST /api/quick-filters/preview/` 提交完整草稿，返回 `{count, scope}`。需本人登录，统计本人全手账，不叠加页面当前搜索、状态或分页，不返回作品数据。已有同名组合不阻止预览，实际保存仍检查重名。

未命名草稿可预览，保存仍要求名称；没有条件时提示先设置条件。合法条件延迟 350ms 请求，变化/关闭时取消旧请求并忽略迟到响应。失败或 429 不自动重试，可主动重试。计数是读取时快照，不把数量当成固定作品集合。

预览不创建组合、不修改作品或更新时间，响应为 `private, no-store`。保存失败不重放，草稿保留；同步门闩阻止双击重复写入。

服务端分页、私人/公开列表、预览及标签整理沿用同一完整记录过滤入口。只有评分/观看状态时直接在 SQL 中过滤计数；需要标签、年份或长评时再检查元数据。前端“全部作品”模式使用相同规则。

## 精选兼容

`FeaturedQuickFilter` 同步支持新字段，作用于作者投稿快照的评分、状态和长评。公开精选只读公开投稿；`POST /api/featured-filters/preview/` 仅超级管理员可用，范围明确显示“全部未拒绝投稿”。不向普通用户开放管理计数。

管理员列表适配器补齐日文标题、年份、评分、观看状态及长评；公共精选的仅年份资料增加专用筛选日期，展示文本不变。编辑公共筛选不修改投稿快照或作者手账。

## 迁移与部署

新增 `anime/0030_featuredquickfilter_review_state_and_more`：两个组合模型各增加五个字段，以及评分范围顺序、未评分不得带区间的数据库约束。旧行使用空边界/不限状态，不清洗历史条件或作品。

排序新增 `anime/0031_alter_featuredquickfilter_options_and_more`：两个组合模型增加 `sort_order`，按各账号原有 `created_at, pk` 顺序填充位置，全站精选单独编号；不根据名称重排，也不重置用户条件。后续通过排序界面调整成用户希望的顺序。

先执行 `python manage.py migrate --noinput` 并更新 Render 后端，再发布 Cloudflare 前端。没有新增环境变量或依赖。仅使用本地隔离数据库和合成浏览器数据，未执行线上迁移或真实账号写入。
