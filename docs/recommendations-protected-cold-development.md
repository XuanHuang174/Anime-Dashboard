# 保护型 V2 公共冷启动读取协议

本轮不调排序、题材规则或门槛；不采用已失败的整体画像替代/等权双视图实验。线上默认继续 V1，新增能力只供显式离线诊断，不由 HTTP 参数或服务开关启用。

## 修正范围

1. **精确目录版本**：旧路径传回全目录 `(pk, SHA256)` 列表后计算 JSON 摘要；新路径在服务器生成完全相同的 JSON 字节摘要，只返回一行。包括不安全目录项的分级变化，原版本语义不变，并非 `MAX(updated_at)` 猜测。
2. **消除重复读取**：公共索引构建时已经得到原始题材、标题、评分、季度、类型。新 `public-bootstrap.v1` 直接利用这些公共元数据，每次把本地完整行摘要与服务器当前安全目录摘要比较，避免排序时再下载一份。
3. **预备公共快照**：可将七个公开字段写入本地签名 gzip 快照，在新索引/reader 实例中从磁盘读取并重建 IDF/特征。浮点评分采用 IEEE754 字节编码，两端摘要一致，不猜 PostgreSQL 浮点文本格式。
4. **事务往返**：仅新离线路径将两个事务属性合并为一次 SELECT，仍同时验证只读和重复读。普通路径不改变。

所有摘要比较都发生在 PostgreSQL 强制只读重复读事务；保留候选水合、来源分级复查和用户隔离。快照内容改变、分级改变、新增作品或范围不一致会返回明确失效，不静默使用部分新旧目录。快照不含用户、评分长评、偏好、反馈、证据、结果或图片；其中 `score` 仅是目录公共评分。

## 不把成本藏到指标外

首次生成快照仍需读取全目录，文件生成成本单独记录，不能声称从未准备数据的部署也无成本。应用运行前准备公共快照、跨副本分发、共享缓存和生产目录更新流程尚未部署。本轮只验证机制；新实例逻辑冷读不等于重启 OS、Render 冷启动或完整 HTTP 首屏。

测试同时记录：用户画像读取、旧/新版本校验、强制未命中公共缓存的索引构建、未优化保护型 V2、元数据复用首次调用、快照生成、磁盘快照重建索引后首次调用、三次后续调用。真实账号只取原冻结账号中主键最小的一个，按既定规则选取，不根据效果挑选。不进行新的留出质量评测。

## 执行

先运行本机独立 PostgreSQL 的固定回归并生成当前代码凭据（测试库变量与现有文档一致）：

```powershell
.\.venv\Scripts\python.exe manage.py verify_unused_holdout_validation --output .tools/v2-cold/20261019-tests/tests.json
```

然后正常数据库配置下只读诊断：

```powershell
.\.venv\Scripts\python.exe manage.py profile_recommendation_cold_read --confirm-sitewide-readonly --prior-site-lock .tools/v2d3/20261018-expanded-freeze/cohort.lock.json --test-report .tools/v2-cold/20261019-tests/tests.json --output-dir .tools/v2-cold/20261019-profile
```

输出必须为新目录，私有凭据及公共快照仍放在被忽略的 `.tools`，不提交、不自动覆盖或删除旧文件。所有业务写入、并发测试只在隔离 PostgreSQL。原 5000ms/6 SQL 门槛不放宽；引擎时长、快照准备成本和端到端首屏不得混用。

## 后续闸门

冷读验证不代表 V2 质量通过。依然需要：保护型基线的召回/相关性修正及人均不退步；预注册独立自然验证；部署环境冷/热延迟、版本游标与回退验收。在这些条件满足前，V1 是正式稳定版本，失败实验只留作复现。
