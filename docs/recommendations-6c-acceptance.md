# 核心 6C 验收报告与遗留项

## 结论与范围

本阶段补齐状态闭环的自动化回归、客户端页/证据版本防串台、只读部署验证脚本与回退操作文档。
不改变候选池或排序公式，不启用线上 V2，不修改正式用户的评分、题材、观看状态、偏好或长评。

本地验证通过不等于部署后的页面交互已通过。完整 6C 结案需按下面的部署检查及浏览器清单补验。

## 状态重载保障

- 手账评分/标签更新、删除等成功操作已有无私人数据的失效通知；身份确认与加入想看成功后显式重载。
- 新进入推荐页执行三接口重读；窗口重新可见、focus、bfcache 恢复或其他标签页通知通过原有订阅合并触发读取。不新增后台轮询。
- 编辑偏好等面板打开时保留草稿并延迟自动刷新，关闭后补刷；“实时”指已知操作成功或重新进入/前台恢复后重读，不承诺感知任意后台改库的瞬时变化。
- 已取消的详情或分页响应不能提交。新分页除令牌外，还核对页号、页大小、算法、题材/特征/证据合同版本、画像与偏好上下文。
- 首屏卡片证据上下文必须与该页一致；详情核对原卡片的令牌和上下文，错误只显示重载入口，不静默换依据。
- 公共缓存不存私人口味；不读取个人长评，不调用外部模型。

## 遗留与明确限制

1. SQLite 不能验证 PostgreSQL 的真实行锁竞争；现有 `WantConcurrencyTests` 四项在此环境跳过。需另行准备隔离 PostgreSQL 测试配置后补跑，禁止使用正式 Neon。
2. 真实归档样本的可选导入测试未指定样本文件时跳过；不为本阶段重新导入正式数据。
3. 部署后的手机/桌面点击行为、返回手账再返回推荐、偏好面板草稿保护需用正常授权的内置 Browser 或人工验收；SSR/函数测试不能替代浏览器测试。
4. 单一授权账号的 GET 验收不能证明真实多用户切换或线上并发写入；相关边界由隔离样本测试覆盖，真实验证不得扫描其他用户。
5. profile/preferences/list 是独立 GET，不宣称三接口拥有数据库级原子快照。现有冷启动/偏好一致性检查、证据上下文和下一次重读用于拒绝不一致；若读取期间连续编辑，应重载，而非混用结果。
6. 约 871 KB 既有主包体积警告仍在；本阶段不调整分包阈值，也不将诊断耗时等同 V2 性能批准。
7. 6C 增补的安全测试纳入发布指纹，旧 V2 批准凭据不适用于新代码。当前仍保持 V1。
