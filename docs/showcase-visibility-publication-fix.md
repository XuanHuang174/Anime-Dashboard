# XHcode 公共番剧搜索可见性修复（阶段 1）

2026-10-23 更新：当前已补齐审核有效的一般成人作品公共发布，参见[主理人一般成人作品公共发布](showcase-general-adult-publication-20261023.md)。下文记录此前阶段的范围及验证，旧的“所有 NSFW 拒绝”规则已被新实现替代。

## 范围与兼容性

修复“普通用户先创建非公开共享资料，XHcode 后加入时仍不可被公共搜索找到”的状态衔接缺陷。普通添加、推荐想看、Bangumi 收藏导入统一调用 `anime.showcase_services.publish_new_showcase_record`；标准 records 创建接口也复用该规则。

不修改推荐 V1/V2、排序、标签映射、资源搜索或前后台浏览连续性。公开搜索仍只读且仍要求 XHcode 拥有记录、共享资料 `is_active=True`，不在 GET 请求中修复数据。未新增业务表或前端控件。

## 新字段与状态来源

`Anime.hidden_reason` 仅在 `is_active=False` 时有意义：

| 值 | 含义 | XHcode 新建手账记录后 |
| --- | --- | --- |
| `private_only` | 推荐加入/Bangumi 导入新建的仅私人共享资料 | 可以公开 |
| `showcase_removed` | 主理人曾删除且仍被其他用户引用 | 明确重新添加可以公开 |
| `admin_retired` | Django 管理后台明确关闭公开状态 | 保持隐藏，返回待审核通知 |
| `legacy_unknown` / 空值 / 未知值 | 历史资料或缺少可信隐藏原因 | 保持隐藏，返回待审核通知 |

0023 迁移只增加字段、调整帮助文字，不修改任何 `is_active`、手账、评分或标签。所有旧行新增字段取 `legacy_unknown`；已公开行不受该原因字段影响。默认原因同时设置 `default` 和 `db_default`，滚动部署期间旧进程仍可使用旧列清单 INSERT。

## 写入与隔离边界

- 仅服务端配置的准确用户名可触发公开协调，昵称和外部传入 ID 不提供权限。
- 只对**本次确实新建**的主理人手账记录执行协调；已有记录重试、读取、编辑、核对身份和导入已有记录不偷偷恢复公开。
- 推荐接口先保留现有 NSFW/未知分级、身份确认、容量、长度、幂等校验；公开服务不替代任何校验，也不按标题猜测身份。普通手工作品不必存在于推荐库。
- 共享资料行锁下重新核查当前隐藏原因，仅允许更新 `is_active`、`hidden_reason`、`updated_at`；不把任何人的私人资料复制回共享行。
- 沿用入口现有用户锁/事务，创建与公开在同一事务提交，失败一起回滚。不同用户仍各自拥有记录。
- 普通用户复用隐藏资料不更改公开状态。管理员的明确下架不能因导入补空字段或创建竞争而被覆盖。
- 主理人删除仍保留旧语义：没有其他引用时删除共享资料；有其他引用时只隐藏，并标记 `showcase_removed`。已隐藏的管理员/未知原因不被重标记。迟到的清理调用发现主理人已有新记录时不再隐藏。
- 收藏导入对本人已有记录的原有更新语义不改变；新增公开服务不增加任何个人字段写入。其他人的记录始终零改动。

## 增量响应通知

XHcode 创建记录响应可增加 `showcase_publication`：`published` / `already_public` / `review_required`。待审核不代表私人加入失败，不回滚正常私人记录。普通用户和公共读取不返回这个通知；公共读取不暴露隐藏原因。

收藏导入批次增加 `showcase_publication_notices`，最多列出 5 项待审核作品的 Bangumi ID 与通知。不含其他用户信息、长评或评分。当前阶段提供后端通知合同，不新增前端弹窗。

## 2026-10-21 补齐：历史隐藏作品的页面确认闭环

### 第二次复现与缺口

“少女手工”（Bangumi 331445）在新代码部署后加入，仍复用了较早创建的隐藏共享资料，其原因为 `legacy_unknown`。第一阶段的自动协调按设计阻止这种未知来源直接公开，但页面没有处理 `showcase_publication.review_required`，使“加入手账成功”看起来等同于“公开成功”。先前对一个作品的定向修复不代表所有历史资料的使用闭环已完成。

自动规则不放宽；历史原因不能靠相似标题、创建时间或没有后台日志猜成私人来源。本次补充用户可见的、单作品的明确公开确认，不批量翻转历史状态。

### 新接口

- `GET /api/records/showcase-publication/?page=1`：要求登录。只有配置的主理人返回自己的待公开作品，其他用户返回 `can_publish=false` 和空列表。只接受单个正整数 page 参数，每页 12 条，稳定按记录主键排序。只读查询不选择评分、长评或标签字段，不触发任何修复。
- `POST /api/records/{record_id}/publish-showcase/`：仅接受 `confirm_publication: true` 和 GET 签发的 `ticket`。用户、手账记录 ID、共享 Anime ID、Bangumi ID、当前隐藏状态及资料更新时间绑定在服务端签名中，有效期 10 分钟。不能用其他用户 ID、Bangumi ID 替代记录 ID。
- 两接口均为 private/no-store，并 Vary Authorization/Cookie。普通用户无法利用主理人的 ticket 写入。
- 确认使用事务和用户、记录、目录、共享行锁。管理员下架、未知的非白名单隐藏原因仍拒绝；已有 Bangumi 身份需有当前非成人的目录资料，缺失/NSFW/未知分级拒绝；明显身份冲突拒绝。无 Bangumi ID 的手工作品可以由主理人明确确认，不猜测或补写身份。
- 资料/状态变更或凭据失效返回 409，需要重新读取再确认。已成功公开的同一有效凭据重试返回 `already_public`，不再写入。
- 只更新共享资料的公开标记、隐藏原因和更新时间；不新增或改写任何用户记录、私人配色、评分、长评或推荐设置。

### 页面闭环

- 推荐页与私人手账页复用 `ShowcasePublicationPanel`。只有主理人存在待公开作品时才展示管理入口；普通用户无管理面板，公开/共享浏览页也不挂载。
- 推荐加入返回 review_required 时明确显示“已加入手账，但尚未公开”，并指向“公共库待公开”。标准添加及收藏导入结束后，复用手账现有刷新键读取待公开状态；旧的待公开作品也可在重新进入页面时处理。
- 面板逐作品展示名称、原名、季度和已知 Bangumi ID；默认不勾选。必须勾选“我确认将本账号这部作品的手账信息公开展示”后才能确认。
- 显式提醒公开展示会包含本账号对应记录的评分、长评、观看状态和标签，不伪装成仅公开海报。
- 不创建第二套弹窗；使用原生 details 内联区域，适配窄屏。无批量公开按钮，管理员下架条目显示需管理员核对。
- 请求代次、AbortController 和账号会话作用域阻止旧响应串台；快速连击只发一次确认。失败保留条目，409 要重读并重新勾选；“确认已保存但列表刷新失败”单独显示，重试只 GET，不重复 POST。无 Mock 回退、不持久化私人列表或签名到本地存储。
- 不改变 V1 排序、原有加入想看幂等规则、资源会话或前后台浏览连续性。
