# 手账往返与系列回顶补齐

本轮补齐批次 C 未覆盖的“手账详情 → 相似/标签探索 → 返回手账”，并修复系列页回顶和详情按钮对齐。

## 原因与修复

系列覆盖页由外层 `dialog` 滚动，内层 `.rec-dialog-body` 随内容自然撑高。
旧回顶组件固定监听内层正文，实测外层 scrollTop 为 500 时内层仍为 0，因此不会显示。
现在按祖先元素的 CSS `overflow-y` 查找实际滚动容器，监听和点击共用相同解析；
直接打开的系列页面仍以 window 为滚动目标。嵌套详情打开时保留原有隐藏规则。

推荐、相似、标签和人物作品详情的固定底栏统一靠右；手机换行仍靠右。
系列关联作品详情也将想看和资源入口放入共用固定底栏，并沿用原有写入与资源状态。

手账以前进入相似/标签探索会卸载，返回后搜索、标签、年份、状态、排序、快捷组合及页码
恢复默认值。推荐内部缓存只由推荐主机持有，无法保留它外面的手账。
现在路由主机在从私人手账进入三种推荐模式时保留一个原页面，隐藏并设为 inert；
探索期间卸载原手账的预览/编辑弹窗并暂停通知轮询，保留选择和筛选，释放弹窗的正文滚动锁。
返回时恢复原预览与窗口滚动位置。不同推荐路径及其系列/人物覆盖页可继续使用原路由机制。
直接从手账进入系列或人物模块仍走它们已有的原页保留机制，避免重复挂载手账。

无写入的往返不会重读记录；仅位置对象变化不再触发列表加载。
有确认写入时，原页在返回后按原条件刷新。探索确认自己写入时使用 `local:false`，
不会发出普通推荐重载事件，因此返回处理也监听其配套的 `series-reminders-data-changed` 通知。
这不会重放 POST，原有失败/不确定写入流程保持不变。

原页仅由当前路由主机内存持有，以账号会话为边界；没有将记录、认证或返回状态存进浏览器持久存储。
切换账号会卸载旧原页。离开探索链路或整页刷新后不保留这次往返状态。
