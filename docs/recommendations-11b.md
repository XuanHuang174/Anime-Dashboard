# 扩展 11B：单番相似后端

日期：2026-10-24。状态：接口与隔离回归完成，生产探索开关默认关闭。完整导航和可视页面在 11C 接入；按标签找的结果执行仍留给 11D。

## 交付与边界

- 单番相似真实排序、前置筛选、独立证据、签名分页快照、详情和前台上下文检查。
- 复用只读事务、现行题材/别名、公共特征索引、精确目录指纹、身份绑定和内容范围；没有改写个人推荐排序或启用 V2。
- 复用当前想看与反馈服务；没有新增业务表、迁移、推荐历史、私人结果缓存或外部请求。
- 导航文案保持“个性化推荐／单番相似／按标签找”，当前项追加“· 当前”；本轮没有向线上挂载未完成的页面入口。

## 排序和硬筛选

参照从当前范围的推荐目录按 Bangumi ID 读取，使用其有效标准题材。类型、公共评分和年份只约束结果，不要求参照也满足这些筛选条件。

初始请求执行一次：

1. 读取全部当前范围目录的版本化公共特征和 IDF 权重。
2. 前置执行类型、年份、公共评分区间、隐藏已有记录和作品隐藏反馈。
3. 始终排除参照自身；候选至少有一个共同题材。
4. IDF 加权余弦降序，同分依次按参照题材加权覆盖率、公共评分降序、Bangumi ID 升序。
5. 记录完整合格数量，截取最多 120 项固定顺序，每批 24 项、每页 12 项。

不存在“先截取旧的 400 个候选，再做严格筛选”的步骤。IDF 基于本次范围的完整目录，不随结果筛选或翻页重新拟合。没有题材时返回 `seed_without_topics`；有题材但没有合格作品时返回 `no_matches`，均不拿热门结果填充。

可将已在手账中或已隐藏的作品明确选作参照，但它不会作为结果出现。默认隐藏全部已有观看状态；关闭该条件后返回相应状态，加入操作仍遵守原有幂等和身份确认规则。系列识别和总集篇分类仍属于扩展 12。

## 接口

均要求登录、现行读限流、`private/no-store`，内容范围参数沿用 `content_scope`；不接受客户端指定用户或算法。

| 接口 | 请求与行为 |
| --- | --- |
| `GET /api/recommendations/explore/` | 初始查询使用 11A 的 `intent=similar&seed_bangumi_id=...` 及筛选；续页仅传 `cursor` |
| `GET /api/recommendations/explore/<bangumi_id>/` | 必须提供本次结果签发的 `detail_context`；可提供 `evidence_token` 严格核对卡片依据 |
| `GET /api/recommendations/explore/context/` | 使用 `snapshot_context` 检查现有查询、目录、范围、已有记录和反馈是否仍有效 |

目录选择和合同描述接口继续保留。`intent=tags` 的执行返回明确 503、`exploration_intent_unavailable`，不会转为个人推荐或伪造空结果。游标与初始条件混用返回 400。

### 列表响应

版本为 `recommendations.explore.v1`，算法为 `similarity.v1`。主要字段：

- `query`、`selected_seed`：规范化已应用条件及公开参照资料。
- `eligible_count`：所有硬筛选后的合格数量；`returned_count`：当前有序快照数量；`result_limit=120`。
- `snapshot_id`、`snapshot_expires_at`、`snapshot_context`。
- 批次、页码、批次首推 ID、下一页/下一批游标及耗尽状态。
- `results`：受控作品资料、当前观看状态、理由、证据、证据令牌与详情上下文。

例如：

```http
GET /api/recommendations/explore/?intent=similar&seed_bangumi_id=123&type=OVA&year_from=2008&year_to=2012
GET /api/recommendations/explore/?cursor=<本次签发的下一页游标>
```

ID 仅作请求格式示意，不代表本轮读取或放行了某部真实作品。

## 快照与隔离

- 所有计算在独立 PostgreSQL `REPEATABLE READ, READ ONLY` 事务内执行；不接受 SQLite 或嵌套写事务替代。
- 游标固定公开查询和结果 ID 顺序，包含经过密钥保护的用户、目录/范围/身份状态、隐藏反馈与规则版本绑定。没有个人评分、私人题材、长评、用户名或明文用户 ID。
- 续页只验证上下文并读取已签发的 ID，不召回、不排序、不重建公共索引。同游标重试和并发读取返回同一位置。
- 游标、详情与上下文检查采用不同签名命名空间，不能互换；详情还绑定具体候选 ID。
- 固定绝对有效期最长 15 分钟，受内容范围期限进一步约束。续页和详情刷新不会延长原期限；永久审核的空到期时间正常支持。
- 目录指纹包含直接 UPDATE 及分类/简介/封面变化，不依赖最大更新时间；响应离开只读事务后再次检查目录与作品安全，覆盖零结果和上下文检查。
- `RECOMMENDATION_EXPLORATION_EPOCH` 默认 `1`。关闭/重新开启或发布时应统一更新所有 worker 的代次，旧上下文不会在新代次复活。

公共特征缓存继续按精确目录版本及内容范围区分；没有共享私人推荐结果。公共缓存故障可计算回源；限流缓存故障仍明确不可用，不绕过限流。

## 身份与个人资料

已有记录只用于解析正确身份、排除已收录作品和展示观看状态。`resolved_records` 增加可选的精简投影，默认调用保持原行为；探索显式选择不含个人评分、自定义标签、私人基础题材的投影，也不查询长评或私人简介。

身份匹配仍复用原有已确认映射和指纹，必要的本人名称/季度字段仅用于验证映射。缺失或过期映射不会按名称自动补齐、合并或写库。身份表未就绪时探索明确不可用，不悄悄忽略已有记录。

个人评分、长期偏好和长评变化不影响单番排序，也不会仅因这些变化使游标失效；解析后的已有 ID/状态、目录或隐藏反馈变化会使旧结果失效。

## 证据与详情

使用独立的 `recommendations.explore.evidence.v1` 和 `selected_work` 来源。共同题材严格等于参照与候选的标准题材交集，理由形如“与参照作品《…》共同包含「音乐」「日常」题材”。不读取或伪造个人打分，不解释成喜欢概率。

列表和严格详情的证据、证据上下文、理由和令牌一致。证据令牌绑定当前用户、快照、候选、版本和实际解释，不能拿一部作品的令牌查看另一部。

详情有两种读取方式：

- 带 `evidence_token`：严格要求卡片上下文仍有效；状态/目录等变化返回 409。
- 仅带有效 `detail_context`：保留原参照和条件，读取完整最新资料、观看状态及证据。用于想看操作确认后的整份详情重读，不重新推荐列表，也不延长原有效期。隐藏、无共同题材或不再符合硬筛选的作品仍拒绝。

刷新详情不会把旧列表升级成新列表；旧列表仍需重新加载。想看、反馈、撤销和资源服务的写入语义没有变更。

## NSFW 范围与客户端

默认安全范围；主动包含成人目录时，参照与结果都必须通过当前总开关、审核和边界检查。未知分级不进入。永久审核允许 `scope_valid_until=null`，成人封面继续中性展示，公共库发布政策不受本轮影响。

客户端新增探索列表、详情和上下文检查方法，并传播显式范围。普通探索快照变化使用 409 + `exploration_snapshot_changed`：丢弃旧结果，但保留仍有效的 NSFW 浏览选择。实际范围校验失败继续按原流程通知范围变化。

能力响应现在声明 `supported_intents=[similar]`；开关开启时 `query_execution_enabled=true`。导航页面可用标记仍只有个性化推荐为 true。11A 的公共合同 fixture 与新前端校验已同步，旧个人推荐解析不变。
