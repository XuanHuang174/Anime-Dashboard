# 基础 2：番剧发现手账 UI 样刊

本阶段仅交付独立页面骨架、响应式卡片及状态演示。未接入推荐算法、推荐 API、用户画像或正式手账写入。页面始终显示“设计预览 / 静态样本”说明，不能把 Mock 结果解释为用户个人推荐。

## 路由与入口

- `/recommendations` 复用 `ProtectedRoute`，未登录跳转 `/login`；按需加载页面与独立 CSS。
- 私人 Dashboard 预览模式的推荐 Banner 改为 React Router Link，徽标为“界面预览”。共享手账原本不展示该 Banner，不改变原有访问边界。
- 返回入口为 `/dashboard`，不携带其他人的用户名或手账内容。

## 组件与数据边界

- `frontend/src/pages/Recommendations.jsx`：状态调度、筛选草稿、偏好演示、详情、通知。
- `frontend/src/components/recommendations/RecommendationCard.jsx`：主推/普通卡片、封面、元数据与操作。
- `RecommendationDialog.jsx`：原生 modal dialog 顶层浮层、背景 inert、焦点陷阱、Escape、关闭后恢复焦点。关闭面板丢弃未应用的筛选/偏好草稿。
- `RecommendationStates.jsx`：冷启动、静态低对比骨架屏、空结果、请求失败。
- `frontend/src/styles/recommendations.css`：所有规则限定 `.memphis-rec-container`；不改全局主题或原手账组件。
- `frontend/src/data/recommendationPreview.js`：8 条公开番剧资料静态快照、2 条占位案例及成人/未知分类过滤测试样本；ID 使用 `demo-*`，不是业务记录 ID。文案与评分非实时，简介/推荐理由是明确标注的示意。
- `frontend/src/utils/recommendationPreview.js`：纯函数封面地址校验、分类过滤、状态判定、幂等演示想看。

图片仅允许 `https://media.xh-anime.com/covers/{正整数}.jpg`，可携带既定格式的版本参数；拒绝其他域名、凭证、端口、路径与查询参数。不接受外部原图作为回退。缺图或图片加载失败均展示米白 CSS 网格占位海报。成人与未知分类始终过滤，UI 中没有解除过滤的开关；真正的内容权限仍需下一阶段在后端实施，前端过滤不是安全授权边界。

“+ 加入想看”只更新当前页面内存演示记录，不发送 POST/PATCH，不访问 localStorage，不写 Neon。已有记录原状态、评分和长评原样保留；重复加入返回同一记录，退出或刷新后演示操作重置。后续接入正式功能必须以 Bangumi ID 进行明确映射，并使用服务端幂等创建/返回已有记录接口，不允许通过前端 PATCH 覆盖已有手账。

偏好设置只影响演示便签，不保存到服务器、不改变排序，也不会让冷启动场景凭空产生个性化结果。页面不显示未定义的匹配百分比，不把 Bangumi 评分当作推荐匹配度。

## 状态与布局

- 默认是明确标识的静态结果展示。
- 页面底部“样刊验收台”可切换正常、加载、喜好不足、空结果和失败；重试模拟短暂加载后恢复静态结果。切换场景会取消旧的重试定时器，不保留失效请求回调。
- 类型、评分和隐藏已有演示记录可组合筛选；应用前取消不影响当前结果。空结果支持重新加载、恢复筛选。
- 1100px 起网格 4 列，768–1099px 为 3 列，360–767px 为 2 列，低于 360px 为 1 列；手机便签压缩，筛选/偏好面板变成贴底面板。
- 不使用闪烁骨架或持续动画；按钮微互动遵循 `prefers-reduced-motion`。

隔离样刊没有认证令牌、后端访问或生产写入；正式 `/recommendations` 未登录跳转 `/login` 已单独通过浏览器验证。截图和本地验收入口位于 Git 忽略的 `.tools/`，不进入构建产物；不以绕过真实登录来验证受保护页面。

后续接入点：真实推荐数据 provider、真实用户画像、服务端成人过滤、可解释推荐证据、用户已有手账状态映射及幂等加入接口。替换 Mock 后应移除样刊验收台及演示文案，而不是直接把这些模拟状态当作真实业务结果。
