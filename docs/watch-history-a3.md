# 观看历程 A3：管理边界、紧凑时间线与清空恢复

## 入口与模式

编辑详情左侧依次为“删除私人记录”“观看历程”，右侧为保存和关闭。历程按钮改为白底，保留黑边、偏移阴影和按压反馈。预览详情的白色历程入口保留青绿阴影，接入现有详情分块入场；内部展开使用短过渡，减少动态效果时停用动画。

预览只读：可展开、查看轮次、筛选和分页，不提供随记、状态变更、撤销或清空。显式点击“前往编辑模式管理”后切入编辑模式，并直接打开该作品的历程工作区。公开手账和精选快照仍没有私人历程入口与请求。

编辑中的历程是同一个详情容器内的独立管理工作区，不叠加另一层弹窗。标题标注“观看历程管理”，底部提供“返回作品编辑”。保留作品编辑页签与滚动位置，历程成功响应同步最新作品状态；作品草稿未保存时禁止进入，历程草稿离开时可继续或明确放弃。保存处理中不能离开，账号变化忽略迟到响应。可修改身份绑定的“核对标准作品”入口明确说明进入编辑模式；评分展示配置仍可从预览打开。

标记完成而已看集数不足时，要求明确选择补齐至总集数或保留填写值，不隐式补齐。总集数未知仍允许记录完成。日期保持未知、年、月、日精度，不用系统时间反推观看日期。

## 时间线

- 默认最近 5 组，可切换 5／10／20 组；上下均提供分页，翻页定位到时间线标题。
- 分类为全部、状态与进度、重看、随记与补录、更正与撤销，在后端筛选后分页。
- 默认显示动作、实际日期、变化摘要及短随记。全文、来源、系统时间在“详情”中展开。
- 已撤销操作与撤销事件合并为“原操作 · 已撤销”，详情内可核对原事件及撤销时间；实际事件仍完整保存。
- 只允许撤销最近一次非撤销操作，较早资料通过轮次更正处理。筛选后的最新条目若并非真实最新版本，不提供误导的撤销按钮。
- 重新获得窗口焦点时安全重读；草稿不丢弃，版本变化仍须显式核对。结果未知的写入不自动重放，沿用原 UUID 重试。

GET `/api/records/<id>/watch-history/` 新增可选 `category=all|progress|rewatch|notes|corrections` 与 `compact=true|false`。旧调用保持原始事件分页。响应增加 `total_count`（原始事件数）、`base_revision`、分类和合并信息；合并撤销事件附带 `undone_event`。备份始终导出全部原始事件，与展示筛选无关。

## 清空本作品历程

仅编辑工作区“历程管理”内提供清空。先列出轮次、原始事件数量及删除范围，可下载完整 JSON 备份；勾选明确确认后才能提交。确认期间数据变化需取消并重新核对，清空不能通过最近操作撤销。

清空删除该作品全部事件与轮次，含随记、补录、轮次评分、备注及日期。保留私人作品、当前观看状态与进度、综合评分、长评、标签、海报等资料，再以日期未知的当前状态建立第 1 轮基线。重看记录数重新计算。没有隐藏内容副本或可恢复的事件快照；旧 JSON 备份仍可有意恢复内容。

POST 原接口新增 `action: clear`、`confirm_clear: true`，仍要求当前版本和操作 UUID。事务中锁定记录、删除子数据、递增版本并建立基线。`watch_history_base` 是事件序列的清空边界，版本不会归零。保留最后一次清空的 UUID 与仅含请求摘要的哈希收据，不保留私人内容；原请求重试返回当前结果，清空前的旧版本请求返回 409。旧事件 UUID 不会因删除而重新执行。普通模型保存读取锁内最新屏障和收据，避免旧实例回写覆盖。

迁移 0034 增加三个私有内部字段，不暴露到公开序列化。JSON 外层仍为 `anime-journal` v2、内层历程 v1，新增可选 `base_revision`，旧备份默认 0。事件必须从边界后连续至当前版本，清空后的空事件备份也可完整往返。清空收据不导出；整体恢复创建新私人记录，不沿用旧记录主键。

## JSON 恢复确认

前端先上传至 `POST /api/import/?preview=true`。服务端完成原有格式校验，仅计算影响，不导入或创建作品，返回：

- 文件作品数，带完整历程的作品数、轮次和事件数；
- 已有历程被文件替换的作品数；旧格式准确匹配后保留历程的作品数；日期未知起点数；
- 文件外将移除的作品数、相关事件数及最多 20 个标题。

确认说明完整备份可能恢复已经清空的随记，旧格式仅在准确匹配时保留历程，有歧义拒绝。可先导出当前 JSON；勾选后发送原文件和 `confirmation_token` 至 `POST /api/import/?confirm=true`。

确认凭据签名绑定当前账号、完整文件内容、当前手账及评分配置，有效期 10 分钟。确认时按用户→作品主键顺序→配置锁定，文件或状态变化、账号不符、过期均拒绝并要求重新预览。原子替换仍使用既有导入服务。为兼容既有脚本，不带 `confirm=true` 的旧导入契约保持原行为；新版网页始终使用预览及确认路径。

导入结果未知时不宣称原数据未变，不自动重复导入，禁用原确认并提醒先检查手账，再重新预览。草稿和令牌不存入公共存储；账号切换忽略旧结果。弹窗支持键盘焦点约束、错误定位和窄屏滚动。

## 验证与发布

隔离 PostgreSQL 101 项关联回归通过，包含清空事务回滚、版本屏障、同 UUID 重复清空、清空与旧版本写入并发、隐私、完整与旧格式备份、恢复预览、凭据账号/文件/状态/有效期绑定。前端 495 项测试通过，增加分类分页参数保持、合并事件校验、清空结果不明后的同 UUID 重试。原 36 项布局浏览器回归和 A2 异常流程浏览器回归继续通过。

`frontend/scripts/test-watch-history-a3.mjs` 连接真实本地 Django 和专用 SQLite 合成数据，验证编辑入口、草稿与页签、只读边界、日期、完成选择、重看、撤销合并、分页、独立评分、清空成功但响应丢失后的安全重试、恢复影响、过期状态拒绝、旧备份恢复和恢复结果不明保护。覆盖 320／390px 手机、844px 横屏、桌面和正常／减少动画设置。所有账号、凭据、数据库与截图仅在忽略的 `.tools` 中。

本地运行使用 `config.watch_history_e2e_settings`，继承隔离配置并禁止生产数据库及 R2；先迁移，再运行 `scripts/seed-watch-history-e2e.py` 创建新合成账号，启动 127.0.0.1:8000 的后端与前端。每次重跑浏览器脚本重新生成合成账号；不要在生产使用此设置。

发布顺序：备份 → 应用 **0034** 迁移 → 更新后端 → 发布前端。无新增依赖或环境变量。清空后导出的备份需由支持 `base_revision` 的新后端恢复，不宜回退到 A1／A2 旧导入校验。本轮未操作生产迁移或真实用户数据。
