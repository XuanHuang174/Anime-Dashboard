# 扩展 13B：参与关系资料存储、导入与覆盖审计

日期：2026-10-27。按[扩展 13 方案](recommendations-extension-13-plan.md)和[13A 合同](recommendations-13a.md)交付数据基础。新增迁移 `0016_credits_foundation`，本轮只在本机隔离 PostgreSQL 应用；没有迁移、读取或写入生产数据库，没有更改 Render 配置、私人手账、原推荐目录、系列或提醒。没有新增 HTTP 路由、前端页面或功能开关。

## 存储与发布

新增九个独立模型：CreditsState、CreditsSnapshot、CreditsSubject、CreditsPerson、CreditsCharacter、CreditsAlias、CreditsObservation、CreditsHead、CreditsAssertion。

- 所有公共名称、实体类型、角色和别名均绑定归档快照。人物、角色和作品 ID 是独立命名空间；没有用实体名称合并身份，也不复用私人 studio 文本。
- 每部作品分别建立 studio、voice_actor 两个来源观察与发布指针，保留 current 和 last_attempt。完整来源才能更新 current；partial／failed 只记录最新尝试，保留旧版可用关系。
- 旧观察引用旧快照的实体及别名。新版姓名、公司类型、失败解析不会覆盖旧观察所使用的资料；没有全局“最后导入者覆盖名称”的行为。
- 原始职务、CV／译配等类型、角色定位、来源顺序和备注独立保存。缺失端点保留原始 ID 与空 FK，不伪造公共实体。未知角色定位仍只是注记，不扩散出演到其他作品。
- 同一快照、同一来源观察幂等；同版本不同字节／事实／质量状态拒绝覆盖历史。同一来源不能回退到更旧归档；独立来源可用旧归档补录，因为它不会覆盖其他来源的当前实体版本。
- 全批事务包含快照、实体、别名、观察、断言和指针，失败全部回滚。共享状态行锁串行化发布并递增公共修订。分批中断允许已提交批次保留，用原计划幂等续跑。

`credits_store.publish_batch` 只接受同进程 `ArchivePlan` 的本地预检结果。fingerprint 是变更检测，不是可信签名；不得将请求 JSON 或外部上传的“预检计划”直接交给它。公开导入命令始终重新读取 ZIP、核对摘要、建立计划再发布。

## 归档预检

`credits_source.ArchivePlan` 在入口和完整扫描结束后两次验证 ZIP SHA256，要求六个唯一、未加密且受限的成员，逐行读取并计算成员摘要；不解压、不下载、不调用上游 API、不初始化 Django。

大目录使用单个随机命名的 SQLite 临时索引，缓存约 8 MiB，保存选定来源的原始关系、端点投影和角色绑定。结束或异常时关闭并删除本次创建的这一个临时文件，不删除目录或其他文件。

主要界限：最多 50,000 个来源、400,000 个引用人物／角色端点、2 GiB ZIP、2 GiB 临时索引、单行 2 MiB、每来源每种关系最多保留 5,000 条、预检 1–900 秒；发布每批 1–25 个来源，命令默认 10 个。超过单来源保留量会准确记录原始数量并置 partial，不把截断结果计为完整来源；归档整体超限／无法归属的源 ID 格式漂移直接停止预检。

公司完整性仅针对初版 position=67。其他职务仍保存，但不会因导演是个人就把公司来源判为 partial；只有动画制作关系的端点／实体类型问题阻断该公司的当前观察。声优完整性针对原声 CV：译配等已知非初版类型单独保留，不混入原声；原声的端点、角色绑定、实体类型问题以及未知出演类型会使该声优观察 partial。

`empty_observed` 表示初版范围内没有可用关系，可能存在其他职务或译配，不代表作品没有工作人员或配音。来源缺失、非法元数据和非动画来源为 failed；重复身份、重复／冲突断言、缺失端点、未知出演类型及限额问题不自动修复。

## 别名解析

`credits_aliases.py` 的 `bangumi.credits-names.v1` 是有界名称字段解析器，不是通用 wiki 渲染器。只接受明确的简体名和受支持的别名列表项；姓名原文、纯假名、罗马字等可以成为检索键。大小写、NFKC 与空白规范化不合并人物 ID。未知昵称项目、链接、HTML、嵌套 wiki 或损坏列表不会生成推断别名，保留主名称并标注 partial。

别名资料状态与参与关系状态分离：名字别名无法完整解析不抹掉已经确认的职务／出演。主名称本身非法则端点不能用。库中检索键允许不同人物重名；每个名字仍绑定自己的 person 快照，没有跨人名称迁移。

## 操作命令

默认只预检并写一份新的本机报告；只有提供匹配的 `--expected-plan` 和 `--apply` 才写入资料表。报告路径必须未存在。`--ids` 与 `--catalog` 互斥；后者读取目标库真实公共目录的 ID 和分级，不读私人记录。

下面是本机隔离环境示例，先启动项目已有隔离 PostgreSQL 并设置其 `RECOMMENDATION_TEST_DATABASE_URL`；不要将示例当作已完成的生产导入：

```powershell
.\.venv\Scripts\python.exe manage.py migrate --settings=config.recommendation_pg_test_settings
.\.venv\Scripts\python.exe manage.py sync_credits_archive --input data/recommendations/archive/dump-2026-10-20.210332Z.zip --expected-sha256 9fe8de272398ff4bd12994b73e25aac37cca631372383f6aadc503528623aa93 --ids 265,1424,3774,8019,9717,10639,328609,436738 --report .tools/13b/NEW-preview.json --settings=config.recommendation_pg_test_settings
```

审阅报告后，使用同一组输入参数，换一个新的报告路径，追加：

```text
--apply --expected-plan 前一份报告中的plan_fingerprint
```

`--catalog` 会将目标目录身份与分级绑定到计划。开始写入前复核整份目录，逐批仅复核本批来源，结束后再次全量比较，避免每批往返传输整份目录。目录发生变化会停止或要求重新预检／审计；已经保存的公共事实不会变成候选放行凭证。

命令的 SQL 写入守卫仅允许九个 Credits 表。跨批数据库异常会留下已提交批次及失败类型报告，再以同一来源重新预检并按匹配计划续跑；没有完整计划时的 ZIP 校验失败只报错，不伪造数据库失败观察。审计／导入不能替代作品审核和账号资格校验。

## 覆盖审计

```powershell
.\.venv\Scripts\python.exe manage.py audit_credits_coverage --output .tools/13b/NEW-coverage.json --settings=config.recommendation_pg_test_settings
```

使用强制只读一致性事务，普通／成人／未知目录分开，声优／公司独立统计：目录分母、当前与最近尝试状态、45 天内完整且身份／分级一致的来源数、实际有关联的作品数、原声端点／绑定问题与其初版行数分母、当前参与实体的别名状态。空分母比例为 null，未读取与成功空观察分开；非法或被隔离的元数据也会作为不可用端点统计，不把它写成“上游一定缺少条目”。

两类资料分别给出最多 100 个普通目录待复查来源 ID，供后续定向核验；不会据此自动修复或下载。

完整来源覆盖与实际关系覆盖不是同一指标：有一万部完整空观察，不等于有一万部声优资料可展示。unknown 分级的完整来源只是资料观察，仍不获得线上展示资格。成人计数也不代表已审核或任何账号获授权。

审计最多处理 50,000 部目录和 1,000,000 条当前初版合格断言；原始当前断言总量由 SQL 精确计数，不将所有非初版职务加载进内存。只加载必要的版本化字段，检查当前指针及合格断言的实体快照一致性。达到上限失败，不发布部分成功报告。报告状态为 foundation_audit_not_release_acceptance，不包含线上放行结论或可调低的验收门槛。

## 13C 交接

下一阶段从 current 观察出发连接它自己的快照实体，不能直接搜索全部历史别名并将结果视为当前参与资料。查询需先按现有目录／审核／账号内容范围过滤，再计算实体、角色及作品数量。人物一部作品多个角色必须先按作品去重，再做计数和稳定分页。partial 无旧版时准确显示资料待核验，不伪造成空或全覆盖。

正式数据导入、生产覆盖门槛、语种扩展、灰度和页面验收继续留给后续阶段。此次发现的来源类型冲突须保留核验依据，不能靠改模型类型或合并艺名提高覆盖率。
