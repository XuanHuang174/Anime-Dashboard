# 批次 B：标签与筛选

## 本次行为

- 私人档案预览在单列手机布局中按内容自然撑高；海报不会被压成横线，百科区块完整排在信息卡之前。桌面两列布局在矮屏中允许左侧资料独立滚动。
- Bangumi 自动填充及共用该资料解析的导入，只从已有标准题材词表和别名中提取标签。先扫描全部来源标签，再去掉年份、地区、公司、作品名和未知标签，避免热门杂项占满前八项。更换缓存命名空间，避免继续取到旧的混合标签。已有手账与用户自定义标签不批量改写。
- 自定义快捷筛选的包含、排除标签各有搜索框；已选标签不会因搜索消失，旧的已选自定义标签仍可移除。保存年份上下界，可只填一边，也可建立纯年份组合。
- 年份为包含两端的 AND 条件，不受标签“任意/全部”匹配方式影响。设置年份范围后排除未知或无效日期。私人、分享、公共全量列表与精选筛选共用相同规则。
- 个性化、找相似、按标签、按声优/制作四种推荐入口均可组合选择作品类型。清空选择回到“全部类型”；全部类型保留未知类型作品，指定类型只匹配所选类型。
- 新建番剧底部操作顺序为“创建并加入手账”在前、“取消”在后。

## 接口与迁移

`0026_featuredquickfilter_year_from_and_more` 为 `UserQuickFilter` 和
`FeaturedQuickFilter` 各增加可空的 `year_from`、`year_to`，并约束起点不大于终点。
接口允许 1000—9999 的四位整数或 `null`，PATCH 会与已有另一端一起校验。
旧筛选新增字段默认 `null`，没有历史数据清理或回填。

推荐查询仍使用 `type` 参数，兼容 `all` 和原先单值；多值采用逗号分隔，
例如 `TV,OVA` 在服务端归一为 `OVA,TV`。未知、重复、空项以及 `all,TV`
均返回校验错误。签名浏览上下文、后续分页和前端结果校验使用同一归一值。
类型过滤发生在候选截断和分页之前；现有身份、NSFW、归属和排序规则保留。

部署后端前须让部署流程执行 `python manage.py migrate --noinput`，再启动新版本；
之后部署前端。没有新增环境变量或依赖。本次本地验证没有操作线上数据库。

- 隔离 SQLite：25 项（标签解析、资料接口、标签管理、组合筛选和精选筛选）通过。
- 隔离 PostgreSQL：133 项（组合筛选、浏览、找相似、标签探索、人员作品、公开目录读取及分页）通过，包括合成大目录回归。
- 前端单元测试：455 项通过；生产构建通过，仅有现有的大分包体积提示。
- Django 配置检查通过；迁移漂移检查没有额外变更。
- 浏览器：36 项通过。覆盖 320—1440px 七档宽高，包括 639px 断点前与 840×420 矮屏；检查海报高度、资料不重叠、Bangumi 链接可点、包含/排除搜索、保存年份、四模式类型多选、自动填充和按钮顺序。该检查模拟不同 CSS 视口，并非真实手机浏览器缩放验收。

三项原有测试仍把缓存故障预期为 503；用修改前的 HEAD 代码已复现相同失败。
现有实现会在缓存不可用时读取数据库，因此更新为验证正确意图的 200 结果，
同时保留数据库故障必须返回 503 的断言。本次没有改变缓存降级策略。

```powershell
$env:PLAYWRIGHT_MODULE = '<Playwright 模块路径或已安装的 playwright>'
```
