# 人物与制作：电脑时间偏差修复

## 问题与边界

2026-11-02 用户反馈：手机能正常浏览多个声优、制作公司的作品，同一账号在电脑端收到 HTTP 200 后却显示“资料合同不兼容”。本地复现旧逻辑：服务器给出 900 秒有效期，但浏览器时间慢约 2.5 秒，即触发前端的未来有效期上限。电脑时间过快、加载后系统校时也会影响缓存、翻页和作品操作。

用户提供的公司 `17980` 响应另有作品 `485782` 缺少 `content_rating`，同样足以触发整批拒收。当前后端在序列化后逐条显式写入该字段；本次保留这一行为，增加回归与具体错误信息。尚未确认线上缺字段的产生环节，不能把所有实体失败都归因于它，也不能将缺失分级自动视作普通作品。

## 修改

- 作品列表响应新增整数秒 `server_time`，向上取整；有效期仍绑定原有服务器签名与最长 900 秒上限。
- 浏览器使用 `expires_at - server_time` 计算剩余时长，并以 `performance.now()` 记录经过时间。将整个请求耗时计入消耗；续页只能缩短，不能刷新签名批次的有效期。
- 首次校验、缓存返回、翻页、作品详情、加入想看、页面失效定时器和窗口重新获得焦点均使用同一剩余时长。
- 老后端尚未返回新字段时保留旧合同校验，但明确提示系统时间不一致；新字段存在但无效时直接拒收，不退回宽松路径。
- 分级缺失时提示对应作品编号，不输出签名上下文或令牌；旧结果标为待重新读取，禁止继续操作。

## 部署与验收

需要前端和 Django 后端均更新；不需要新迁移、环境变量或重新导入 Credits 归档。旧前端仍可读取新增字段，但只有新前端具备时间偏差修复。部署完成后刷新页面以加载新资源。

电脑验收：搜索制作公司 `person:17980` 和任意已收录声优，检查首批、加载更多、打开详情及跨模块返回；对比手机。若仍出现分级缺失提示，记录提示中的作品编号、HTTP 状态及是否含 `server_time` 即可；不要提供登录令牌或签名字段。

回归覆盖正负一天的电脑时钟偏差、读取后系统校时、续页不延长有效期、真正到期／超长请求、缓存返回、详情及确认加入、缺失／未知分级拒收，以及实际 PostgreSQL HTTP 响应通过前端验证。
