# 观看计划 B3：页面整合、私人筛选与批量安排

在 [B1](watch-plans-b1.md) 与 [B2](watch-plans-b2.md) 基础上完成计划入口、管理界面和既有功能联动。计划仍是私人观看意愿，与实际观看状态、评分和历程分别保存。

## 页面与入口

- “手账 / 观看计划”融入个人页头身份标牌行，共用紧凑外框、黄色选中态和较轻阴影。移除页头外独立导航行，恢复手账统计与筛选区原有衔接。手机标牌隐藏英文前缀，避免被菜单覆盖；导航在页头内部换行。
- 编辑详情首页移除内嵌的观看安排。底栏从左到右为删除私人记录、观看历程、**观看安排**；观看安排为白底、沿用黑色阴影与底栏入场动画。点击进入独立管理视图，保留原编辑页签、位置及返回焦点。
- 独立视图仅展示作品名称、安排与独立保存提示。返回作品编辑、关闭、取消及进入历程均经过草稿/保存中保护；有作品草稿时须先保存再进入安排。
- 计划页使用白色紧凑标题、青绿侧边条和短说明，不再重复大面积横幅。阶段、筛选、匹配数、刷新及编辑工具统一放入筛选面板；规则按需展开。两个工作区继续分别保留筛选、分页与滚动。
- 作品选择改为原生模态抽屉，桌面靠右、手机接近全屏，具有独立滚动、搜索及分页。已有活跃安排显示“调整安排”；看过作品提示可安排重看。选择作品后关闭抽屉并进入该私人作品的安排视图。
- 列表突出海报、作品名、短备注、计划开始时间和观看进度；只有待开始计划才显示过去时间的温和调整提示。优先级分组计数覆盖当前条件的全部匹配，不以当前页条数冒充总量。手机控件可换行，动画遵循减少动态效果。

## 私人计划快速筛选

新增 `UserQuickFilter.plan_state` 与可空的 `plan_priority`，由迁移 **0036_quick_filter_private_plans** 提供。旧组合默认为 `any / null`，维持原有语义；不创建或回填观看计划。

阶段支持 `any / none / active / pending / ongoing / completed / archived`，优先级为 1–3 或不限。`active` 是待开始与进行中的并集；`none` 指没有安排记录，已移出单独匹配。无安排与优先级不能同时设置。计划条件与评分、观看状态、长评、年份和标签条件同时满足，在分页前由服务端筛选；编辑器的摘要和全量预览使用相同规则。

私人作品接口仅向本人返回 `watch_plan_summary: null | {state, priority}`，主手账本地全量过滤与服务端分页结果一致。只改安排也刷新手账筛选依据，避免回到手账后仍显示旧优先级。

隐私边界：公开/共创手账和展示用筛选列表不返回含计划条件的组合，也不返回计划摘要；即使本人查看自己的公开链接也保持公开契约。公共查询不能用猜测的组合编号推导私人计划。精选专栏编辑器不提供计划字段。

## 推荐加入入口

个性化推荐、单番相似、按标签找的作品卡片与详情操作共用“观看安排”入口，沿用当前推荐客户端及内容访问范围。

点击先说明两个独立步骤。用户明确确认后，调用既有幂等加入想看接口：已有记录保留全部私人数据，新作品创建空评分、空长评的想看记录；随后进入 `/dashboard?arrange=<record_id>` 对应的本人编辑安排视图。用户另行保存优先级、日期与备注后，才加入计划。取消安排保留已经加入的手账作品，绝不自动开始或重看。

深链接只读取认证本人可访问的作品，不直接写入安排；消费参数后移除 URL 参数。身份冲突、访问范围失效和加入失败沿用原推荐接口规则，不用名称猜测或绕过核对；请求结果不明时重试既有幂等加入接口。内容范围变化或离开页面会中止过时请求。

## 批量调整

编辑模式在当前、待开始或进行中列表提供“批量调整”。只对**当前页明确勾选**的活跃计划操作，单次最多 100 部；其他分页不自动选中。用户可统一优先级、统一日期精度或移出计划。日期默认保持各自值，勾选统一时间后才能清空或更改；备注不批量覆盖。核对步骤展示所有选中作品和具体变更。

新增 `POST /api/watch-plans/batch/`，认证本人、禁止查询参数，响应 `private, no-store`。请求示例：

```json
{"action":"update","version":7,"operation_id":"fb58ee95-9ab1-450a-9cbc-19e1141f8b7b","record_ids":[12,18],"priority":1,"planned_for":"2031-02"}
```

`action=remove` 不得携带调整字段；`update` 至少一项 `priority / planned_for`。拒绝重复、外部账号、已删除或非活跃作品，整批校验与写入同事务。跨档移动追加到目标档末尾，保留被移动作品原来的相对顺序；原本已在目标档的作品不移动。

按作品主键顺序锁定，再锁账号队列；版本冲突返回 409，失败整批回滚。`operation_id` 复用既有收据机制，同一 UUID 同一请求重试返回最新规范状态，不重新应用旧变更；换请求拒绝。回执契约 `journal.watch-plan-batch.v1` 包含队列版本、明确选择的 `record_ids`、每部当前摘要与计划及 `replayed`。

前端保留结果不明的原请求和 UUID，通过“重试原操作并核对结果”确认，期间禁止另一条批量写入。确认写入与展示刷新分别处理；冲突保留选择供核对，取消、刷新、重新选择后才可发起新操作。不提供批量开始、批量重看或删除作品。

## 恢复影响

JSON 恢复预览展示既有后端的 `plans_in_file / replaced_plans / preserved_plans / cleared_plans / removed_plans`：文件内安排、其中覆盖已有安排、旧格式匹配保留、明确清除及随作品移除。新增作品的安排计入文件内总数，不误算成覆盖。签名、确认时限和版本冲突保护维持 B1/A3 规则；预览不会应用恢复。
