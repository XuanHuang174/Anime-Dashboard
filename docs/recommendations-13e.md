# 扩展 13E：人物与制作的本人状态与手账闭环

日期：2026-10-28。承接 [13D](recommendations-13d.md)，补齐本人观看状态、“我看过的”、目录详情、资源检索和幂等加入想看。三个推荐主导航不变，人物与制作仍为次级工具。没有新增迁移，没有修改线上开关或生产数据；正式覆盖和灰度验收留在 13F。

## 展示与交互

- 作品卡显示本人“已在想看／在看中／已看过／已搁置”，无匹配时写“无已确认记录”，不推断没看过。不读取其他账号的记录。
- “浏览范围”提供“关联作品”和“我看过的（已看完）”，与其他条件一起点击“应用筛选”。后者只包含 completed，强制 hide_recorded=false，隐藏已有记录的复选框禁用。在看、想看和搁置不计入。切回关联作品恢复默认隐藏已有记录，可再手动取消。
- 卡片提供“查看详情”和“加入想看”。详情显示目录资料、简介、公共标签和当前本人状态，复用原生详情窗口及资源抽屉。资源检索提示核对标题和季度，不把搜索结果当作身份确认。
- 已有状态不能被加入操作覆盖。确认加入后卡片和详情同步状态，保留窗口与资源入口，提示重新读取更新筛选结果、数量及分页，无需自动整页刷新。
- 卡片和详情共用一个正在执行的 POST。没有确认响应时不显示假成功、不自动重试；用户可明确重试，服务端不创建重复记录。服务端确认后，即使通知其他页面失败，已保存操作也不会变成失败。

## 接口与一致性

13C 分页签名包含本人记录修订，加入作品后分页签名必然失效，不能直接拿它重试写入。13E 为每个已返回作品增加独立的 `action_context`，与分页签名、推荐 evidence token 分开。新增薄适配入口，创建仍调用原 `add_want` 服务：

| 方法 | 路径（位于 `/api/recommendations/credits/` 下） | 合同 |
| --- | --- | --- |
| GET | `entities/{kind}/{person_id}/items/{bangumi_id}/?context=...` | `recommendations.credits.detail.v1` |
| POST | `entities/{kind}/{person_id}/items/{bangumi_id}/want/?context=...`，空 JSON | 原 `recommendations.want.v1` |

详情只返回目录资料和本人 watch_status，不输出记录 ID、私人评分、评价或私人标签。写入返回原服务的身份、状态、created/outcome 及内容范围，不建立第二套手账创建逻辑。

操作签名绑定账号、登录会话、密码会话哈希、具体作品、人物类型和 ID、内容范围、目录修订、参与关系修订、放行修订及期限（最多 900 秒且不超过内容范围有效期）。它不绑定本人记录修订，使已提交但回包丢失的请求可重试。每次仍重新检查有效来源、可展示目录、本人身份冲突和隐藏反馈；来源／目录／权限变更后旧签名不可用，不能替换作品、人物、kind、账号或会话，不能用分页签名冒充操作签名。

GET 使用原有 PostgreSQL 独立只读快照、响应大小限制、最终范围／来源／目录／本人状态复核及 private,no-store。POST 按 owner → CreditsState → 内容范围／审核 → 目标目录行顺序加锁，序列化来源发布和本人写入，再走原无损创建、容量、身份、标签及公开库策略。已有记录不会被重设为想看，不覆写评分、长评或观看集数。成人资料继续遵守原审核与封面隔离。

容量不足、旧身份待核对、字段不兼容等业务冲突不撤回本次 NSFW 选择；真实范围失效继续走原保护。成功提交后的确认不在响应结束时被标成只读快照冲突。

## 生命周期

操作限定当前账号、实体、内容范围和有效列表。更换筛选或加载分页会关闭旧详情；正在写入时阻止替换列表。离页、账号变化、范围撤回、过期及手账通知取消旧交互，迟到响应不能回填当前页面。

本窗口和跨窗口手账更新将当前及缓存结果标为待重读，关闭旧详情并阻止续页／新操作。自身确认的写入通知使其他页面失效，同时保留本页确认状态。前后台切换不重新读取关系列表。
