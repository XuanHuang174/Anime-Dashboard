# 私人手账评分样式与统计个性化

## 入口与使用

- 编辑模式 → 数据管理 → **评分样式与统计**。
- 预览模式 → 更多功能 → **评分样式与统计**。
- 手机端先打开菜单。公开分享页没有配置编辑入口，只提供作者评分口径说明。

设置面板沿用手账的青绿标题、奶油白内容和黄色底栏。桌面左侧编辑、右侧实时预览；手机上方预览默认折叠，主体统一滚动，保存与关闭保持可见。支持系统减少动态效果、原生 dialog 键盘约束、关闭焦点返回。未保存关闭会询问是否丢弃草稿。

预设“项目默认”“Bangumi 整数习惯”“仅数字”只载入草稿；**保存并应用后才生效**。预设不转换或批量改写已有评分。“项目默认”也用于恢复默认外观，仍需保存。

### 档位与星级

- 星级上限 1–10，可隐藏星级保留数字。
- 评分档位 1–10 档，支持添加、移除、按起点排序。每档配置名称、起点、点亮星数、数字配色、星级配色及纯色/渐变/柔和高亮。
- 起点为 0–10、最多一位小数，从高到低且不重复。最低档固定从 0 开始；上限由上一档起点联动，修改上一档起点即可调整相邻区间上限。下限包含，上限不包含；最高档包含 10。无重叠和未覆盖区间。
- 点亮星数可以为 0，不超过星级上限。调小上限会在草稿中收拢超出的星数。
- 配色使用 8 个受支持色系；不接收任意 CSS 或 HTML。档位和统计名称最多 16 字。
- 默认保留原来的星级阈值：9 分起 5 星、8 分起 4 星、7 分起 3 星、6 分起 2 星、正低分 1 星、真实 0 分 0 星；9.9/9.5/9 的颜色档位独立保留。展示规则由同一组件用于列表（含手机）、海报墙、详情和精选卡片；结案报告使用对应评分配色。

原始评分仍为 **0–10 分**，不会按星数换算、影响排序、观看状态、评价或推荐算法。未评分始终与真实 0 分区分。

### 统计显示

- 自定义推荐统计的名称及上下限（0–10，最多一位小数，两端包含）。例如“我的珍藏，8–9 分”。
- 选择追番数量、平均评分、剧场版、OVA、泡面番、自定义推荐统计中的任意卡片，至少保留一项。数量变化后卡片布局自适应。
- 推荐数量依据**全手账**，与当前搜索、筛选和分页无关。未评分不计入，真实 0 分按范围判断。平均分仍按所有已评分作品计算。
- 私有设置接口返回评分直方图（至多 101 个分数桶和一个未评分桶），无需下载作品标题或长评。实时预览以打开面板时的分布计算，保存后重新统计。

## 保存、公开展示与投稿

配置存于账号 `UserProfile.rating_preferences`，`rating_revision` 做乐观版本控制。相同读取版本的两次并发保存只有一次成功，另一请求返回 409 并保留草稿；用户可明确选择重新读取并替换草稿。写入不自动重放，失败和 429 有提示；重复点击保存只发一个请求。

列表、海报墙、详情和统计从所属手账的配置读取；晚到的旧统计响应不能覆盖已保存的新版本。账号切换会关闭设置并丢弃旧响应。昵称/头像修改和后台其他字段编辑只保存其变更字段，避免写回旧配置。

- **本人公开手账、共创大厅、站长公共展示**使用作者当前配置，不使用访问者的偏好。公开页面显示配置口径和对应统计；私有直方图不对外发布。
- **精选投稿**由服务器在提交时复制作者配置，客户端不能覆盖快照。精选卡片、作品详情及审核预览读取该快照。作者之后调整设置不会改变已有投稿，保持与投稿评分、长评等快照一致。
- 历史投稿在迁移时使用项目默认配置。新设置不自动重发旧投稿或改变审核状态。
- 共创大厅的展示数量和标签个性化；大厅原有排序依据及推荐算法不因展示配置变化而重新定义。
- Django 后台可只读查看用户配置、版本及投稿配置，修改请使用本人手账的设置入口。

## JSON 备份

完整导出仍使用 `anime-journal` version 2，增加可选顶层 `rating_preferences`，不导出账号保存版本。

导入含此字段的新备份时，记录替换与配置恢复处于同一事务；任何失败都回滚，配置版本也回滚。导入旧备份（没有该字段）保留当前配置。导入确认文案明确提示会覆盖记录及文件内配置。共享导出也携带作者配置。

## 接口

| 接口 | 行为 |
| --- | --- |
| GET `/api/rating-preferences/` | 本人配置、revision、私有 histogram；需登录，`private, no-store` |
| PATCH `/api/rating-preferences/` | `{preferences, revision}`；只允许当前账号，严格校验字段和范围 |
| GET 手账 `stats/` | 追加 `rating_preferences`、`rating_revision`，masterpiece_count 按作者配置计算 |
| 公开用户卡片/资料 | 仅包含可公开的展示配置，无私有评分直方图 |
| 精选投稿表示 | 只读 `rating_preferences` 快照；提交时由服务器决定 |

配置 version 1：

```json
{
  "version": 1,
  "star_max": 5,
  "show_stars": true,
  "tiers": [
    {"min": 8, "label": "推荐", "stars": 5, "color": "teal", "star_color": "amber", "effect": "plain"},
    {"min": 0, "label": "其他评分", "stars": 0, "color": "slate", "star_color": "slate", "effect": "plain"}
  ],
  "statistics": {"label": "推荐", "min": 8, "max": 10, "cards": ["average", "highlight"]}
}
```

## 部署

新增迁移 **`anime/0028_rating_display_preferences`**，为用户资料新增配置与版本，为投稿新增配置快照。没有新增环境变量或依赖。

1. 在正常生产备份及部署流程中，先执行 `python manage.py migrate --noinput`，确认 0028 已应用。
2. 启动新版后端，再发布 Cloudflare 前端。
3. 用本人账号验证预设 → 实时预览 → 保存 → 刷新；匿名查看公开手账，再查看新投稿。测试时不需要批量修改分数。

本次开发只在本机隔离数据库及合成浏览器中操作，没有执行生产迁移或生产用户配置写入。
