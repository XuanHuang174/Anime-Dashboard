# NSFW 筛选轻量开关：独立交付与接入边界

## 本轮实现

- 筛选区改为“包含 NSFW 作品”开关、一行状态说明和刷新/重试按钮。
- 前台不再显示申请、勾选申请确认、等待审批或授权有效期表单；模块 3 与历史审计保留。
- 打开/关闭筛选面板、刷新可用状态都只读取既有自己的 eligibility 接口，不产生申请或授权写入。
- 开关仅修改本地草稿；点击“应用筛选”后才更新当前浏览，直接关闭不会应用。不写长期偏好或 localStorage。
- 可用状态未读取完成、读取失败、服务关闭或访问不可用时，开关禁用且不显示勾选。即使初始草稿残留 true，提交也降为普通范围。
- 请求合并、AbortController 和请求代次共同阻止旧会话的迟到成功/失败覆盖新状态。

## 后端展示合同

自己的 eligibility 响应新增 `scope_control`，不增加数据库查询或迁移：

```json
{
  "contract_version": "recommendations.scope-control.v1",
  "selection_mode": "session_draft",
  "default_scope": "safe",
  "available": false,
  "reason": "service_closed",
  "revision": "与既有 eligibility_revision 相同的指纹"
}
```

reason 为 `available` / `service_closed` / `access_unavailable`。
available 只是既有服务端授权结果的展示，不是客户端签发凭据，也不表示任意 NSFW 作品可进入候选池。
旧后端没有这个附加字段时，新前端仍从原合同读取可用性；字段存在但不合法时拒绝使用。

## 明确未完成 / 未改变

本轮是前台简化和只读合同适配，不是取消后端门槛的完整上线：

- **原账号授权与作品审核过滤暂时保留**。未授权账号当前仍不能开启；不伪造授权，也不自动批准。
- 不把“有有效题材”当成内容安全证明，不直接用全部 nsfw=True 目录替换当前候选范围。
- 不实施或代为确认用户负责的禁止内容判定，不审批指定作品，不开生产总闸。
- 不改变 content.v1 排序、候选上限、既有安全范围、反馈排除、手账隐藏、证据和游标校验。
- 不修改用户评分、标签、长评、申请、历史授权和审核记录。

用户完成可靠的禁止内容排除后，再单独对接实际候选策略。该对接必须继续覆盖列表、详情、水合复核、证据与旧快照，且服务端校验始终是权威；不能只把本展示合同的 available 改成 true。

2026-10-22，本机独立 PostgreSQL 合成数据：

- `test_scope_control`、`test_content_scope_n2`、`test_controlled_serving_m2`、`test_controlled_release_m3`、`test_self_approval`：64 项通过。

- Vite 生产构建通过；仍有既有主包超过 500 kB 的提示。
- Django 测试运行系统检查通过，无迁移。
- 没有进行线上读写、真实账号数据测试或浏览器人工交互验收；SSR/控制器测试不等于多端浏览器验收。

## 部署与回退

1. 可前后端滚动部署；旧合同字段保留，新字段附加。无需迁移或修改环境开关。
2. 部署后核对开关默认关闭、状态读取失败可重试、关闭面板不生效、应用筛选后才更新结果、底部按钮可见。
3. 新前端移除了申请入口，但当前后端仍使用原授权规则；不得据此宣称自助访问与新候选池已全部接通。
4. 回退对应代码版本即可恢复旧申请面板；本轮没有数据写入，不清除任何用户数据或审核审计，不切换 V2。
