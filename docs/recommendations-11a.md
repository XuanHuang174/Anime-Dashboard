# 扩展 11A：探索基础与合同

日期：2026-10-23。状态：基础实现及隔离回归通过；生产探索开关保持默认关闭。没有新增业务表、迁移、真实作品导入或线上数据操作。

## 已确认的导航

一级入口固定为：**个性化推荐｜单番相似｜按标签找**。当前入口追加“· 当前”，例如“个性化推荐 · 当前”。桌面端放在红色标题区右侧；窄屏独占一行。现有个人推荐类别、风格与筛选保留为二级控件。整体布局和其余模块按[开发方案](recommendations-extension-11-plan.md)推进。

11A 已集中定义导航标识、名称、路径及当前入口文案，但未把尚未完成的两个入口挂到生产页面。完整导航、搜索组件和模式切换在 11C 接入；标签查询界面在 11E 接入。

## 交付范围

- 独立探索能力开关、查询/目录/证据合同与严格校验，不调用用户画像排序。
- 本地目录名称、Bangumi ID 与严格格式 subject 链接搜索；返回可作参照的标准题材、稳定身份和特征指纹。
- 前端专用目录适配器、能力/合同校验、只读客户端及可取消的搜索控制器。
- 共用组件边界明确：目录选择结果不会传入个人推荐分页器；不伪造个人评分、长期偏好或推荐理由。
- 统一当前内容范围、永久审核与中途安全状态变化的处理，沿用认证、限流和 private/no-store。

本阶段没有实现相似排序、标签结果执行、结果签名快照或完整推荐详情。它们分别属于 11B/11D；证据结构校验不是权限校验或签名签发器。

## 能力开关

`RECOMMENDATION_EXPLORATION_ENABLED=False` 为默认配置。只有布尔值 True 才启用目录选择与合同接口，不能用字符串或数字绕过内部判断。

既有 `GET /api/recommendations/capabilities/` 保留原字段，新增 `exploration` 对象：

- `contract_version = recommendations.explore.capabilities.v1`
- `enabled` / `catalog_search_enabled`：当前开关状态。
- `query_execution_enabled = false`：11A 不提供实际相似/标签结果。
- `navigation`：三个入口及可用状态；目前只有个人推荐页面可用。
- 各独立合同版本，供新客户端识别；旧客户端可忽略新增对象。

关闭开关后两个新接口返回 JSON 503，`code=exploration_disabled`，不替换为个人推荐或热门列表。原推荐入口和 V1/V2 发布决策不变。

## 目录选择 API

```http
GET /api/recommendations/explore/catalog/?q=作品名称
GET /api/recommendations/explore/catalog/?q=123
GET /api/recommendations/explore/catalog/?q=https%3A%2F%2Fbgm.tv%2Fsubject%2F123
```

均要求登录。默认安全范围；主动包含已审核成人目录时沿用 `content_scope=include_adult` 和现有范围校验，不创建账号申请。

| 规则 | 行为 |
| --- | --- |
| 名称 | 支持中/日文已有名称；NFKC 与首尾空白规范化；至少两个字符 |
| ID | 只表示 Bangumi ID；正整数，不超过 2,147,483,647 |
| 链接 | 仅完整的 http/https、bgm.tv / bangumi.tv / chii.in、`/subject/<ID>` 路径；无额外参数、片段、端口或认证部分 |
| 输入上限 | 原始和规范化内容均不超过 120 个字符；拒绝控制字符 |
| 搜索范围 | 本地当前范围的推荐目录；不读取私人手账，也不发起外部抓取 |
| 顺序 | 名称完全匹配 → 前缀匹配 → 包含匹配；同组公共评分降序、Bangumi ID 升序 |
| 数量 | 固定最多 15 项，另取一项判断 `has_more`；不接收客户端自定义 limit 或分页 |
| 有界目录 | 当前范围超过 50,000 条时明确 503，不搜索截断子集后声称全库无结果 |
| 无结果 | 200 + 空 results，不泄漏范围外作品是否存在 |
| 无题材 | 返回目录资料，但 `can_seed=false`、`unavailable_reason=no_valid_topics` |

响应版本 `recommendations.explore.catalog.v1`，`identity_namespace=bangumi`。结果包含中日文名称、年份/季度、类型、公共评分、标准题材、内容分级、受控封面、`can_seed` 与 `feature_revision`。不包含私人观看状态、个人评分、长评、原图地址、详情证据或伪造的推荐原因。

成人作品继续返回中性封面；未知分级不返回。已在手账中的作品仍可作为参照，因为这里没有执行“隐藏已有记录”的结果过滤。

## 查询和证据合同

`GET /api/recommendations/explore/contract/` 返回规范词表、版本、约束和来源字段描述。同样受开关、登录、限流及内容范围约束。

初始查询规范为 `recommendations.explore.query.v1`：

- `intent=similar`：必须提供一个 `seed_bangumi_id`；不接受标签、匹配规则或标签排序参数。
- `intent=tags`：包含 1–5 个规范题材，可排除 0–5 个；默认 `match=all`、`sort=relevance`，支持 any 与 score。
- 题材仅使用现行词表与批准别名；去重并按标准顺序输出；包含/排除冲突拒绝。
- 共用类型、公共评分区间、四位年份区间、隐藏已有记录及固定每页 12 项的条件语义。低于 6 分等严格评分上限可沿用现有筛选规则。
- 用户标识、个人评分、旧分页游标、私人偏好字段、混合意图、未知/重复/空参数均拒绝。

规范化公共条件还提供稳定查询指纹：别名、题材顺序及等价默认值不改变指纹；它不是用户授权令牌。

本阶段没有注册执行该查询的结果接口；11B/11D 使用这个已测试的规范实现各自结果服务。

探索证据规范为 `recommendations.explore.evidence.v1`：

| 意图 | kind | 来源 |
| --- | --- | --- |
| similar | selected_work | 已验证参照作品的 Bangumi ID、名称与标准题材 |
| tags | selected_tags | 本次规范化条件，source 必须为 null |

证据包含真实共同题材、版本上下文和明确的非概率解释。校验器要求调用方提供当前查询、候选 ID/题材、参照来源及预期版本；拒绝来源错位、自身推荐、伪造个人评分字段、错误标签交集、违反 ALL/排除条件和版本不一致。

版本上下文包含查询指纹、目录特征版本、范围版本、词表版本及排序策略。11B 必须在真实范围校验和签名快照基础上签发、验证证据；本阶段的结构校验不代替这些操作。

| 部分 | 11A 处理 | 后续接入 |

查询不写 localStorage，不保存偏好或私人画像。搜索控制器只接受当前请求的响应；旧请求即使不理会 AbortSignal 仍不能覆盖新结果。模式/账号切换时，界面层应销毁旧控制器及详情/资源会话。

- Django check 与迁移差异检查通过；React 构建通过，仍有既有主包超过 500kB 的体积提醒。
- 所有数据库用例使用本机 `test_recommendation_isolated_tests` PostgreSQL；测试设置禁止生产数据库地址。未对真实账号、推荐目录或审核记录执行写入。
- 初次跨端回归因沙箱 Node 路径权限失败；在正常本机权限下复跑通过。日志中部署防护命令的拒绝信息来自预期负例，不代表执行了线上验收。

本阶段不涉及新页面布局，未将浏览器视觉验收标记为通过。相关机器日志位于 Git 忽略的 `.tools/11a-*.log`。
