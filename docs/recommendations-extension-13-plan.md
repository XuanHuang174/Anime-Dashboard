# 扩展 13：声优与制作公司探索

日期：2026-10-28。方向由用户确认；13A 合同、13B 存储／导入／覆盖审计、13C 登录态只读后端、13D 前端检索与参与作品浏览已实现，当前完成离线和本机隔离验证，尚未线上放行。问卷取消，不新增第四种推荐模式，不改变现有推荐排序或隐式写入长期偏好。阶段记录见 [13A](recommendations-13a.md)、[13B](recommendations-13b.md)、[13C](recommendations-13c.md)、[13D](recommendations-13d.md)。

## 产品入口与展示

- 保留个性化推荐／单番相似／按标签找三个主导航。在探索顶部工具区增加次要入口“人物与制作”，进入 `/recommendations/credits`，提供“找声优／找制作公司”检索。
- 私人手账只在预览详情增加可折叠的“声优与角色”和标准制作公司链接；编辑窗口继续只负责编辑。私人填写的公司名保留，只在独立公共来源确认实体后提供标准关联。
- 三种探索的作品详情使用同一摘要。初次展开读取完整演员清单，不对每张推荐卡片单独请求。缩略摘要和长列表分别限额并准确标记截断，不能把“展示前几条”计为完整来源。
- 进入 `/recommendations/credits/{kind}/{person_id}`，其中 kind 为 `voice_actor` 或 `studio`。标题使用现有 Memphis 白字黑底；下方展示当前范围的关联作品／我看过的、类型／年份／评分／隐藏已有记录／既有 NSFW 范围、排序和分页。首版不做头像墙、百科履历、关注推送或多实体交叉组合。
- 声优卡片写“饰演：角色名”，公司卡片写“参与职务：动画制作”，不称相似度或匹配概率。列表复用详情、已有记录状态、资源及幂等加入想看闭环。
- 使用现有系列路由的原页保留模式，返回时保留滚动、筛选与参照。模块分段入场并遵守减少动态效果；展开/收起不重算整个列表，避开刚完成的提醒刷新问题。

## 数据与身份

公共实体、源角色、作品职务、具体出演关系和来源观察独立于 RecommendationAnime／私人手账。以命名空间区分 subject ID、person ID 和 character ID；同一数字可以出现在三个命名空间。公司仍使用 Bangumi person ID，不用公司名建立关联。

公司初版仅接受实体 type=2 且动画职务 position=67（动画制作）。42（製作）、63（制作）和所有其他职务原样保存、单独统计，不放进动画制作清单。联合制作保留多家公司；章节备注只是来源文本，不推断全季参与或解析成未经核验的章节集合。组合 type=3 暂不当作公司。

出演初版限定 person-characters.type=0（CV，原声），并要求具体 subject-character 绑定及个人实体 type=1。不是“所有声优均为日配”：原声的实际语言不能由 CV 值推断。译配、中文／日文／英文／韩文配音、真人演员及未知类型保持区分。职业 seiyu 不能自动纠正错误实体类型。相同角色跨版本的声优不得通过 character ID 全局联接扩散。

角色定位只负责展示顺序。未映射的角色定位值保留原值并列入注记，不猜主配角，也不因此抹掉已由具体绑定确认的出演。已映射 1／2／3 按定位和来源 order 排序，未知定位放在已知定位之后。缺少具体作品绑定则不能展示为确定出演。

别名来自绑定到同一实体的来源字段；NFKC、大小写和空白规范化只用于检索。同名结果保留多个 ID，由用户选择；不自动翻译、拼罗马字、合并艺名身份或按人员迁移推断公司关系。13A 的四条简体名是人工核对的来源样本；13B 需要独立验证 wiki 名称字段解析器，不能用本机抽样脚本当正式别名导入器。

## 在线合同基线（13C 实现）

冻结合同见 `recommendations/tests/fixtures/credits_http_contract.v1.json`；**13C 已实现以下 HTTP 路由，两个资料开关默认关闭**。摘要另支持 expanded=true 按需展开完整有界清单，具体字段、限额和错误处理见 [13C](recommendations-13c.md)。

| GET 路径（均在 /api/recommendations/credits/ 下） | 作用 |
| --- | --- |
| search/?kind=voice_actor\|studio&q=... | 本地标准实体搜索，最多 15 项；仅搜索当前范围有可展示作品的实体 |
| subjects/{bangumi_id}/ | 已具备目录资格作品的声优／公司摘要及来源状态 |
| record/{record_id}/ | 本人手账身份解析；未确认身份返回明确状态，不猜 ID |
| entities/{kind}/{person_id}/ | 名称、当前范围作品数和资料覆盖提示 |
| entities/{kind}/{person_id}/works/ | 当前条件下的稳定作品列表，每页 12 部 |

搜索支持名字、已收录别名、完整 Bangumi `/person/ID` 链接或 `person:ID`。裸数字不当作作品／人物 ID 猜测；未知网址不跟随请求。kind 固定查询意图，不能把公司作为声优返回。

列表默认 `view=all`、`sort=score_desc`、`hide_recorded=true`；另支持 `release_desc/release_asc`，平分以 bangumi_id 固定排序，日期未知放最后，不把季度第一天伪造成发行日。“我看过的”仅查本人已确认且 completed 的记录，此视图明确使用 hide_recorded=false，冲突参数拒绝；不改全局筛选或原手账。

类型、年份、评分沿用原浏览语义，包括“6.0 以下（不含未知评分）”。身份冲突、隐藏作品、作品审核、未知分级和内容范围继续遵守既有资格服务；原始归档标记不代替线上审核。搜索结果、角色、计数和本人统计先做范围过滤再输出，不用全库总量泄露不可见关联。实体没有可见关联时不暴露其跨范围作品证据。

分页上下文绑定账号会话、内容范围、公共参与关系及目录修订、本人记录与隐藏反馈修订、实体／kind、条件和排序版本，有效期最多 900 秒。筛选、身份或权限改变后旧分页失效；不能把个人结果放入共享缓存。公共事实可以独立缓存，登录响应使用 no-store。重算保留已有展示；明确失去范围资格则清除。前台切换只检查必要修订，不逐次重跑人物关系。

13A/13C 的资料浏览只新增 GET。13E 为当前参与作品增加独立签名的详情／加入想看薄适配入口，详情复用目录序列化和本人身份保护，写入调用原有无损幂等 `add_want` 服务；不能把分页上下文当推荐依据，也不能因写入改变本人记录修订而破坏重试。具体合同见 [13E](recommendations-13e.md)。错误码区分 `credits_disabled`、`credits_snapshot_changed`、`credits_data_unavailable` 与既有授权失效，不能因本模块关闭重置 NSFW。参数拒绝未知／重复／错类型值。分页、精确计数和上限必须对同一快照计算，超限返回不可用或准确 partial，不返回“完整成功”。

## 覆盖、性能与开放门槛

公司和声优分别记录 not_loaded／observed／empty_observed／partial／failed／stale。来源成功、零关系、未导入、解析失败和超限不能混为一谈；partial 不能覆盖上次完整发布指针。空来源仅表示本次未取得关系，不证明作品没有声优或公司。

13B 全量预检分别统计普通／成人／未知目录的来源完整观察覆盖，以及有可展示公司／出演关系的作品覆盖。前者分母为对应范围真实目录，后者单列实际关系数量；声优还统计人物端点、角色端点和具体作品绑定缺失率。不能从这次八部策划样本计算全库百分比。正式覆盖门槛在导入预检得到真实分布后，发布前冻结并说明，不能临时降低门槛使审计通过。

访问时只读本地索引，不对每部作品或每位声优即时请求上游。别名、person_id、subject_id、角色绑定及职务使用索引；一个作品多个角色先按作品去重再计数分页。13B/13C 用真实关系体量确定全局及单实体处理上限，验证大公司、大演员表、多人同角、同人多角、并发版本变化和 Render 查询/内存/耗时。

| 阶段 | 交付与验收 |
| --- | --- |
| 13A | 官方常量与样本、纯离线规范化与审计、冻结的产品/API 计划；不启用服务 |
| 13B | 独立存储、增量迁移、可复核预检/导入、来源发布版本、别名解析及覆盖审计 |
| 13C | 登录态搜索、摘要、范围过滤、作品列表与稳定分页后端 |
| 13D | 详情入口、检索/结果页面、多端动画及原页面返回 |
| 13E | 已完成：本人状态、只看已看完、来源限定详情、资源与无损幂等加入想看；见 [13E](recommendations-13e.md) |
| 13F | 正式数据、覆盖与性能报告、多账号和多范围验收、独立灰度/回退 |

声优和公司需独立能力标记与放行门槛，不等待另一项凑齐，也不影响既有三种模式、系列、提醒或推荐 V1/V2 的上线策略。13A 不增加环境变量；具体开关和部署流程在服务实现及发布阶段落地。
