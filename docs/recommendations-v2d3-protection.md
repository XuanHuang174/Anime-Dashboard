# V2 探索候选 v3：相关性保护与历史覆盖

本阶段实现 `association-novelty-explore.v3`，仅供离线只读对照。线上 V1、原 V2 准备配方、探索候选 v1/v2 都保留。不改用户数据或公共评分，不更新 Render 开关，不新增前端入口或算法 HTTP 参数。

结果与遗留问题见 [本轮报告](recommendations-v2d3-protection-report.md)，此前失败结果见 [两轮探索报告](recommendations-v2d3-exploration-report.md)。

## 先定义规则，再运行真实评测

约束在 `evaluation/v2d-exploration.v3.json` 注册，运行前与代码严格核对。沿用 v1/v2 的 0.50 整体关联、0.40 新题材、0.10 公共质量基础分，不搜索或调整权重。

### 1. 固定预算：400 候选、120 返回、每批 24

在已经安全、通过筛选、排除手账/反馈、具备真实关联和证据的集合中：

1. 按原 V2 探索评分/平衡池/重排计算当前请求的 incumbent（原结果），取前 96 条资格保留；这不是上次请求的历史缓存。
2. 取当前未施加重复惩罚的基础排序前 24 条，作为前缀参照。该基础分仍含整体关联、新题材和公共质量，并非仅按相似度排序。
3. 将上述 ID 放入水合池，剩余名额沿用双路候选补齐，最终仍不超过 400，只有一次主水合查询，不增加 800 条合并查询。

96+24 来自现有 120 返回／24 批次规格：保留四批资格，用一批做探索，不由账号、留出目标或已知排名决定。Bangumi ID 只用于同身份去重、定位和稳定平分；不推断续作关系。

### 2. 一个完整批次的关联前缀保护

在水合和证据复核后，先运行现有 V2 多样性提案，再对前 24 个位置逐一检查：

`提案前 k 条的题材关联总和 >= 当前基础排序参照前 k 条的总和`（k=1…24）。

每部作品的题材关联为它与实际高分样本题材／明确偏好题材的最大 Jaccard。与实际来源集合交集计算，不从标题、简介、长评或外部模型推断。Fraction 精确有理数运算，没有为通过评测而设置的容差。

不足时交换已经验证的池内作品：优先调整前缀最靠后的位置，选择能补足缺口的最小增益，再按原提案优先级／稳定 ID 破平。如果一次交换不足，则分步严格提高关联；每次只提高已保护前缀，不破坏更早约束。不可行时明确失败，不静默跳过约束或补不安全作品。

这不是针对 Top10 的特例，也不保证任意单个作品排名不降；必须重新检查留出命中、MRR、类别方向和重复度。**关联代理已成为直接优化目标，所以该代理改善不是独立的推荐质量证据。**

### 3. 返回覆盖保护

返回：保护后的前 24 条 → 当前仍有效的 incumbent 前 96 条 → 按已验证提案补足空位，按 ID 去重，总量最多 120。前 24 与 incumbent 重叠时，名额可补齐；不强行制造 120 条。

原作品若在安全、水合或证据复核时失效，立即从参照与保留区移除，不复活、不向后端发特殊豁免查询；只输出丢弃数量，绝不返回原计划的私人 ID 列表。保护不覆盖整个原前 120，原第 97–120 条仍可能被探索替换，应如实审计。

## 隔离和版本

- 仅修改 `personalized + explore` 的显式离线候选分支；其他类别、明确偏好冷启动和 V1 默认路径保持原逻辑。
- 保留 close 加权、open 重复惩罚等已版本化风格控制；不把偏好变为硬过滤。
- 分数和证据对象保持原值，只改变选择及顺序；关联证据不是完整排序原因，更不是喜欢概率。
- 候选配方摘要纳入本规则。`serving_enabled=True` 与探索候选参数一起使用直接拒绝，旧审批不能开启它。
- 计划只存在于单请求 scorer 中；返回统计为保留/丢弃/交换数量，不建立跨用户结果缓存。
- 将来若晋升线上，需要另行补全服务配方、证据/详情/游标版本合同与部署审批，不能靠修改默认值直接上线。
