# 推荐 V1 稳定性收口（2026-10-19）

## 范围

保持 `content.v1`、既有增强 9 控制与分页；不启用 V2，不改推荐权重、类别定义、排序公式、评分语义或推荐页布局/装饰/动效。
不创建业务表、不改用户评分、长评、标签、偏好或反馈，不继续做 V2 质量试验。

本次是核心用户链路的稳定性基线，不是全仓所有功能、全量图片迁移、压测或正式线上新版本的最终验收。

## 修复

### 1. 旧 V1 公共特征缓存不再是硬依赖

原 `public_features()` 直接调用缓存读写，异常可能使旧列表和详情失败，增强 9 关闭后的 V1 回退路径也受影响。
现缓存读取失败、常见缓存结构损坏时按 miss 处理，重新读取安全目录并构建真实公开特征；缓存写入失败仍使用本次真实特征。
缓存健康时沿原路径复用，排序、证据和状态令牌的生成规则不变。

只包围缓存操作，不吞数据库或特征构建异常。数据库失败仍由既有 API 合同返回 JSON 503，不回退 Mock、不伪装空手账。
缓存内容仍只有公开作品特征，没有用户画像、私人记录、评分或长评。

### 2. 共享限流故障必须拒绝服务，不能绕过

公共特征缓存可降级不代表限流也能忽略。推荐接口检查限流时，如共享限流缓存或检查发生非 API 异常，返回 JSON 503，业务写入不执行。
真正的 429 及 `Retry-After` 原样保留，未登录仍先返回 401；日志仅保留异常类型，不输出缓存连接地址、凭据或私人内容。
此保护限于推荐接口，不宣称改变全站其他接口的缓存/限流行为。

### 3. V1 回退配置明确关闭 V2

`scripts/prepare_recommendation_browse_rollout.py` 无论启用还是关闭增强 9，均输出：

```text
RECOMMENDATION_ALGORITHM_VERSION=content.v1
RECOMMENDATION_V2_BROWSE_ENABLED=False
RECOMMENDATION_BROWSE_ENABLED=True 或 False
RECOMMENDATION_BROWSE_EPOCH=本次新生成值
```

脚本仅输出配置，不修改 `.env`、Render、数据库或用户数据。每次显式切换生成新 epoch，防止旧游标重新生效。
部署人员应一次性将配置应用到所有 worker；增强 9 正常使用时保持开启，不为“稳定”而删除现有功能。

- 拒绝非本机、错误库名、SQLite 或生产 Neon 测试目标。
- 子进程固定 V1、关闭 V2 浏览、开启增强 9，测试中单独验证关闭/回退。
- 覆盖真实画像提取、冷启动、私人标签、旧记录关联、证据、加入想看、反馈撤销、批次游标、用户隔离、安全分级、失败恢复与并发锁。
- 旧 6C 状态用例迁至独立 PostgreSQL；其单个 V1/V2 令牌兼容用例只在测试方法内模拟审批函数。
  **没有放宽应用的 V2 审批或增加 PostgreSQL 生产旁路。**
- 冻结引擎 AST 检查继续验证 V1 公式未变。


## 发布与后续调整

本地正常配置已核对为 V1、V2 浏览关闭、增强 9 开启。无数据库迁移。
这不等同于已读取或修改 Render 运行配置；本轮未执行生产账号写入，也没有把本地测试称作新构建线上已部署。
部署完成后可沿既有 `verify_recommendation_browse_closure_deployment.py` 做授权账号只读联调；登录是唯一允许的 POST。
源码故障可回退上一提交；若增强 9 故障，使用既有回退脚本关闭它并轮换 epoch，保留 V1 和全部用户数据。
不全局清空缓存、不删除私人数据，按版本/epoch 失效旧浏览上下文即可。

接下来页面布局、排版、装饰、动效与转场按用户逐项提供的要求处理；不将它们捆绑进本次稳定性修复。
