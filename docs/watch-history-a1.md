# 观看历程与重看记录 A1：数据与接口基础

## 交付边界

A1 提供私有观看轮次、日期精度、历程接口及现有写入衔接。后续 [A2 已交付详情入口、时间线和操作表单](watch-history-a2.md)，[A3 已完成管理边界、清空恢复确认及端到端验收](watch-history-a3.md)。本文保留 A1 基础契约，新增行为与迁移要求以 A3 为准。

现有 `UserAnimeRecord` 仍是作品的唯一私人记录和当前状态；列表、快捷筛选、推荐、公开手账及现有统计继续读取它，不把重看轮次当作新增作品。

## 模型与日期

- `watch_revision` 是每条私人记录独立的历程版本，普通记录 API 只读。匿名及其他用户读取公开手账时不返回该版本，不返回轮次或随记。
- `WatchRound` 保存轮次编号、当前标记、状态、进度、起止日期、可选评分及备注。每条记录最多一个当前轮次，编号不重复；撤销重看后保留作废轮次，不复用编号。
- `WatchEvent` 保存版本、动作、来源、前后快照、可选实际日期/随记、系统记录时间及幂等操作编号。事件追加保存，撤销也追加一条事件，不改写过去的日志。
- 日期以 `YYYY` / `YYYY-MM` / `YYYY-MM-DD` 保存，空字符串表示未知。不会把年月补成某一天，也不会用记录的 `created_at` / `updated_at` 反推观看日期。不同精度只在其可能范围完全矛盾时拒绝，例如开始 `2021`、完成 `2020-12`。
- 迁移不扫描并重写旧作品，不推定旧观看次数。尚无历程的记录读取时返回日期未知的虚拟第 1 轮，GET 不创建数据。首次真实变化才将变化前的状态物化为基线。
- 首次物化的已完成旧记录不回填所谓“当时评分”；后续从未完成切换为完成时才截取当时总评分，来源为 `completion_snapshot`。轮次评分可单独更正，总评分后续变化不追改历史快照。

## API 契约

`GET /api/records/<id>/watch-history/?page=1&page_size=20`

仅本人访问，分页大小 1–100，事件按版本倒序。返回 `contract_version: journal.watch-history.v1`、`version`、`rounds`、`completed_rounds`、`rewatch_count`、事件数量及当前页 `events`。当前记录状态、该页事件和版本在同一行锁事务中读取。响应为 `private, no-store`。

`POST /api/records/<id>/watch-history/`

所有命令必填当前 `version`、新生成的 UUID `operation_id` 和 `action`：

| action | 参数 | 行为 |
| --- | --- | --- |
| `transition` | `watch_status` / `watched_eps` / `total_eps` 至少一项；可选 `occurred_on`、`note` | 同步当前轮次与主记录。无变化或进度越界返回 400。明确提供日期时，想看→在看填开始日期，未完成→完成填完成日期 |
| `start-rewatch` | 可选 `started_on`、`note` | 当前轮次须已完成；保留旧轮，创建新的在看轮次，进度归零，总集数沿用。没有提供日期则保持未知 |
| `update-round` | `round_number`；起止日期、`rating`、`note` 至少一项 | 更正指定非作废轮次；不改变主记录的当前状态、进度或总评分 |
| `note` | 非空 `note`；可选 `occurred_on` | 保存随记，不改变当前进度 |
| `memory` | 非空 `note` 与 `occurred_on` | 补录往事，可填大致年月；不重放历史去改写当前状态 |
| `undo` | `target_revision` | 只允许撤销最近一次非撤销操作；校验当前状态与轮次快照，较早操作需通过更正处理 |

响应返回最新历程与 `replayed`；A2 在成功响应上补充同一事务内的最新标准 `record`，用于同步界面，幂等重放也返回当前记录。相同操作编号、相同原始请求重试不重复写入；编号复用于不同内容、版本落后、状态冲突返回 409。发生冲突不自动重放。无效日期、混入其他动作参数、空随记等返回 400。

撤销只恢复观看状态、进度及相关轮次，不覆盖之后修改的主记录总评分、长评、标签或海报。开始重看的撤销将新轮作废，恢复旧轮为当前；再次重看使用下一个编号。

## 原有写入入口

`UserAnimeRecord.save()` 在同一事务内锁定旧值，保存成功后只比较状态、已看集数、总集数。发生变化时同步当前轮次并追加 `change` 事件；仅评分、长评、标签、作品资料变化不生成观看事件。

因此普通 PATCH、详情保存、快捷 +1、Django 后台和现有 Bangumi 收藏更新均保留其原行为并自动积累观测历史。收藏更新额外标注 `collection_import` 来源。未明确填写日期的旧接口不会把操作当天称作实际观看日。普通编辑从看过改为在看属于当前轮次更正，**不会自动推断重看**；重看须显式调用命令。

主记录、轮次和事件任一写入失败，整个事务回滚。详情编辑在身份绑定前遵循“用户→记录”锁顺序；导入按主键顺序锁定已有记录。新接口使用记录行锁串行化和版本冲突检查。

新建/批量导入的当前状态不自动伪造成一条过去的观看过程。其他模块不得用 `QuerySet.update` / `bulk_update` 直接改观看字段绕过事件服务；标签等无关字段的批量整理不受影响。

## JSON 备份与恢复

沿用外层 `anime-journal` v2，每条记录增加可选 `watch_history`：内部 `version: 1`、历程 `revision`、完整轮次和按版本升序的事件。不包含数据库主键或用户标识。实际日期、系统记录时间、评分来源和作废轮次都保留。

导入先校验日期、轮次唯一性、当前轮次、连续事件版本、操作编号及当前状态一致性，再开始整体替换。所有新子记录归属于恢复目标账号的新私人记录；异常回滚原手账。每条记录最多导入 1000 轮、10000 个事件，文件上传继续遵循既有 5MB 限制，超限明确拒绝。

旧模板不含历程时，按私人中文名、日文名、季度的完全相同组合匹配，或匹配到同一公共作品记录，保留该作品的现有历程。私人改名后即使恢复时建立了不同的公共资料行，完整私人资料仍可准确匹配；有歧义则拒绝恢复，不猜测合并。旧模板改变该作品状态或进度时，追加 `backup_restore` 观测，不假装这些是实际观看日期。提供完整历程的备份按其内容恢复。原有“整体替换手账”语义仍存在：备份未包含的作品及其子记录会随作品移除；新旧名称均不同且无法准确关联时不猜测合并，这部分差异预览仍留待后续数据工具完善。

## 发布与验证

迁移 **0033_useranimerecord_watch_revision_watchevent_watchround** 新增版本字段及两张表，包含轮次唯一性、当前轮次唯一性、进度/评分边界、事件版本与操作编号唯一约束。无新增环境变量。先执行 `python manage.py migrate --noinput`，再启动新版后端；A1 不依赖前端更新，也不提供额外公共接口。

使用隔离测试配置与本地专用 PostgreSQL，未执行生产迁移或真实账号数据写入。测试覆盖读接口无写入、旧接口兼容、日期精度、完成评分快照、重看、补录与更正、最近操作撤销、幂等、事务回滚、分页、账号隔离、公开隐私、JSON 新旧格式及真实双连接并发。相关回归同时覆盖标签整理、评分展示、公开手账、投稿与旧导入功能。

关联回归首轮 205 项及身份/推荐衔接补充回归 185 项通过（两轮存在重叠，不累加计数）；备份关联 35 项及最终 A1 专项 19 项通过。前端既有 483 项测试通过，Django 检查与迁移漂移检查通过。并发验证包含同版本命令一成功一冲突，以及旧快捷进度双连接各 +1 后数值和事件均完整保留。A1 未改前端生产组件，不以浏览器截图替代接口和事务验证。
