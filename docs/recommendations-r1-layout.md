# R1：推荐页布局与信息层级重构

## 范围

- 首屏改为紧凑的“我的手账 / 发现篇”标题、原有控制栏、主推作品与口味便签。
- 桌面主推卡在左、口味便签在右；平板及手机先展示主推卡，再展示压缩便签。
- 主推卡仍取当前批次第一项，标记为“本批首推”，不宣称每日精选。
- 原有其余结果及顺序不变；默认 12 项为 1 张主推卡 + 11 张网格卡，不添加凑数卡片。
- 重复的类别、风格及技术解释收纳到“浏览说明”；画像已充足时，待关联记录提示移入口味便签，完整说明可展开。
- 冷启动没有结果时，主推位置保留引导；明确偏好推荐显式标注依据；筛选无结果、请求失败仍有各自的恢复入口。保存成功但刷新失败的警告不折叠。
- 页尾收紧为真实批次进度及原有加载/换批操作。

## 工程边界

仅修改 React 展示组件、页面结构及 `.memphis-rec-container` 内的样式。没有后端、数据迁移、V1 排序、推荐请求层、证据合同、反馈/加入服务或资源会话逻辑修改；不启用 V2，不修改用户数据。

新增 `recommendations-layout.css` 在现有样式后加载，便于后续 R2 统一视觉；本阶段不引入 GSAP、不重做普通卡片与弹窗装饰。R2 负责手账视觉语言统一，R3 负责动效与转场及最终体验验收。

## 重跑方式

在 `frontend` 目录执行：

```powershell
node --test tests
node node_modules/vite/bin/vite.js build
# PLAYWRIGHT_MODULE 指向本机已安装的 playwright 模块；默认使用 Edge headless。
node scripts/test-recommendation-layout.mjs
```

无数据库迁移，不需要启动或写入 PostgreSQL。线上部署后仍需按真实数据检查视觉效果；本报告不代表已部署。

## 回退

通过正常代码发布回退 R1 的前端提交并重建静态资源即可；没有数据库变更和需清除的业务数据。算法开关、推荐快照命名空间及用户偏好/反馈保持原样，不需要切换 V2 或清理用户数据。
