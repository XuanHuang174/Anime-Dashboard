## 进入受控开放的操作顺序

1. **部署能力先行，服务保持关闭**：操作者在 Render 将 `RECOMMENDATION_RESTRICTED_CONTENT_ENABLED=True` 后重新部署，保持 `content.v1`、`RECOMMENDATION_V2_BROWSE_ENABLED=False`。模块 3 的数据库服务仍保持关闭。
2. **只读核对第一道闸**：确认后台部署能力开启、数据库服务未开启、实际服务未生效。当前 `verify_recommendation_controlled_deployment.py` 是“部署总闸与服务均关闭”的验收工具，不能原样作为此中间态／开放态放行脚本，否则预期 403 错误码及关闭态断言会变化。
3. **明确首批账号与作品**：仅对操作者确认的申请做人工审批；作品需在现有审核台账逐条审核，保留依据、当前指纹及有效期。不能按标题猜身份或仅凭 NSFW 标记批量放行；未知分级继续拒绝。
4. **最后开启数据库服务**：前两类资格准备完毕后，由超级管理员模块 3 明确确认开启，再执行小范围开放态验收；不要以本报告自动批准所有账号或作品。
5. **用户仍需明确选择**：默认安全范围不变。只有有效人工授权账号主动应用 NSFW 筛选，才可看到已审核作品；不把人工授权说成年龄核验。
6. **回退就绪**：异常时优先模块 3 持久关闸，必要时再关闭部署变量；重新开放前保证持久控制版本已递增，不能仅环境变量来回切换而宣称旧凭据永不恢复。详见 [M3 发布／回退清单](recommendations-controlled-m3-release-checklist.md)。

本报告只读验收没有实际执行以上开闸步骤。需要操作者在外部部署平台执行第一步，并在后续阶段明确生产灰度账号、公共目录作品和写入演练范围。
