# F1：导入差异与安全应用基础

F1 建立可供下一阶段工作区调用的私人导入服务：手动读取 Bangumi 收藏，冻结来源，比较字段，明确选择后应用。另提供 JSON 恢复逐项差异接口，并完成收录筛选、手账工具栏和片单标题的三处样式调整。

旧 Bangumi 导入入口和 JSON 整体恢复仍按原流程运行；F2 才把界面接入新方案。F1 没有反向写入 Bangumi、后台定时同步或完整冲突处理界面。

## 数据与边界

迁移 `0038` 新增四张表：

| 模型 | 职责 |
| --- | --- |
| `JournalImportPlan` | 本人的来源账号、读取游标、数量、版本、过期时间和创建请求编号 |
| `JournalImportItem` | 每项冻结来源、身份分类、字段差异、本地依据和是否已应用 |
| `JournalSyncBaseline` | 本人／来源账号／作品 ID 对应的确认来源值和确认后的本地值 |
| `JournalImportOperation` | 应用操作 UUID、请求摘要和成功回执，供原请求安全重试 |

读取来源只写这些导入表，不修改手账、公开作品、观看历程、计划或片单，不下载海报。来源调用在写事务之外执行；详情失败或字段不合法进入 `failed`，不使用旧导入器的截断或静默降级。失败项保留位置及失败说明，F1 不提供单项重读接口。

方案有效期 24 小时，每人滚动 24 小时最多创建 20 个方案；作品最多 `min(10000, USER_ANIME_RECORD_LIMIT)`，单个方案累计来源与差异最多 5MB。按每次一项读取控制事务与上游请求规模。过期后拒绝新应用，已成功操作仍可用原 UUID、原请求获得回执。F1 不自动清理过期快照；后续保留和清理策略在 F3 完善。

## Bangumi 接口

全部要求登录、限定本人，响应含 `Cache-Control: private, no-store` 和 `Vary: Authorization, Cookie`。请求拒绝未知字段；创建、读取步骤、应用不接受额外查询条件。

| 方法／路径 | 请求与结果 |
| --- | --- |
| `POST /api/import-plans/` | `{uid, request_id}`；创建方案，同 UUID 同来源重试返回原方案 |
| `POST /api/import-plans/<UUID>/scan/` | `{cursor}`；读取下一项并推进游标；旧游标重试返回已保存进度 |
| `GET /api/import-plans/<UUID>/` | `page`、`kind`；每页 20 项，可按分类筛选，返回差异及确认凭据 |
| `POST /api/import-plans/<UUID>/apply/` | `{revision, token, operation_id, decisions}`；整批明确应用，最多 50 项 |

合同版本 `journal.import-plan.v1`。方案状态为 `reading`／`ready`／`invalid`；扫描发现总数改变或重复作品 ID 时标记无效，必须重新读取。外部收藏不具备事务快照，数量未变且没有重复时仍可能跨请求发生变化，接口不宣称来源是同一时刻的完整快照。

`kind` 支持 `all`、`new`、`changed`、`unchanged`、`needs_review`、`failed`。名称和日文名只能用于发现潜在重复，不用于自动绑定；有效的已验证来源、标准关联或仍有效的私人身份更正才能确认更新对象。旧同名记录、身份冲突／失效、明确取消关联、共享三字段唯一键冲突，以及同步基线对应记录已删除／替换时均先核对，不能直接应用。

可比较的字段：

- 作品资料：`chinese_title`、`japanese_title`、`airing_period`、`studio`、`episodes`、`description`、`poster_url`、`bangumi_url`、`base_tags`。
- 个人记录：`personal_score`、`watch_status`、`watched_eps`、`total_eps`、`review`。

差异包含 `before`、`after`、`changed`、`source_empty`、`default`。已存在记录默认保留本地；新增项明确确认完整冻结来源。来源未提供的字段不进入可应用字段，不把缺失当成清空。总集数未知仍使用 0，数值 0 不属于“空”，`rate: 0` 按 Bangumi 未评分转换为 `null`。Bangumi 类型 1／2／3 映射为想看／看过／在看，4／5 映射为搁置，快照同时保留原类型以区分来源。

`decisions` 每项形式：

```json
{
  "item_id": "方案项 UUID",
  "action": "source",
  "fields": ["studio", "review"],
  "clear_fields": ["review"]
}
```

| `action` | 行为 |
| --- | --- |
| `create` | 只允许新增项，明确采用该项完整来源；不接受 `fields`／`clear_fields` |
| `source` | 只替换所选字段；来源为空须在 `clear_fields` 逐字段确认 |
| `fill-empty` | 仅对所选的本地空字段采用非空来源；不覆盖 0 或已填写内容 |
| `keep` | 保留本地并确认本次来源；不接受字段覆盖 |

客户端只提交取舍，不提交新字段值；服务端从已冻结快照读取实际值。`token` 有效 15 分钟，绑定账号、方案及版本；GET 可重新获取，无法绕过每项本地依据复核。快照之后的私人字段、进度版本、自定义标签、身份或基线变化会使应用返回 409；本批不写入。另一批成功后方案版本递增，须重新读取再确认。

同一方案的操作 UUID 对完全相同请求只应用一次；改变内容复用 UUID 返回 409。请求中后面的某项失败会回滚前面已进行的修改、基线和回执。验证错误 400、身份／版本／约束冲突 409、上游读取失败 502。

## 应用与模块关联

更新仅写当前用户的私人资料；尚未初始化的旧记录先复制现有共享资料为私人快照，再处理所选字段。自定义标签及已有私人配色保留。采用海报 URL 时切换为该 URL，不在事务里下载图片或删除存储文件。新增共享身份占位行只按确切 Bangumi ID 查找，不修改既有共享作品资料，不靠名称绑定；普通用户新建的占位作品保持隐藏。原有站长新作发布规则继续独立适用。

进度变化沿用观看历程观察机制，事件来源为 `collection_import`；不把导入时间当作实际观看日期，不自动创建重看轮次。已看大于已知总集数时拒绝，要求重新选择字段，不自动截断或补成看完。既有观看计划仍按原历程规则协调状态，不新建计划，不改优先级、计划日期和备注；片单成员和入选理由不变。

应用成功后，即使选择保留本地，也保存已确认的来源值和实际本地值，供 F3 区分来源单侧变化、本地单侧变化和双侧变化。F1 只暴露这两份基线与 `first_review`，尚未提供三方冲突决策或撤销接口。该内部基线不进入 JSON 备份；整体恢复重建记录后，旧基线保留空关联，下一次要求重新核对，避免误当成可自动新增的作品。

事务锁按账号、方案、私人记录、方案项顺序取得。账号使用 `FOR NO KEY UPDATE`，仍串行化同账号命令，同时允许已有记录写入者完成延迟外键检查；片单账号锁同步使用该模式。回归覆盖真实 PostgreSQL 的原 UUID 并发应用、记录写入／账号锁确定性交错及回顾创建与真实历程更正，避免互相等待。

## JSON 恢复差异

`POST /api/import-plans/json-diff/?page=1&kind=all` 接受现有 JSON／文件格式，限 5MB 和既有记录数量上限。该接口只比较，不执行恢复、不建立 Bangumi 同步基线，也不提供逐项合并写入。

返回文件摘要、每页 20 项差异、分类计数和原整体恢复影响 `restore`（含原确认 token）。分类为 `new`／`changed`／`unchanged`／`removed`／`needs_review`；用原私人三字段匹配规则及共享三字段兼容规则确定可保留对象，不引入模糊匹配。

逐项比较作品资料、百科链接、标签配色和个人记录；历程／计划比较完整内容，但响应只提供摘要、轮次数／事件数或状态，避免重复返回大段私人内容。文件未提供历程／计划时明确 `preserve_if_uniquely_matched`；提供时标记替换，计划显式 `null` 表示清空。删除项与原整体恢复影响同时列出。

私人身份凭据继续由原恢复接口校验，本接口不把凭据差异当作可单独写入的字段；评分规则和片单影响沿用原整体预览。最终提交仍须使用原 `/api/import/` 整体恢复确认流程，原令牌有效期 10 分钟。F2 再完善详细预览和资料整理入口，不把 JSON 恢复与增量 Bangumi 同步混为同一种操作。

## 三处界面优化

- 收录作品的观看状态复用 `SearchableSelect` 外观但不显示搜索框。支持方向键、Home／End、Enter；Esc 只关闭下拉框，焦点回到触发按钮，不连带关闭抽屉。
- 手账分页、排序说明与收录操作合并为一张紧凑工具栏：分页和轻量排序说明在上方，收录及限制说明在下方，自然换行。排序用 `fa-arrow-down-wide-short`，收录沿用 `fa-layer-group`；取消原右侧大面积空卡片。公开展示页不改变。
- 主题片单标题增加 `fa-list-check`，编辑／只读预览一致，隐私锁图标仍沿用统一样式。
