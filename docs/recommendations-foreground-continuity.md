# 推荐页前后台切换与浏览连续性修复

## 问题与原因

原 `recommendationReload.js` 将每次窗口 focus、页面变为 visible、BFCache 返回都标记为“数据已变化”，触发整页 `retry()`。浏览控制器随即清空卡片、游标并重新读取第一批。已用纯内存合成数据复现：无数据变动时，第 3 批直接回到第 1 批。

这是通用重载监听器过度触发，不是 V1 推荐排序算法问题。本次不修改排序、候选规则、用户评分、标签、长评或生产开关，也无数据库迁移。

## 新行为

- 普通切换标签页、浏览器进入后台后回来：保留当前批次、已加载卡片、DOM、滚动位置、理由展开状态及未失效的详情会话。
- 前台检查防抖 250ms，普通检查至少间隔 30 秒；没有持续轮询。未超过间隔不会发请求，超过后只发上下文探针，不重新计算推荐。
- 版本不变时不操作浏览状态。请求失败、断网、404/429/503 或不兼容响应不会清空卡片，不假装数据已更新。
- 其他标签页的通用通知只包含不透明 nonce。新客户端会绕过普通时间间隔、先核验当前账号；即使另一账号操作，也不会仅凭同源通知令当前账号失效。
- 确认外部上下文变化：保留作品标题、元数据、顺序和当前批次，停止使用旧证据、停用旧游标/写入按钮、关闭失效详情/资源会话；显示“推荐依据已更新，已保留当前浏览位置”。只有用户点击“重新加载推荐”才回第一批。
- 已知本页保存偏好、加入想看、隐藏/撤销成功，仍走原有确认后立即刷新闭环。不弱化 409 和幂等保护。
- 已知快照过期：保留列表位置，提示过期并要求主动重读，不强行跳页。
- 不同账号登录仍立即销毁旧工作区；不把私人推荐持久化到 localStorage 或共享缓存。离开推荐路由导致组件真正卸载、手动刷新网页或浏览器丢弃标签页，仍会创建新浏览会话，本次不提供跨路由/跨重启恢复。
- 原“取消偏好设置后重读最新设置”的明确操作路径保留，不把它混同为普通前后台切换。

## 只读上下文接口

`GET /api/recommendations/context/`

要求登录，只使用 `request.user`，拒绝所有查询参数，POST 不支持；沿用推荐读取限流、数据库故障 503、private/no-store 和 Vary Authorization/Cookie。

返回：

```json
{
  "contract_version": "recommendations.context.v1",
  "rollout_revision": "<不透明发布摘要>",
  "browse_enabled": true,
  "context": {
    "algorithm_version": "content.v1",
    "profile_version": "<本人画像HMAC摘要>",
    "preference_version": 1,
    "feedback_version": 0,
    "profile_policy_version": "profile-sampling.v1",
    "profile_min_score": "8.5"
  }
}
```

实际还包含现有 ranking/taxonomy/feature/selection 规则版本。复用已有本人画像与 `EvidencePresenter` 版本生成，不构造公共题材索引、不查询全库候选、不排序。仅选择必要本人字段，不 SELECT review，不返回来源作品/逐作品评分，不向外部模型或服务发送数据，不创建偏好/反馈行。

探针是更新提示，不是授权、安全凭证或目录全量审计。它检测本人画像、偏好、反馈和发布设置；目录候选作品的实时安全、目录变化和完整快照有效性仍由原详情/分页服务直接验证，不能凭一次“未变”跳过服务端检查。

## 竞态与会话边界

探针独立使用 AbortController、请求代次与当前上下文签名；账号卸载、页面隐藏、明确重载或数据流变化后，迟到成功/失败均不能覆盖新状态。偏好编辑期间延迟通用通知，不覆盖草稿；同页保存仍按 expected_version 检查。

反馈的跨标签页消息继续读取本人反馈版本后处理；不再每次 focus 重复读隐藏作品。后台收到的反馈消息保留待检查标记，回到前台后补查，不丢通知。

外部失效取消推荐分页请求但不取消尚未确认的业务 POST。保留卡片壳，不再展示旧证据；恢复按钮只读新列表，不重放加入/反馈/保存请求。

## 发布与手动复验

先部署后端上下文接口，再部署前端；无新环境变量、无迁移，不改变当前 V1 或门槛功能开关。滚动部署时旧后端 context 404 仅跳过该次探针，不回退到重新排序；原分页/详情 409 恢复仍有效。

部署后刷新一次加载新前端，浏览至第 3 批，记住一部作品并滚动到中段。反复切标签页/最小化恢复（含超过 30 秒），确认不出现整页骨架屏、不回第一批、展开项和滚动位置保留；打开详情后重复，确认未变时详情保留。在手机端做相同检查。

若在另一处真实修改本人偏好/手账，再返回原页面，应看到更新提示而非自动换榜；点击重载后才开始新第一批。该写入场景本次已在隔离环境验证，线上复验须限定用户明确授权的测试账号，不对其他用户写入。

本任务没有代替用户操作生产部署，也未执行线上业务写入。若需回退本修复，按正常版本发布回退代码，仍保持 V1 和既有数据库列/个人资料；不清除全站缓存、登录信息或用户手账。
