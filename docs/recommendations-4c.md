# 核心 4C：偏好确认、画像解释与更新闭环

## 范围和数据安全

复用 `GET/PATCH /api/recommendations/preferences/`、画像与推荐接口。不新增表、不迁移、不重跑全站关联，不改变 V1 排序权重。偏好只能保存到当前用户独立表，GET 不写入；不修改手账评分、长评、原标签或作品身份。成人/未知分级作品仍由后端排除，不读取长评、不请求外部模型。

画像 `extraction.preference_policy` 兼容扩展上限/建议数量以及“非硬筛选”“观察须确认”语义。个人推荐 API 使用 `Cache-Control: private, no-store` 和 `Vary: Authorization, Cookie`，防止保存后复用过期私人响应；内部公共目录特征缓存不受影响。

## 三区块面板

`RecommendationPreferencesPanel.jsx` 在原“我的口味”弹窗中展示：

1. 白底明确偏好：显示已保存设置和本地草稿，最多 20 项，首次建议 3–5 项。
2. 青绿色只读画像：安全已关联、看过且个人评分达到阈值的作品；去重样本数及题材出现次数，不提供勾选。
3. 淡黄色常见题材：只观察 4A 的安全弱样本，最多 8 项，默认不勾选。点击“加入我的偏好”只更改本地草稿，保存后才成为明确偏好。

自动画像与独立明确偏好不会互相覆盖。空白私人标签不从目录自动补齐，未知管理标签不猜测。缺失摘要使用不可用说明，不编造 0 数值。

## 保存与刷新分离

`createPreferenceEditor` 与 `useRecommendationPreferences` 管理编辑、保存、失败、冲突与重新读取。

- 草稿修改、清空、关闭均不写后端；清空只有点击保存后才清空明确偏好。
- 连击只发一次 PATCH，携带 `expected_version`；请求未确认保留草稿，重试仍受版本保护。
- 校验后端确认合同、题材集合和版本后，才能显示已保存。
- 后端响应内容不兼容时不声称已保存，须重新读取确认，不重复提交。
- 409 保留草稿，提供“读取最新设置”。读成功后可以明确采用最新设置，或将本次相对旧基线的新增/移除合并到草稿。其他页面新增的题材不会被整份旧草稿覆盖；合并后必须再次检查并保存。超过 20 项时不合并写入。
- 已保存确认与推荐读取使用不同状态。`useRecommendations` 记录已确认设置，在刷新失败时显示“偏好已保存，推荐更新失败”，重试只 GET，不再 PATCH。
- 刷新校验画像/偏好/推荐一致性，以及读取版本不早于保存确认。更新成功后同步便签、冷启动卡、推荐内容及分页。
- 不持久化本地草稿，不将画像放入浏览器存储。卸载取消请求、禁止迟到响应改写新页面。

排序解释：冷启动有明确偏好时“根据你选择的题材推荐”；画像充足时“参考高分作品，并结合你的明确偏好”。取消题材不是禁止该题材，评分画像仍可能支持对应作品。

## 手账同步

- 推荐路由重新进入自然重新读取。
- Dashboard 编辑、删除、新增、导入成功后发送无私密内容的失效通知；不以乐观更新或失败通知代替真实成功。
- 身份确认成功、偏好保存成功通知其他标签页；同页显式刷新。
- 浏览器焦点返回、页面恢复可见、BFCache 返回及其他标签页失效通知触发合并刷新，250ms 防抖，无轮询。
- 面板打开或正在读取时暂缓自动刷新；关闭后处理待更新通知，避免覆盖编辑草稿。偏好面板关闭也重读最新设置，不写入。
- 显式重载会消耗待处理失效通知，避免关闭面板/保存后重复发起同一轮刷新。
- 存储事件只写随机失效 nonce，不包含用户 ID、标题、题材、评分、令牌。浏览器禁止存储时仍可通过重新进入/焦点返回读取。
- 推荐重新加载后按真实观看状态协调本页“加入想看”成功状态，避免另一处删除记录后旧成功按钮仍禁用；在途 POST 不清除。
