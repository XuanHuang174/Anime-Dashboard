# 一般成人内容：用户自助浏览开关与服务端边界

## 本轮功能

新增可独立启用的“一般成人内容会话模式”。启用后，活跃登录用户通过筛选草稿中的 NSFW 开关选择本次浏览范围，不再提交账号申请或等待管理员批准。

- 不新增账号授权、不自动审核作品、不改手账、评分、标签和长评。
- 原账号审批记录及审计保留，不删除、不改写。新模式的推荐上下文不读取旧账号审批表；旧授权的到期、批准或撤销不再决定本模式的访问资格。
- 旧账号申请与批准 API 在新模式下拒绝新写入；历史审核记录仍可读取。
- 普通安全范围依然为默认。只有应用筛选才改变本次浏览，不写长期偏好。
- content.v1、原排序、前置筛选、400 候选上限、120 单轮上限保持不变。一般成人作品仍须有真实题材关联，不凑数、不伪造依据。

## 内容安全边界（不是全 NSFW 目录放行）

既有作品审核服务升级为 `release-review.general-adult.v2`，复用现有台账、专门权限、版本校验、签名确认和审计，不新建另一套业务表。

有效结论须同时满足：

1. NSFW 分级明确、Bangumi 身份有效。
2. 有当前目录指纹绑定、尚未到期的新版审核结论及内部依据编号。
3. 审核人员基于可靠依据明确确认：涉及性内容的人物均为成年人，且排除禁止内容及年龄不明情形。未勾选、字符串或数字代替布尔确认均不能通过服务。
4. 未命中已知禁止身份或保守风险排除。即使管理员确认或历史数据库中已有 approved，也不能覆盖这些排除。

风险检查只读取公共目录身份与标签，不读取私人文本，不从标题、简介、相似名称或没有风险标签推断“成年”。**风险词不是完整识别器，检查通过不代表已核验；仍须有真实依据支持的新版本结论。**

历史 `release-review.ledger.closed.v1` 结论不会自动升级，原数据与审计原样保留；部署后不再作为成人作品放行依据。没有可用核验作品时，开关显示不可用，显式成人范围请求返回 `adult_catalog_unavailable`，不会伪装成完整成人推荐。

本轮不代替人工确认任何真实作品，不批量导入、不审核指定 ID、不获取成人媒体，不承诺旧统计中的所有作品都可参与推荐。

## 合同与失效

- 新账号展示合同：`recommendations.eligibility.session.v1` / `eligibility.session.v1`。
- 新会话范围策略：`content-scope.general-adult.v1`。
- `eligibility_version=0` 表示不依赖账号审批；不是自动创建“已批准”账号记录。
- 作品结论版本、服务开关版本、目录指纹、释放集合和用户绑定仍进入范围指纹、证据与快照上下文。
- scope_valid_until 由当前作品核验有效期约束，不继承旧账号授权的到期时间。
- 作品撤销、到期、风险或分级变化时，旧游标/证据不返回旧数据；有旧上下文的请求在释放集合变空时返回 409。初次请求无可用范围返回 403。
- 列表、详情和响应水合后继续复核当前目录；成人封面仍使用中性占位，不增加资源媒体分发。
- 前端兼容旧人工授权模式与新会话模式；不支持新版合同的旧前端关闭式降级，不会获得额外权限。

## 配置与部署顺序

新增配置 `RECOMMENDATION_NSFW_SELF_SERVICE_ENABLED`，默认 False；本轮没有修改生产环境。

这是账号依赖的灰度开关，不是内容豁免：原部署总闸和带审计的后台服务开关仍必须有效，新版一般成人内容校验始终执行。

1. 先部署兼容前后端。无需数据库迁移；`makemigrations --check --dry-run` 应无差异。
2. 新版内容结论只应对有充分依据、符合一般成人边界的作品建立；禁止批量继承历史批准或仅凭 NSFW/有效题材放行。
3. 完成隔离验证后，才安排明确授权的只读部署核验及受控启用。不能把新模式开关当成生产全量放行许可。
4. 模块 3 会显示当前是会话模式还是旧人工授权模式；会话模式禁止再批准账号，下方审批仅为历史记录管理。

## 回退与缓存

- 只回退账号模式：先通过既有带审计的服务关闭流程关闭 NSFW，再将新模式配置设为 False 并部署；回到需要账号授权的旧模式，但新版作品内容校验仍保留。
- 需要重新开启时按正常受控流程执行，服务版本递增后旧游标和证据保持失效。仅来回切环境变量不等于持久化缓存失效，不能依赖它使旧上下文永久作废。
- 如须回退整个代码版本，先保持 NSFW 服务和部署总闸关闭；不得在服务开启状态恢复会接受旧审核结论的旧代码。
- 不清除手账、偏好、反馈、审批或审计；不切换 V2。不需要全局清空其他业务缓存。

## 验证范围

自动化均使用本机独立 PostgreSQL 与合成作品，未连接生产 Neon 或读取真实账号。覆盖：

- 无账号申请的活跃用户、新模式申请/批准写入拒绝、旧授权到期不影响新模式。
- 无新版审核、历史审核、缺少确认、未知分级、风险标签及已知禁止身份的关闭式处理。
- 安全 V1 同条件顺序一致、私人字段不变、候选前置、列表/详情证据一致。
- 目录变化后的最终复核、作品撤销后的 PostgreSQL 行锁竞争、并发加入与反馈不覆盖。
- 新旧模式合同兼容、旧游标/证据失效、前端草稿与失败重试。

单元/SSR 合同测试不代替真实浏览器验收。本轮未打开生产开关、审核真实作品或声明线上已开放。
