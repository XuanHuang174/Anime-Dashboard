# V2 质量修订：相关性、重复度与计算开销

本次仅修订候选引擎 `content.v2`，重排策略号为 `balanced-rerank.v2`。
`content.v1` 的评分公式和排序实现保持不变；线上默认仍为 V1。
5B-3 的六项门槛及阈值保持不变，失败报告不能产生发布批准。

## 修订原因

- 聚合题材向量容易让单个高频题材超过与真实高分作品更接近的题材组合。
- 仅使用最大重复度，遇到第一部相似作品后惩罚即饱和，不能体现重复持续累积。
- 熟悉类应允许围绕有实际高分样本支撑的题材组合适当集中。
- 对每个公共作品反复计算相同题材的证据，以及跨区域数据库的游标多次读取，会增加延迟。

## 固定策略

所有得分仅用于内部排序，不是喜欢概率，不返回页面，不做评分可信度修正。

| 分类 | 基础排序信号及权重 | 重复惩罚上限 |
| --- | --- | --- |
| 为你发现 | 最近真实参考题材集合重合度 0.50，证据 IDF 关联 0.20，向量关联 0.15，公共评分 0.10，新题材 0.05 | 0.25 |
| 熟悉的心动 | 证据 IDF 关联 0.65，高分样本支撑组合 0.25，证据来源个人评分乘关联 0.06，向量关联 0.03，公共评分 0.01 | 0.005 |
| 换一种口味 | 最近真实参考题材集合重合度 0.45，向量关联 0.30，新题材 0.15，公共评分 0.10 | 0.18 |

真实参考集合只来自有效高分样本或明确偏好。熟悉类的支撑组合按有效高分样本的个人评分权重汇总，确定性选取最有支撑的组合；这是题材特征，不推断作品系列，不合并作品身份。

发现类使用完整已选前缀的 `0.7 × 平均重合 + 0.3 × 最大重合`；熟悉类仅轻度最大重合惩罚；探索类使用 `0.2 × 平均完整题材重合 + 0.8 × 平均新题材方向重合`。
分差超过对应惩罚上限的高关联作品不会被多样性项逆转。

候选池仍最多 400 部：一半优先保证相关性，一半按喜好题材分层，再在层内轮换实际题材组合。只按 Bangumi ID 去重；不同作品即使题材相同也仍然有资格入选，不推断续作，不填充无证据作品。

## 性能与安全边界

- 每次请求独立复用公共原始标签/已识别标题冲突及有效题材组合的计算，各最多 2,048 项。超过上限正常计算，不丢弃有效作品。
- 证据缓存绝不跨请求或跨用户；公共评分始终按当前作品重新计算，不因题材相同而复用其他作品的评分。
- 公共目录读取使用有上限的客户端游标与紧凑元组，读取当前 Bangumi ID、公共评分及原始题材输入的 SHA-256 指纹，最多 50,001 条；超过 50,000 条拒绝计算，而非无上限载入。
- 指纹基于长度前缀编码的原始标签、中文名、原名，避免分隔符歧义。只有与公共特征索引完全匹配时才复用题材；新增、变化或缺失指纹的条目统一重新读取元数据，不依赖可能未更新的 `updated_at`。题材过滤前即完成比对，不让失效特征占用分层配额。
- PostgreSQL 使用内置 `sha256(bytea)`，无需安装扩展或迁移；实现及用途可核对 [PostgreSQL 官方说明](https://www.postgresql.org/docs/current/functions-binarystring.html)。SQL 与 Python 指纹编码有 Unicode、标点、空字段一致性测试。
- 保留候选水合时的当前安全过滤，以及返回前来源作品的安全复核。目录变更不允许使用旧特征编造证据。
- `_ranking_trace.stage_ms` 仅用于内部评测，区分公共读取、题材计算、分层、候选水合/安全复核和重排。不会作为推荐概率展示。
- 缓存键、分页状态和发布指纹绑定新策略，旧凭据不能批准新代码。回滚仍只需将服务端算法设置为 `content.v1`。

## 验证方法

先运行隔离测试，禁止使用生产库作为测试数据库：

```powershell
.\.venv\Scripts\python.exe manage.py test --settings=config.recommendation_test_settings --noinput
```

真实对照继续使用 `verify_recommendation_release` 与 `compare_recommendations`，步骤见 [5B-3 文档](recommendations-5b3.md)。
仅对明确授权且自然具有足够有效样本的账号进行只读评测，禁止改评分、遍历其他用户或读取长评；每次代码变化后重新生成测试凭据，报告写入新的受控目录，不覆盖历史报告。

必须逐项检查原有安全、证据、相关性、类别、性能和回滚门槛。即使全部通过，也只是该授权样本的基线验证，不代表统计显著性、真实用户满意度或自动上线许可。留出命中全为零时必须如实披露，不能宣称预测准确率提升。

本次不需要数据库迁移，不改前端、不改原始目录或私人手账数据。
