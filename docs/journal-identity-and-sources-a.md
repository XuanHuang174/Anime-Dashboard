# 批次 A：手账作品身份与外部资料

本批修复从公共库加入/添加番剧后，必须编辑保存一次才可能读到系列与制作资料的问题，并将标准作品核对接入手账。标签清洗、类型多选、年份组合筛选和跨推荐模块返回快照留在后续批次。

## 身份写入与读取

- `records/add/` 与既有标准新增、详情保存、导入路径保持一致：在私人资料完成保存后进行严格唯一匹配，之后才返回记录。匹配有歧义时不自动绑定。
- Bangumi 智能录入返回当前账号专用、有效一小时的签名来源凭据和规范条目链接。创建时验证凭据，保存到 `UserAnimeRecord.verified_bangumi_id`；不通过客户端直接传一个 ID 来修改公共 `Anime.bgm_id`。
- 新来源进入既有身份解析、已拥有作品判断、系列提醒、系列/制作资料状态及重复加入保护。当前标准库未收录、内容范围不可用时仍按原规则处理，不能用来源凭据绕过内容审核。
- 已确认来源与输入条目 URL 不一致时返回明确错误；录入凭据过期时可重新智能录入，或清除来源后手动创建。手填 URL 始终只是外链，不凭它宣称完成身份关联。
- GET 不修复或批量修改旧记录。旧记录可继续人工核对；不会修改观看状态、评分、长评、标签或别人的公共资料。

## 手账内核对

预览详情的“系列与关联”在未关联/关联过期/身份冲突时提供“核对标准作品”，打开现有核对工作台并定位当前记录，使用 `scope=all`。编辑模式“数据管理”和预览模式“更多功能”可打开全部待核对记录。

核对不依赖“看过”、评分或推荐取样门槛；草稿确认、候选凭据、批次幂等、冲突处理沿用原工作台。核对面板在手账上层打开，底层列表及详情保留；完成关闭后刷新身份与资料。NSFW 范围为本次显式选择，服务端资格与作品审核仍生效，暂存/提交期间禁止切换范围。

界面区分“未关联”“关联需重核”“标准库未收录”“当前内容范围不能读取”和读取错误。真正的服务异常不再被简单当作系列模块关闭而隐藏。

## 两个独立的资料链接

- 私人 Bangumi URL 存入 `private_bangumi_url`，萌娘百科继续使用原字段。JSON 备份接受/输出新 URL，旧模板默认空值，同账号已签名标准身份引用继续复用原恢复逻辑。
- 已核验来源/公共权威 ID/有效私人关联可生成规范 `https://bgm.tv/subject/<ID>`；不根据标题拼接 Bangumi 详情地址。
- 编辑窗口分别显示两个 URL 框，提供“填入 Bangumi”和“生成萌百链接”。后者按标题 URL 编码生成，明确提示可能需要修正消歧义页面；改名不自动覆盖手填链接。
- 预览“百科与原站资料”提供两个独立、有图标的外链，在新标签页打开，缺失时显示未设置。禁止可执行协议及包含用户口令的外链。
- 从备份恢复、跨账号复制或内容范围变化时，来源/私人关联仍需通过既有验证；普通 URL 不提升为已确认身份。不在标准库或未获当前范围许可的条目不会因此获得系列与制作访问权限。

## 部署与验收

新增迁移：`anime/0025_useranimerecord_private_bangumi_url_and_more.py`，仅添加可空来源 ID 与默认空链接，不做历史数据回填。无新增环境变量或依赖。生产部署须先执行原部署流程中的 `python manage.py migrate --noinput`，再启动新版服务；不要用测试配置操作生产库。

建议检查：

1. 从公共库加入一部可严格匹配的旧条目，不编辑，立即预览系列与制作。
2. 智能录入后保留来源，即使修改展示名，创建后仍指向所选 Bangumi 条目；纯手填无充分依据时显示核对入口。
3. 分别用想看、在看、搁置、未评分、低评分记录打开核对入口，确认后返回原详情，不需要改评分/状态。
4. 编辑/生成两个站点链接，确认私人保存不改变公共条目及其他账号。
5. 同账号 JSON 导出/恢复，验证链接与允许恢复的身份引用；检查其他账号不可读取私人记录或复用录入凭据。

本地测试使用隔离 SQLite/PostgreSQL、模拟 Bangumi 数据与合成浏览器夹具，不代表已完成生产登录态验收。
