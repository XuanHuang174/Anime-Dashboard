# 核心 5C：页面表达与上线验收

## 本次交付范围

保留“克制的孟菲斯”页面骨架、我的口味便签、冷启动引导、横向主推及响应式卡片网格，不新增统计卡片或第二套收藏体系。

- 三类推荐各有一句定位说明；当前分类说明使用轻量文本区域与无障碍实时提示。
- 主推和普通卡片保留一行推荐理由，新增原生“为什么推荐？”折叠区域，默认收起；详情复用同一组件并默认展开。
- 高分作品依据展示来源作品、来源作品的个人评分及实际共有题材；不会把当前作品的 Bangumi 分数当作个人评分。
- 明确偏好依据单独展示，仅列出后端实际返回、且与当前作品共有的已选题材。不伪装成完整高分画像。
- 明确说明共同题材不是喜欢概率，Bangumi 评分属于公共评价。
- 页首/页尾版本标识跟随服务端 `algorithm_version`；尚未加载版本时不预设 V1。兼容 V1/V2，未知版本按合同错误处理，不回退 Mock。

## 数据与交互边界

新增 `recommendationExplanation.js` 只负责展示前的结构校验，不是推荐引擎：

1. 接受 `rated_work` 和 `explicit_preferences` 两种既有证据类型。
2. 共有题材必须非空、不重复，且确实位于当前作品的有效题材中。
3. 高分来源须有有效 Bangumi ID、非空作品名和有效高分个人评分；公共评分不参与补齐。
4. 明确偏好的来源作品应为 null，不虚构作品或个人评分。
5. 缺失/不兼容证据显示中性说明，不从片名、简介、目录标签或长评推断理由；仍可查看基础详情或执行原有想看操作。

前端检查不替代后端安全过滤、来源真实性核验或用户隔离。服务端继续负责成人/未知分级过滤与证据溯源。

展开区域不发请求、不写偏好、不添加手账、不进行外部跳转，使用浏览器原生 details/summary，支持键盘操作。作品或证据发生变化时重建折叠区域，避免新卡片沿用旧证据。
详情独立读取当前详情接口的证据，不用点击时的旧卡片理由填补失败请求。

“查看详情”“加入想看”、旧记录保护、取消旧请求和分页状态校验继续复用现有逻辑。本次不改后台模型、迁移、推荐权重、版本开关、验收阈值或线上数据。

## 浏览器与部署验收清单

- 桌面 4 列、平板 3 列、手机 2 列/超窄单列；长来源标题与共有题材不能横向溢出。
- 卡片默认收起；点击或聚焦 summary 后按 Enter/Space 可展开、收起；焦点提示清晰，不触发加入想看。
- 详情默认展示完整证据；缺证据仍可关闭详情，不显示虚构来源。
- 切换三类分类时更新定位说明；明确偏好推荐持续显示降级提示。
- 加载、失败、空结果不出现虚构作品或虚假 V1/V2 版本。
- 加载下一页保留前页结果；画像、偏好或算法变更后重新读取，不混入旧快照。
- 使用真实授权账号检查理由与手账一致；重复加入不会覆盖评分、长评、状态；禁止为验收修改分数。

本次 computer-use 在浏览器 URL 安全校验阶段停止，未完成真实浏览器视觉/键盘操作验收。这些条目必须人工补验或在可用的安全浏览器环境中验证，不能用静态组件测试冒充端到端通过。

## 上线与回退边界

5C 页面表达兼容当前 V1，不需要先启用 V2。页面部署后仍使用服务端实际配置的版本，前端不接受任意算法覆盖参数。

V2 的现有性能门槛仍未通过，本次不改变此结论，也不生成新发布许可。V2 正式切换必须按 [5B-3](recommendations-5b3.md) 在部署环境完成独立验收并人工批准。
回退服务端算法仍设 `RECOMMENDATION_ALGORITHM_VERSION=content.v1` 并重启，无需更改 5C 组件或清理全站缓存。前端请求失败保持明确错误/重试入口，不偷偷替换 Mock。
