## 选项如何排序

仅调整“我的明确偏好”的选项展示，全部 41 项统一按安全公共目录中的有效题材作品数降序排列，不把新题材单独塞到列表尾部。每部作品的同义标签只计一次；数量相同按固定规范顺序排列，0 部作品的选项仍保留在后面。

统计口径是：显式 `nsfw=False`、有效 Bangumi ID，并经当前词表清洗的公共题材；名称等于标签的排除规则与推荐提取一致。包含已审核别名的规范计数，不采用简单字符串包含匹配。不统计私人手账、不依据用户选中情况、个人评分或反馈决定排序。这里的数量不是个人可见结果数或喜欢概率。

`available_tags` 在独立的偏好 GET/PATCH 响应中提供展示顺序；`available_tag_counts`、`option_order_version`、`option_order_status` 和 `option_catalog_revision` 是新增的只读元数据。前端沿用服务端数组顺序渲染，无需维护第二套 41 项列表，也不增加统计卡片或数字仪表盘。

**固定规范顺序没有修改**：保存的 `tags`、自动画像、画像内偏好合同及推荐计算仍按固定顺序处理。展示顺序不进入推荐向量、权重或快照计算。用户选中状态按标签身份绑定，排序不自动选择任何题材。正在编辑的面板使用已打开的选项快照，不在点击复选框时重排。

后续扩充只需完成审核、纳入版本化词表并发布，公共计数会自动遍历新的可用选项；有覆盖量的新题材会进入对应位置，不需要再写前端排序表。

## 性能与失败恢复

统计只在偏好选项接口执行，不在画像、推荐排序或证据生成链路执行。公共统计使用独立 `recommendations.preference-options` 缓存命名空间，包含词表、提取规则、排序策略版本与目录精确摘要；缓存只保存规范题材计数和总量，不保存私人资料或作品原文。

每次读取先用一条聚合 SELECT 检查当前安全目录摘要，命中时仅传输摘要/总量，不下载全部公共标签。首次或摘要变化时进行一次有界构建，缓存 300 秒；摘要覆盖 ID、原标签和中日名称，安全目录成员变化及未更新 `updated_at` 的直接修改也会失效。读取与构建之间发生目录变动时拒绝将不一致计数写入缓存。

计数故障只降级选项顺序：返回 `option_order_status=unavailable`，保留固定选项，不编造全 0 计数、不丢选项，不影响选择和保存。PATCH 已成功时，统计失败不改报保存失败。缓存不可用时可使用本次新鲜计数；不全局清缓存。

首次冷构建仍有额外的公共目录读取与清洗成本，本轮未测量部署后的跨网首屏耗时，不能声称统计完全无延迟。部署只读验收需检查冷/热读取耗时；本次保证的是统计不进入画像/排序链路，以及热读取不反复传输整库标签。
