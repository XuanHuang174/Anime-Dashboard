# 扩展 11：单番相似与标签探索开发方案

日期：2026-10-23，更新：2026-10-24。性质：整体开发设计；11A 基础、11B 后端、11C 单番前端、11D 标签后端与 11E 标签前端已实施，11F 待验收发布，未开启生产探索能力。增强 10 按用户决定跳过；本方案不依赖每日精选或推荐历史。

## 1. 建议结论

在现有“番剧探索”中增加 **个性化推荐｜单番相似｜按标签找** 三种入口，共用目录、标准题材、安全范围、作品卡片、详情、资源抽屉、想看与反馈能力；为新的查询意图增加独立排序、证据和浏览合同。

- 手账推荐：根据自己的有效评分与明确偏好，回答“适合我什么”。
- 单番相似：选定一部作品，回答“还有哪些作品的题材与它相近”。
- 标签探索：明确这次想看的题材条件，回答“哪些作品满足条件”。

后两种入口登录即可使用，不要求先建立高分手账，也不把本次查询保存为长期偏好。不把单番选择伪装成一条高分记录，不把标签探索提交到偏好设置接口。

“共用核心逻辑”应体现为共用可靠的数据、特征、权限与展示能力；不同查询意图仍需要各自的排序和理由。当前手账推荐 V1 保持原行为，扩展 11 不承担 V2 放行。

有两处不能直接套用：

1. 当前 `EvidencePresenter` 与前端理由解析依赖个人评分/长期偏好，不能用它凭空生成“因为你给这部打了高分”的解释。

## 4. 单番相似：具体行为

### 4.1 如何选择参照作品

提供三个入口：

1. 单番相似页：搜索中文名、日文名、Bangumi ID；可解析严格格式的 Bangumi subject 链接，但不抓取任意输入地址。
2. 私人手账的作品详情：增加“找相似”，使用已确认的 Bangumi 身份跳转。
3. 推荐作品详情：增加“以这部找相似”。卡片可通过操作菜单提供同一入口，避免每张卡片堆叠按钮。

搜索框约 300ms 防抖，优先精确 ID/名称，然后前缀及包含匹配，最多返回 15 项。候选显示名称、年份、类型及 Bangumi ID，避免同名、续作误选。支持键盘选择及清除。

搜索对象为本地推荐目录，不是实时向 Bangumi 发起每键请求。当前目录没有英文名称完整字段，不承诺英文名、拼音或所有番剧都能搜到。

手账跳转时只带已确认的 Bangumi ID；旧手账缺少可靠身份则进入现有身份确认流程。只有私人手账记录但没有进入推荐目录的作品，明确提示“暂未收录到推荐目录”，不按名字猜测，也不因点击而自动导入或修改作品。

### 4.2 来源和结果规则

- 第一版一次选一部，使用其推荐目录中有效的标准题材，显示“本次使用的题材”。不静默读取用户对此作品的私人标签、评分或长评。
- 参照作品允许已在手账中；“隐藏手账已有记录”只限制结果，不应把参照作品一起筛掉。用户明确用某部作品作参照，也不等于撤销其隐藏反馈。
- 类型、年份、最低公共评分针对结果；参照作品不必满足这些结果筛选条件，但必须符合当前内容范围。
- 始终排除参照作品自身；结果至少有一个有效共同题材；隐藏作品仍排除。
- 默认继承“隐藏手账已有记录”，覆盖已有观看状态；关闭后允许展示并标明当前状态，加入按钮遵守已有幂等规则。
- 有效题材为零时展示原因和更换参照入口，不拿热门榜冒充相似推荐。
- 第一版不保证排除所有续作、外传、总集篇；可靠系列图谱归扩展 12。不能把“同系列”当成已经实现的推荐依据。

### 4.3 排序与理由

建议新策略名 `similarity.v1`，在全部硬筛选后排序：

1. 标准题材的 IDF 加权余弦相似度降序。
2. 同分按共同题材覆盖率、有效 Bangumi 公共评分排序。
3. 最后按 Bangumi ID 固定打破平局，缺评分不补成高分。

可以复用现有 IDF 权重定义：题材存在则该维度取该题材 IDF，不存在取 0；余弦按向量点积及范数计算。权重使用统一、带目录版本的特征基线，不能每翻一页重新拟合。质量分只作后续排序依据，不以高公共评分替代题材关联。

对用户展示“题材相近”，不展示“喜欢概率 92%”。示例理由：“与参照作品共同包含「音乐」「青春」题材”。这不代表已经分析人物、剧情结构或观感；没有对应数据就不生成这些解释。

## 5. 标签探索：具体行为

### 5.1 条件与语义

第一版支持：包含 1–5 个标准题材；排除 0–5 个标准题材；默认“同时满足全部”，可切换“满足任一”。

设作品题材为 T，包含集合为 I，排除集合为 E：

- 全部：`I ⊆ T`。
- 任一：`I ∩ T ≠ ∅`。
- 两种模式均要求：`E ∩ T = ∅`。

这三条是截取候选与排序之前的硬约束。不能先拿 400 个相似候选，再在里面做全部匹配而漏掉目录中的合格作品。

规范化后同一标签不能同时包含与排除；重复值去重；未批准词、超限和非法条件返回明确错误，不静默丢弃。第一版不做只有排除条件的全库浏览，至少选一个包含题材。

例如“包含：音乐、日常；全部满足；排除：战斗”，含义仅为目录同时标注音乐和日常、且没有战斗标签。排除标签应注明“按目录已有标注筛选”，不能保证作品绝无相关内容。没有结果时提供用户可点击的放宽建议，不自动改成任一或偷偷取消排除条件。

### 5.2 标签来源、数量和排序

- 使用本站现行标准题材与批准别名；不把参考项目的标签词表或私人手账的全部自定义标签直接搬进来。
- 标签选择器可搜索、按名称/数量浏览；包含与排除使用明确的文字及选中状态区分，不能只靠颜色。
- 第一版标签旁数量定义为“当前内容范围的目录数量，未叠加本次结果筛选”。不能与已经应用年份、隐藏记录等条件后的结果数量混称。
- 点击“开始探索”后，返回这次完整条件的合格总数及最多展示数量。标签面板草稿不触发长期偏好写入。
- 第一版不做复杂的实时共现预测；如之后增加“再选此标签会剩几部”，必须按同一条件与目录快照计算。

默认排序建议为“题材相关”：全部模式在硬匹配后按题材余弦、公共评分、ID 排序；任一模式先按已选题材的加权覆盖率，再按余弦、公共评分、ID 排序。另提供实际生效的“Bangumi 评分”排序，先保留硬约束，再按有效公共评分、相关度、ID 排序，缺评分置后。

不直接复用“贴近口味／开放一些”的名称和私人画像公式，以免用户误以为单次标签搜索正在改变或依赖其长期口味。

理由显示“命中 2/2 个所选题材：音乐、日常”或“命中 1/2 个所选题材：音乐”。不显示“你喜欢音乐”，也不把题材命中数改称个人评分。

## 6. 最终页面呈现

保持“番剧探索”的整体 Memphis 风格、现有返回手账及详情样式；桌面端三种入口置于红色头部的标题右侧，原有白色工具栏承载当前模式的二级控件。一级选中使用青绿色，个人推荐二级选中保留黄色；窄屏一级入口独占一行、三个等宽。当前入口追加“· 当前”，并提供相应的当前页语义。原来的“为你发现／电波契合／换一种口味”继续只属于手账推荐。

### 6.3 入口与导航细节

- 标准题材芯片增加“探索这个题材”入口；非标准私人标签不伪装成可探索题材。
- 相似结果详情中的“以这部继续找相似”关闭当前详情后更新参照；浏览器后退可回到上一次查询，不构造无限层弹窗。
- 建议路由：`/recommendations`、`/recommendations/similar?seed=<BangumiID>`、`/recommendations/tags?...`。链接是登录后的查询入口，不是公开私人推荐清单。
- URL 仅保存公开作品 ID、标准题材与普通筛选。个人评分、长评、令牌、签名游标和内容授权不进入分享链接；收到链接的人按自己的范围与隐藏记录重新查询。
- 三种模式使用各自浏览状态。切换模式时清理旧详情/资源会话、取消旧请求；不能把迟到的搜索或资源响应写入另一模式。
- 查询区保留“草稿”和“已应用条件”的区别。失败时保留草稿，只有成功应用后更新结果摘要。

## 7. 后端与前端落地设计

### 7.1 查询管线

```text
登录及能力检查
  → 解析本次内容范围、查询意图和条件
  → 读取同一范围的目录及版本化标准题材
  → 验证参照作品 / 包含与排除标签
  → 应用年份、类型、公共评分、已有记录与隐藏反馈
  → 硬匹配与新意图排序
  → 固定有序结果快照
  → 生成与本次查询一致的证据
  → 共用作品数据、详情、资源与操作组件
```

初始建议沿用当前工程的有界规模：最多处理 50,000 条目录、最多展示 120 部、每批 24 部、每页 12 部、快照 15 分钟。对全部合格目录完成必要筛选与排序后再截取展示结果；如保留内部召回上限，必须证明它不会漏掉硬匹配结果，不能机械沿用旧的 400 个召回截断。

`eligible_count` 表示本次条件的全部合格数量，`returned_count` 表示有序快照实际收录数量，`result_limit=120` 表示展示上限。目录超过处理上限要返回明确的不可用状态，不能声称已经统计全库。

### 7.2 最小接口集合（建议名称）

| 接口 | 作用 |
| --- | --- |
| `GET /api/recommendations/explore/catalog/?q=...` | 选择参照作品，返回有界搜索结果与有效题材 |
| `GET /api/recommendations/explore/options/` | 返回标准题材、范围内数量、定义及版本 |
| `GET /api/recommendations/explore/` | `intent=similar` 配参照 ID；`intent=tags` 配包含/排除/匹配规则；首次查询或用游标续页 |
| `GET /api/recommendations/explore/context/` | 页面回到前台时检查当前意图、目录、范围及反馈等是否仍有效 |
| `GET /api/recommendations/explore/<bangumi_id>/` | 根据探索证据上下文返回详情，不伪装成个人画像推荐详情 |

新列表合同建议 `recommendations.explore.v1`；排序策略分别为 `similarity.v1` 与 `tag-explore.v1`。字段包含意图、已应用条件、版本、统计、快照、翻页游标、结果与独立证据上下文。

证据来源新增 `selected_work`、`selected_tags`；分别绑定参照 ID/特征指纹或规范化标签集合/匹配方式。证据与列表、详情使用同一上下文；不只改一句前端文案而继续返回个人评分来源。

新详情入口可在内部复用现有作品详情服务与序列化工具，但校验探索自己的证据。想看、反馈与撤销继续使用已有写接口和服务，不再创建一套写入语义。接口最终路径可在 11A 确定，避免 URL 散落在组件中。

### 7.3 建议代码边界

- 后端新增探索意图/条件校验、排序服务、证据与浏览适配器，例如 `exploration.py`、`exploration_evidence.py`、`exploration_views.py`。按文件规模拆分，不要求为了文件名额外分层。
- 复用 `features.py`、`taxonomy.py`、`content_scope.py`、通用筛选及业务写服务。仅提取确实通用且可回归证明的工具，避免顺手重写冻结 V1。
- 前端增加探索 API 客户端、合同解析、控制器/Hook，以及单番和标签查询区。共用 `RecommendationCard`、Dialog、资源面板、想看和反馈交互。
- 调整理由组件接受新的显式来源种类，保持旧来源分支测试；禁止把新结果强行塞入旧个人推荐合同。
- 第一版原则上不新增业务表和数据库迁移；来源仍是现有目录，查询是临时状态。后续若搜索测量证明需要索引，再独立评估迁移。

## 8. 内容范围、隐私及失效处理

沿用当前模式：默认安全范围；用户本次浏览主动包含 NSFW 时，仍受推荐总开关、现行作品审核和目录版本约束。无需重新引入已经取消的账号申请审批。

- 搜索建议、参照作品、标签数量、结果、详情与加入操作都读取同一当前范围；不能只在最终结果过滤。
- 永久有效审核按当前 `never_expires` 规则判断，不能把 `scope_valid_until=null` 当成失效；但永久审核不代表总开关、撤销和资料变更永不生效。
- 默认排除未知分级；未通过当前审核边界的作品不能因手账已存在或公共库可见而自动进入探索。
- 私人推荐封面继续走已有展示策略，不通过此次扩展改变公共库发布和封面政策。
- 模式切换不得自行清除一个仍有效的内容范围；遇到真实的开关/审核变更才按现行合同更新，并明确原因。
- 签名绑定当前用户的不可逆标识、意图、参照/标签、筛选、隐藏记录与反馈版本、目录/词表/算法/范围及发布代次。签名不是加密，不放入个人长评和评分明文。
- 无效身份或不可见作品统一返回适当的不可用响应，不泄漏其他用户手账。所有查询接口登录保护、限流、`private/no-store`。
- 只共享公开特征缓存；私人查询结果和证据不进入跨用户缓存。缓存键包含范围与版本；故障时按现有可验证策略回源或明确不可用。
- 相同游标重试返回同一位置；续页不重排。参照特征、题材、审核或用户隐藏条件变化时返回上下文已变化，保留查询条件供重新加载，不接着拼旧列表。
- 400、401、409、429、503 分别呈现条件问题、登录失效、上下文变化、限流和服务不可用；不能统统展示“没有相似作品”。

## 10. 验收清单

### 正确性与可解释性

- 空手账、无高分、未评分账号可使用两个新入口；不创建评分或长期偏好。
- 同名作品正确消歧；Bangumi、AniList、目录主键和私人记录主键不混用；缺身份、缺目录、缺题材分别提示。
- 参照作品已有记录仍能选择；结果按“隐藏已有记录”生效；参照自身始终不出现。
- 单番至少一个共同题材；未标注题材不靠简介/长评推断；理由共同标签逐项可核对。
- 标签全部/任一/排除与形式定义一致，超过旧召回规模的合成数据仍不漏硬匹配；非法词和冲突拒绝；零结果不擅自放宽。
- 数量区分全量合格、快照收录及结果上限；缺失年份/评分遵守现有筛选语义。
- 公共评分、个人评分和内部排序分不混用；新理由不出现伪造的个人喜好。

### 状态与业务闭环

- 同游标重试、全轮遍历、跨批及返回上页不重复、不跳位；超时不会自动推进位置。
- 快速搜索、改参照、切换模式、关闭详情、打开资源抽屉及迟到响应不串场；键盘、Escape、焦点恢复正常。
- 隐藏与撤销在新旧入口遵守既有全局作品反馈语义，不生成标签负偏好。
- 想看幂等，不覆盖原状态、评分、长评和私人标签；从详情与卡片进入结果一致。
- 手账推荐的画像、风格、筛选、已有身份确认、资源及动画回归通过。

### 范围与用户隔离

- 安全范围、主动包含 NSFW、未知分级、审核撤销、永久审核空到期时间、总开关变化、目录直接变更均覆盖。
- 标签数量与搜索建议不泄漏当前范围外作品；手工改 URL/游标不能扩大范围。
- 外来用户游标/详情上下文拒绝；缓存故障、过期、跨页签与前台重读有明确行为。
- 查询前后私人资料逐字段不变；新增接口不调用外部模型或在搜索时隐式写目录。

### 性能与发布

- 使用隔离 PostgreSQL 与合成数据执行自动化，不对生产数据库制造评分或压力。
- 分别记录目录搜索、标签选项、两类首屏、续页、详情的冷/热耗时、SQL 次数、CPU/内存及缓存情况；同环境比较增强 9，未取得的指标明确标记未取得。
- 在 11A 基线后固定可测预算；至少不出现逐作品查库、全字段大对象反复扫描和每次搜索远程抓取。不能以单次返回 200 代替性能验收。
- 桌面、窄屏、低高度及 75%/125% 缩放检查查询区、详情和底部操作可达；低动态效果设置正常。
- 功能开关关闭后只有 11 不可用；原手账和手账推荐仍正常。回退不删除用户数据，不回滚审核记录。
