# M3：受控推荐回归、部署与回退清单

## 结案边界

M3 是受控链路的回归和发布准备，不是开闸授权。不切换 V2，不修改排序、评分、长评或私人标签，不批量审批账号或作品。人工访问审批不等于年龄核验，也不代表全球法律合规结论。

继续保持：`RECOMMENDATION_ALGORITHM_VERSION=content.v1`、`RECOMMENDATION_V2_BROWSE_ENABLED=False`、`RECOMMENDATION_RESTRICTED_CONTENT_ENABLED=False`，模块 3 数据库服务开关关闭。未知分级始终不放行。

## 本阶段实现

- 到期监督从网络完成回调中拆出独立计时器。正在等待的轻量探测不再延后本地到期处理；探测超时 20 秒取消，间隔 30 秒，断网不冒充授权撤销。
- 页面隐藏时暂停探测、取消在途请求，但不暂停到期边界；恢复可见或焦点时检查期限。浏览器休眠或冻结会暂停 JavaScript，不能承诺隐藏页毫秒级执行；恢复执行时首先检查期限，后端始终独立检查当前授权与作品安全。
- 取消／卸载后的成功响应和错误不得回写当前会话；客户端不再采用已取消请求的范围版本，也不让更早的异版本响应污染新版本。相同版本的并行读取仍可完成。
- 新增 12 项 PostgreSQL 受控链路演练、6 项只读验收工具护栏测试、10 项前端时钟／慢网／乱序测试。现有 M1/M2、资源会话、反馈、身份核对及 V1 回归继续运行。
- 新增部署只读工具，无新增迁移、业务表、权限签发器或开闸命令。

## 隔离回归

测试仅运行在本机 PostgreSQL 17.11 的 `test_recommendation_isolated_tests`，不接受 SQLite 或生产 Neon。新测试启动时断言数据库引擎及库名；数据为合成账号与合成作品，不使用真实私人手账。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-recommendation-postgres.ps1
$env:RECOMMENDATION_TEST_DATABASE_URL='postgresql://recommendation_test:local-isolated-7c-only@127.0.0.1:55437/recommendation_isolated_tests'
.\.venv\Scripts\python.exe manage.py test recommendations.tests anime.tests --settings=config.recommendation_pg_test_settings --keepdb --noinput --verbosity 1
.\.venv\Scripts\python.exe manage.py check --settings=config.recommendation_pg_test_settings
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run --settings=config.recommendation_pg_test_settings
```

另在 `frontend` 运行 `npm.cmd test`、`npm.cmd run build`。测试完成用 `scripts/setup-recommendation-postgres.ps1 -Stop` 停止本机实例，不删除测试目录。

新增演练覆盖：

| 场景 | 断言 |
| --- | --- |
| 审计关闸、重新开启 | 新范围可重新读取；旧游标及旧详情凭据仍为 409，V1 安全结果不变 |
| 部署紧急关闭 | 受限范围立即拒绝；持久关闭后重新启用仍要求重新开启、重新读取 |
| 旧开启请求重放 | 返回当前关闭状态，不重新开闸、不重复审计 |
| 资格自然到期 | 无需版本计数变化即拒绝读写，原手账逐字段不变 |
| 作品审核到期／改为未知 | 旧快照失效，直接详情拒绝，撤销隐藏不能重新引入作品 |
| 加入等待用户锁时撤销资格 | 解锁后 409，不新增记录 |
| 加入等待作品锁时撤销审核 | 解锁后 409，不新增记录 |
| 反馈等待用户锁时撤销资格 | 解锁后 409，不产生反馈或手账改动 |
| 管理员等待全局锁时撤销权限 | 解锁后 403，不修改开关、不新增审计 |
| 同版本审批／拒绝竞争 | 只有一个决定成功，另一个版本冲突，其他账号不受影响 |
| 停用账号 | 既有有效资格不能绕过停用 |

四项等待测试通过独立连接的 `pg_stat_activity.wait_event_type=Lock` 确认真实 PostgreSQL 锁等待，不以线程启动或睡眠代替锁验证。到期测试使用隔离时钟，不制造违反数据库期限约束的记录。

## 部署顺序

1. 确认部署对应本次提交，线上仍为 V1、部署总闸与数据库服务均关闭；不要因测试通过而自动审批、审核或开闸。
2. M3 无新数据库迁移。沿用已部署 M1/M2 迁移；如基础迁移缺失，应按正常发布流程先补齐，不直接通过本验收工具执行。
3. 发布前后端。无需清空业务数据、反馈、偏好或手账。旧客户端仍受后端当前授权、安全、游标校验约束。
4. 发布完成后再对明确授权账号运行下述只读终验；没有部署时不得把本机测试写成线上验收通过。
5. 普通账号及超级管理员分别补验页面。业务写入、关闸及到期演练仍在隔离环境进行；真实生产演练须另行明确授权和范围。

### 有界只读工具

在项目根目录运行，密码和登录账号均使用隐藏输入，不写入命令行；`--expected-account` 仅指定已获授权账号：

```powershell
.\.venv\Scripts\python.exe scripts/verify_recommendation_controlled_deployment.py --deployment-confirmed --expected-account "<明确授权普通测试账号>"
```

超级管理员可单独授权运行同样命令并添加 `--admin-view superuser`，只读全局开关，不读取申请列表或其他用户手账。普通账号默认验证该管理接口返回 403，不能由此声称已经读取数据库开关状态。

可选项：

- `--adult-id`、`--unknown-id`：操作者确认的**公共目录** Bangumi ID，用于安全范围的直接详情拒绝测试；不能输入私人手账 ID，不枚举猜测作品。不提供则报告该项未验证。
- `--expected-dist frontend/dist`：与该次部署确切对应的本机构建，校验入口及推荐 JS/CSS 字节；不提供、网络失败或本机构建并非发布版本时，不得声称资产一致。发布版本不同应使用正确构建，不能降低比对要求。

工具硬限制：固定两个 HTTPS 站点、最多 40 请求、禁止重定向、10/45 秒连接／读取超时、不自动重试 POST；唯一 POST 为正常登录，其余仅 GET。禁止申请、审批、开关、反馈、加入、偏好和身份写入；令牌不发往前端。失败不输出异常正文中的私人内容。报告只保留断言、请求耗时和限制，存入忽略目录 `.tools/deployment-m3/`，无密码、令牌、私人标题、评分、游标或完整响应。

`passed_closed_readonly` 只表示完成所选只读范围；不等于真实成人开放验收、浏览器验收、全站账号验收或性能达标。客户端耗时不等于 SQL、计算时间或 P95。M2 的首屏偏慢观察仍应保留，不把本阶段韧性修复宣称为性能优化。

### 人工页面检查

- 普通用户：默认安全范围、取消筛选草稿不写入；应用按钮可见，失败可重试，不出现假画像或假推荐。
- 模块 3：超级管理员能读取当前开关；关闭态不能绕过部署总闸开启。只读终验不要提交申请、审批、撤销或开关。
- 桌面／手机：推荐、详情与资源正常；切换作品／范围、关闭弹窗或离开页面后无旧结果串场；不真实唤醒 Magnet 或改剪贴板。
- 实际到期／撤销／关闸交互仅在隔离环境写入验证。保持详情／资源打开后触发，到期后旧内容清除、回到安全范围；慢网不得阻塞本地期限。
- 若 Browser 再次超时，记录未完成项交由人工补验；不能以 URL、标题或静态代码断言替代页面验收。

## 安全回退与重新启用

1. **首选持久关闸**：超级管理员模块 3 明确确认关闭服务，数据库控制版本递增，有审计。关闭后受限接口拒绝、旧上下文失效，安全 V1 路径继续使用。
2. **紧急部署关闸**：设置 `RECOMMENDATION_RESTRICTED_CONTENT_ENABLED=False` 并完成所有实例部署。不要切换 V2；无需删除任何用户数据。
3. **重新启用前必须持久关闭一次**：部署总闸为 False 时仍可在模块 3 关闭数据库开关。读取确认关闭和新版本后，再考虑后续部署与新的明确开启批准。
4. 不能仅将环境变量 False→True 原值来回切换并宣称所有旧凭据永久失效：无持久控制版本变化时，旧快照在自身有效期内可能重新匹配上下文。**必须执行第 3 步**，不得重置、回滚数据库控制版本或恢复旧审计状态。
5. 再次开放需要另行确定批准范围；新的账号与作品均应满足当前审批、有效期与审核指纹。重新打开后从第一页重新读取，禁止重用原游标／证据。数据库关闸／重开演练验证旧凭据仍为 409。
6. 后端持续复核当前安全和权限；在途已读取响应无法远程收回，但客户端在当前响应拒绝／版本变化时清空，活跃页定期检查、到期独立清空、恢复可见时检查。不能承诺跨网络的零延迟撤回。
7. 前端回退优先保留 M2 受控合同兼容版本。先关闸再回退静态资源；用户重新加载页面清除内存会话。服务端缓存与游标带范围／控制／审核版本，无需全站 `FLUSHALL` 或删除缓存目录，更不能删除业务记录。

真实生产灰度账号、作品、开放时点与真实写入演练均未启动；本阶段不能代替这些决策。人工授权的年龄与地域合规局限继续保持明确。前端大包告警和线上首屏性能应单独定位，不在 M3 顺带更换算法或放宽门槛。
