# V2-D2 隔离验收报告

日期：2026-10-18。结论：**D2快照、游标、详情证据绑定与前端恢复闭环通过隔离验收。生产路径继续V1，未批准或启用V2。** 实现、合同及重跑命令见 [D2说明](recommendations-v2d2.md)。

## 已交付

- 复用同一个批次服务，D2准备路径调用D1完整执行配方；续页/换批不重排。
- 快照、游标、公共缓存、卡片证据和详情上下文绑定配方及用户/数据/筛选作用域；V1/V2命名空间隔离。
- 详情使用同一证据服务，不为一条解释重算整份列表；旧令牌409不自动绕过。
- 加入确认后清空旧详情和资源态，保留签名作品身份与浏览条件、整份读取最新详情；不只更新按钮。
- 前端严格核对服务端能力声明及完整配方，阻止跨版本续页和迟到响应；400/409旧游标有明确首批恢复路径。
- 不增加算法选择UI、业务表、迁移、模型服务或第二套资源抽屉；生产URL没有接入V2准备适配器。

## 关键不变量

1. 首批结果ID序列与同条件D1执行结果逐项一致；后续全120部按原顺序读出，无重复、不跳位。时间跨秒时允许签名字符串生成时间不同，但证据、快照ID、位置及原到期时间一致。
2. 卡片与详情的结构化证据、理由、证据版本和令牌相同；详情读取期间没有推荐列表计算、私人长评读取或DML。
3. 评分、私人题材、明确偏好、反馈、目录字段、风格或rollout版本改变后，旧上下文409；执行配方中的召回/运行时/控制版本变化同样失效。
4. 外用户、错作品身份、篡改签名、过期详情及跨版本游标不能消费原上下文。成人或未知分级重分类后，旧快照被拒绝，最新详情也不能绕过安全目录。
5. V1响应不携带D2配方/详情票据；默认列表、详情与能力接口继续V1。生产详情收到D2票据返回409，不能静默改用V1解释。
6. 公共缓存只保存目录与公共特征；没有私人结果缓存，更不与资源检索共享缓存。V2缓存键已摘要化以避免Memcached长度警告。

## 页面与状态闭环

使用已有生产页面和原生dialog，不是另写展示页面；所有服务响应均为合成合同。复用原9B/9C测试脚本的可选D2模式，不更改原模式：

- 相同控件不重复请求；筛选草稿不提前生效；应用/单项清除与实际请求一致。
- 追加失败局部重试；换批失败保留旧内容并重试同一目标；高频点击只发一个续读。
- 409冻结旧流、清掉证据；明确重载后才使用新首批。旧V2回调不能进入新V1会话。
- 分类变化关闭详情/资源会话；资源失败仍是局部失败。
- 合成加入成功只POST一次，整份重读详情并重置推荐首批；真实用户手账没有写入。
- 手机端双行控制区、原生底部筛选面板、焦点/Escape及无横向溢出通过。
- V2准备能力回退到旧V1分页时，详情/资源关闭、旧游标清空；恢复浏览后建立新首批而非拼接旧结果。

浏览器记录：`.tools/acceptance-v2d2-browser/report.json`。Magnet、剪贴板及外部资源服务不执行真实副作用。前端构建输出仍在忽略的`dist`目录，未提交产物或临时截图。

## 回退说明

当前没有线上算法切换或数据库迁移可回退；继续使用V1即可。D2兼容层使V2旧游标/详情票据失效并首批重读，不能清空用户表、偏好或反馈。未来回退应保留该兼容层，由D3控制服务端分派；全量清缓存或降级到不识别票据的旧代码不是推荐恢复方式。

所有测试与临时报告位于忽略的`.tools`目录，提交仅含代码、合成测试和本脱敏报告，不含`.env`、数据库、凭据或私人手账明细。
